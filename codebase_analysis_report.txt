1. 핵심 요약 (Executive Summary)
================================================================================
SW Engine 프로젝트의 동시성(Concurrency), 메모리 생명주기(Lifecycle/UAF),
자원 관리(Resource/Material), 그래픽스 파이프라인(RHI/RenderGraph), 에디터 트랜잭션,
게임플레이 서브시스템 전반을 정밀 분석하였습니다.

식별된 항목은 다음과 같이 분류됩니다:
- [Critical] 즉각적인 크래시 또는 심각한 GPU 메모리 누수를 유발하는 결함 (2건)
- [High]     특정 실행 흐름에서 Use-After-Free 또는 수명주기 누락을 일으키는 결함 (2건)
- [Medium]   동시성 레이스, 트랜잭션 오염, 32비트 랩어라운드 결함 (3건)
- [Low]      게임플레이 가중치 로직 불일치 및 안전성 이슈 (1건)
- [Bottleneck] GPU 하드 스톨 및 CPU-GPU 파이프라인 병목 (2건)

2. 세부 결함 분석 및 해결 방안 (Defects & Vulnerabilities)
================================================================================

--------------------------------------------------------------------------------
[CRITICAL-01] MaterialCache 머티리얼 참조 해제 시 GPU 자원 누수 (GPU Memory Leak)
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Graphics/Material/MaterialCache.cpp (Line 82 ~ 97)
- 증상 및 원인:
  MaterialCache::release(relativePath) 호출 시 참조 카운트(_refCount)가 0에 도달하면
  _impl->_mapEntry.erase(it)를 수행하여 Material 인스턴스를 즉시 해제합니다.
  그러나 이 과정에서 RHI 디바이스를 통한 it->second._material->shutdown(_impl->_pDevice)가
  호출되지 않아, GPU 상수 버퍼(_constantBuffer)와 바인드리스 디스크립터 슬롯(_descriptorIndex)이
  RHI 디바이스에 등록된 채로 영구히 누수됩니다.
- 해결 방안:
  _mapEntry.erase(it) 이전에 entry._bGpuInit 상태와 _impl->_pDevice를 확인하여
  it->second._material->shutdown(_impl->_pDevice)를 명시적으로 호출한 뒤 엔트리를 제거합니다.

--------------------------------------------------------------------------------
[CRITICAL-02] TaskManager 부모-자식 태스크 수명 불일치로 인한 UAF (Use-After-Free)
--------------------------------------------------------------------------------
- 파일 위치: Source/Core/Task/TaskManager.cpp (Line 650 ~ 695, Line 1286 ~ 1305)
- 증상 및 원인:
  부모 태스크 실행 중 자식 태스크가 생성되면 pNode->_pParent = t_pCurrentRunningTask 로
  연결되지만, 부모 노드의 참조 카운트(retain())가 증가하지 않습니다.
  부모 태스크 본문이 종료되면 TaskManager 큐 참조가 해제되어 노드 풀(_nodePool)로 즉각
  반납/재할당될 수 있습니다. 이후 나중에 완료된 자식 태스크가 onTaskFinished()에서
  pParent->_activeChildren.fetch_sub(1)을 호출할 때 이미 다른 스레드에 재할당된 메모리를
  오염시키는 UAF가 발생합니다.
- 해결 방안:
  자식 태스크 생성 시 t_pCurrentRunningTask->retain()을 호출하고, 자식 태스크 완료 시
  pParent->release()를 호출하여 자식들의 실행이 모두 끝날 때까지 부모 노드를 안전하게 보존합니다.

--------------------------------------------------------------------------------
[HIGH-01] Scene::shutdown() 씬 언로드 시 GameObject 지연 파괴 미완료
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Scene/Scene.cpp (Line 225 ~ 237)
- 증상 및 원인:
  Scene::shutdown()에서 모든 오브젝트를 순회하며 _objectManager->destroyObject(pObj)를
  호출하지만, _objectManager->processDeferredDestruction()이나 clear()를 호출하지 않고
  함수를 종료합니다. 이로 인해 컴포넌트들의 onEndPlay() 및 수명주기 지연 정리 콜백이
  정상적으로 완료되지 못한 채 GameObjectManager가 파괴되어 비정상 상태가 유발됩니다.
- 해결 방안:
  Scene::shutdown()에서 파괴 요청 후 _objectManager->processDeferredDestruction() 및
  _objectManager->clear()를 명시적으로 호출하여 모든 엔티티의 수명주기를 완결합니다.

--------------------------------------------------------------------------------
[HIGH-02] ObjectStateSerializer 비동기 파일 다이얼로그의 Dangling Pointer UAF
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Object/GameObject/ObjectStateSerializer.cpp (Line 424 ~ 450)
- 증상 및 원인:
  openSaveFileDialog / openLoadFileDialog 함수에서 람다 콜백이 원시 포인터인
  GameObject* pGameObject를 캡처합니다. OS 파일 다이얼로그 창이 열려 있는 동안 사용자가
  씬을 전환하거나 해당 GameObject를 삭제하면, 사용자가 파일 선택을 완료했을 때
  이미 소멸된 GameObject 메모리에 saveToXmlFile / loadFromXmlFile을 수행하여 크래시가 발생합니다.
- 해결 방안:
  원시 포인터 대신 GameObjectHandle 또는 uint64 objectId를 캡처하고, 파일 선택 완료 시점에
  GameObjectManager::findGameObjectById()로 유효성을 검증한 후 안전하게 실행합니다.

[MEDIUM-01] AssetStreamingQueue 취소 후 즉시 재요청 시 이전 작업의 콜백 조기 완료
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Resource/AssetStreamingQueue.cpp (Line 187 ~ 202)
- 증상 및 원인:
  cancelRequest(path)가 _uniqueActiveRequest에서 경로를 제거하지만, 백그라운드 워커 스레드에서
  이미 실행 중인 태스크 자체는 계속 실행됩니다. 클라이언트가 같은 에셋 경로를 즉시 다시
  requestAsset()하면 새로운 콜백이 _mapInFlightCallback[path]에 등록되는데, 이전 취소 작업이
  완료되면서 새 콜백을 완료된 것으로 오인하고 실행해 버립니다.
- 해결 방안:
  에셋 요청마다 세대 번호(_generation)를 부여하고 TaskArgs에 전달하여, 워커 완료 시점의
  세대와 현재 활성 세대가 일치할 때만 콜백을 발행하도록 개선합니다.

--------------------------------------------------------------------------------
[MEDIUM-02] CommandStack 중첩 트랜잭션 시 Undo 히스토리 파손
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Utility/CommandStack.cpp (Line 35 ~ 85)
- 증상 및 원인:
  _bInsideTransaction이 1비트 불리언 플래그로만 관리됩니다. 트랜잭션 실행 도중 내부 서브루틴이
  복합 작업을 위해 beginTransaction()을 다시 호출하면, 외부 트랜잭션이 누적해 둔
  _listPendingTransactionCommand가 clear()되어 외부 트랜잭션의 Undo 기록이 유실됩니다.
  또한 내부 endTransaction() 호출 시 _bInsideTransaction = 0이 되어 외부 트랜잭션이 풀립니다.
- 해결 방안:
  1비트 플래그 대신 중첩 깊이 카운터(uint32 _transactionDepth)를 사용하여, 최외곽 트랜잭션이
  종료되는 시점(depth == 0)에만 하나의 복합 커맨드로 합쳐서 push하도록 수정합니다.

--------------------------------------------------------------------------------
[MEDIUM-03] ConcurrentQueue 64비트 정수 확장으로 인한 32비트 랩어라운드 오작동
--------------------------------------------------------------------------------
- 파일 위치: Source/Core/Concurrency/ConcurrentQueue.h (Line 60 ~ 125)
- 증상 및 원인:
  Dmitry Vyukov 락프리 큐 구현에서 seq와 pos(uint32)를 64비트 정수(intptr_t)로 선행 캐스팅한 후
  감산(static_cast<intptr_t>(seq) - static_cast<intptr_t>(pos))을 수행하여, 32비트 모듈러
  언더플로우 랩어라운드가 무효화됩니다. 약 42억 회 연산 후 큐가 영구히 full/empty로 잠깁니다.
- 해결 방안:
  static_cast<int32>(seq - pos) 및 static_cast<int32>(seq - (pos + 1))로 32비트 모듈러 감산으로
  수정하여 무한 랩어라운드를 보장합니다.

[LOW-01] TileMap 몬스터 인카운터 확률 가중치 무시
--------------------------------------------------------------------------------
- 파일 위치: Source/GameFramework/Kits/Overworld/TileMap.cpp (Line 171 ~ 182)
- 증상 및 원인:
  pickEncounterSpeciesId()에서 몬스터별 _weight 합계를 계산해 놓고, 실제 선택은
  s_pick++ % _listEncounterEntry.size()로 단순 라운드로빈을 수행하여 XML에 정의된
  확률 가중치가 완전히 무시됩니다.
- 해결 방안:
  난수 기반 누적 가중치(Cumulative Probability) 알고리즘을 적용하여 XML에 지정된
  가중치 비율대로 몬스터가 출현하도록 수정합니다.

3. 성능 병목 지점 및 아키텍처 개선안 (Performance Bottlenecks)

--------------------------------------------------------------------------------
[BOTTLENECK-01] D3D12RHIResource 구조화 버퍼 갱신 시 커맨드 리스트 재생성 및 GPU 스톨
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Graphics/RHI/DX12/D3D12RHIResource.cpp (Line 317 ~ 358)
- 문제 분석:
  updateStructuredBuffer() 호출 시마다 OS COM API를 통해 ID3D12CommandAllocator와
  ID3D12GraphicsCommandList를 동적 생성하고, 복사 제출 후 _pDevice->waitForPreviousFrame()을
  호출하여 CPU와 GPU가 펜스 동기화를 위해 완전히 멈춥니다(GPU Hard Stall).
- 개선 권장안:
  1) 프레임 업로드 링 버퍼(Upload Ring Buffer)를 도입하여 0-Alloc 메모리 맵 복사로 전환.
  2) 현재 프레임의 메인 커맨드 리스트에 CopyBufferRegion을 기록하여 별도 GPU 플러시 없이
     비동기 복사 수행.

--------------------------------------------------------------------------------
[BOTTLENECK-02] RenderGraph 병렬 레코딩 시 의존성 미반영 플랫 디스패치
--------------------------------------------------------------------------------
- 파일 위치: Source/Engine/Graphics/RenderPass/RenderGraph.cpp (Line 298 ~ 325)
- 문제 분석:
  executeParallel() 시 컴파일된 모든 패스를 TaskStageHandle에 의존성 없이 일괄 투입하고
  전체 워커 완료를 waitStage()로 대기한 후 순차 제출합니다.
  패스 간 선행/후행 데이터 의존성(DAG)이 태스크 그래프에 반영되지 않아 단계적 제출(Pipelining)이
  불가능하고 CPU 파이프라인 버블이 발생합니다.
- 개선 권장안:
  1) RenderGraphNode 간 데이터 의존성을 TaskHandle::precede()로 연결하여 세분화된 태스크 그래프 구성.
  2) 선행 패스가 완료되는 즉시 커맨드 리스트를 GPU 큐에 점진적으로 제출(Pipelined Submission).
