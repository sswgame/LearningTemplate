# 다음 이름 점검

> 상태: 구현대기 · 선행: 없음 · 영역: project · 옛번호: C-17 · 진행: 0/4

2026-10-13 이름 점검에서 남긴 네 가지다. 기준은 [docs/agents/NamingCpp.md](../agents/NamingCpp.md) "Class suffixes" 절(`Settings` · `Config` · `Def` 는 같은 문서 "Type suffixes")과 [결정 기록](../09_Decisions.md) 5-1 이다. 파일이 겹쳐 미룬 정리라 같은 폴더를 다른 작업이 건드리는 중이면 미룬다.

## 1. 단위

| 단위 | 내용 | 상태 |
|---|---|---|
| N1 | `Context` 접미어 타입이 무엇을 담는지 점검한다(목록을 `graphify query` 나 `grep -rE "\b\w+Context\b"` 로 모아 담는 것별로 가른다) | 대기 |
| N2 | `*Util` 정적 클래스 중 한 타입의 메서드가 된 것이 나은 것을 고른다 | 대기 |
| N3 | `Unit` 계열(812 회)이 무엇을 가리키는지 가른다 | 대기 |
| N4 | 남은 지역 · 멤버 변수 단독 `value` 약 50 곳을 뜻이 드러나는 이름으로 | 대기 |

## 2. 하는 법

- 단위마다 먼저 목록을 모아 이 문서 아래에 "결과" 로 적고(고칠 것 · 그대로 둘 것과 이유), 고칠 것만 바꾼다. 이름 바꾸기는 `RenameRedirects` 규칙을 따른다.
