# 모션 매칭 (보류)

> 상태: 보류 · 선행: 없음 · 영역: gameplay · 백로그: D4-16 · 진행: 해당없음

모션 매칭을 지금 만들지 않기로 한 결론, 다시 볼 조건, 그 전에 깔아 둔 선행 구조, 다시 열 때의 구조 초안을 모은 문서입니다.
백로그 항목은 `D4-16` 입니다.

## 1. 결론

보류합니다. 모션 매칭은 데이터(수십 분의 연속 모캡과 태그)와 그것을 요구하는 게임(캐릭터 이동 품질이 핵심인 3D 게임)이 있어야 값을 합니다.
지금 저장소의 캐릭터 클립은 KayKit 의 짧은 루프 몇 개뿐이고, Shooter3D 의 이동은 블렌드 스페이스와 재생 속도 매칭(`LocomotionSpeedUtil`)으로 충분합니다.
데이터 없이 만들면 탐색 · 굽기 · 에디터를 맞춰 볼 대상이 없어 설계를 검증할 수 없습니다.

대신 모션 매칭이 들어올 때 갈아엎지 않도록, 그것이 기대는 구조 두 가지를 먼저 넣었습니다(선행 구조 B안, 3절).

## 2. 다시 볼 조건

다음 둘이 함께 오면 다시 엽니다.

- **데이터**: 한 캐릭터에 이어진 이동 모캡이 10 분 이상 있고(걷기 · 달리기 · 방향 전환 · 멈춤), 클립에 루트 모션이 있습니다.
- **게임 요구**: 이동 품질이 게임의 핵심인 3D 게임이 생기고, 블렌드 스페이스 + 속도 매칭 + 보폭 워핑으로 발 미끄러짐 · 전환 어색함이 남는다는 캡처가 있습니다.

합성 리그 벤치(`도구 - 합성 리그 생성기`)의 비용 곡선은 순서 판단에 함께 씁니다(애니메이션 고급 기능 후보끼리의 순서).

## 3. 선행 구조 (들어간 것)

| 구조 | 자리 | 모션 매칭에서 쓰는 곳 |
| --- | --- | --- |
| 포즈 단위 inertialization | `Engine/Animation/Skeletal/PoseInertializer` · 그래프 링크 `"blend_mode": "inertialization"`, `"half_life"` | 탐색이 고른 새 프레임으로 자주(0.1 ~ 0.2 초마다) 건너뛸 때 두 재생을 섞지 않고 차이만 풀어 낸다. 크로스페이드는 건너뛸 때마다 두 포즈를 샘플해야 하고 끊기면 튄다. |
| 포즈를 내는 그래프 노드 | `Engine/Animation/Skeletal/AnimationPoseNode`(`IAnimationPoseNode`, `AnimationPoseNodeSet`) · 그래프 노드 `"pose_node"` | 모션 매칭은 클립 하나가 아니라 "데이터베이스에서 고른 프레임"을 내는 노드다. `AnimationPoseNodeType` 에 종류를 하나 더하면 상태 기계 · 전이 · 동기 그룹을 그대로 쓴다. |

남은 연결은 다음과 같습니다.

- 스켈레탈 애니메이터가 포즈 노드를 평가하는 길(지금은 그래프에 포즈 노드가 있으면 로드 때 오류). 클립 샘플을 `IAnimationPoseSampler` 로 열고, 재생할 것을 `findPoseNode()` 로 가른 뒤 캐스팅한다.
- 레이어 경로의 inertialization. 레이어는 지금 바로 바뀌고(`restartLayer` · 가중치) 이어 섞지 않는다. 레이어마다 `PoseInertializer` 하나를 두고 `begin` · `apply` 를 부르면 된다.
- 새 재생의 속도(`begin` 의 `pTargetPreviousPose`). 지금 애니메이터는 끊긴 쪽 속도만 잇는다(Bollo 원안과 같다).

## 4. 구조 초안 (다시 열 때)

| 단계 | 내용 |
| --- | --- |
| M0 데이터 스키마 | 특징 벡터 정의를 데이터로 둔다(본 위치 · 속도, 미래 궤적 점 몇 개, 가중치). 클립 구간 태그(제외 · 루프 · 멈춤)는 알림 트랙과 같은 구간 데이터로 둔다. |
| M0 굽기 | 쿡 단계에서 클립을 프레임마다 훑어 특징 행렬(정규화 포함)을 만든다. 런타임에는 행렬만 읽는다. 클립이 바뀌면 다시 굽는다(쿡 의존). |
| M1 브루트포스 탐색 | 일정 간격으로 현재 특징과 모든 행을 비교해 가장 가까운 프레임을 고른다. 가속 구조(KD 트리 · 묶음 경계 상자)는 측정 뒤에 넣는다. 노드는 `AnimationPoseNodeType::MotionMatching` 이다. |
| M2 inertialization | 고른 프레임이 지금과 다르면 `PoseInertializer` 로 건너뛴다(3절의 선행 구조). |
| M3 에디터 | 탐색 결과 · 비용 항목 · 궤적을 보는 디버그 창. 특징 가중치를 고치면 데이터에 쓴다. |
| 제외 | 군중 묶음 공유(`AnimationCrowd`)는 모션 매칭 유닛에 쓰지 않는다. 유닛마다 입력(궤적)이 달라 같은 포즈를 나눌 수 없다. |

## 5. 측정 질문

다시 열면 먼저 이것을 잽니다.

- 특징 행렬 크기(행 수 × 차원)와 브루트포스 한 번의 시간. 캐릭터 몇 명까지 프레임 예산 안인가.
- 탐색 간격(0.1 · 0.2 초)에 따른 반응 지연과 비용.
- inertialization 반감기에 따른 발 미끄러짐과 반응성.
- 블렌드 스페이스 + 속도 매칭 + 보폭 워핑 대비 발 미끄러짐이 얼마나 줄어드는가(같은 입력 녹화로 비교).
