# UI 후보

> 상태: 후보 · 선행: 없음 · 영역: ui · 진행: 해당없음

런타임 UI, 글자 렌더링, 접근성, DPI 에서 아직 안 한 일의 목록이다. 착수하면 절을 계획 문서로 옮기고 여기서 지운다.

## 한눈에 보기

| 절 | 한 줄 설명 | 착수 조건 |
|---|---|---|
| AtSpiBridge | 리눅스 스크린 리더(AT-SPI) 브리지의 좌표 보정 | 즉시 착수 가능 |
| MarkerComputeProjection | 화면 마커 투영 · 컬링을 컴퓨트로 | 게임 HUD 마커 2,000 개 초과 |

## 기능

### AtSpiBridge
제목: 리눅스 AT-SPI 스크린 리더 브리지
왜 필요한가: Windows 는 UI Automation 브리지가 있지만 리눅스 클라이언트는 Orca 같은 스크린 리더에 닿는 길이 없다. 접근성 트리와 브리지 계약은 플랫폼과 무관해 AT-SPI 구현(`AtSpiAccessibilityBridge.cpp`, `-DSW_ENABLE_ATSPI=ON`, 기본 끔)만 있고 리눅스에서 지어 본 적이 없다.
착수 조건: 없음.
남은 첫 일: 사각형에 창 위치를 더해 화면 좌표로 맞춘다(지금은 창 클라이언트 기준이라 확대기 · 강조 상자가 어긋난다).
함정: 브리지는 위젯을 쥐지 않고 스냅샷에서 (화면 핸들, 위젯 번호)로 찾는다(UIA 와 같다). 스크린 리더가 안 붙었으면 일하지 않는다(`isClientActive`).

## 조건부

### MarkerComputeProjection
제목: 화면 마커의 투영 · 컬링을 컴퓨트로
왜 필요한가: 이름표 2,000 개에서 게임 스레드 `GT.UI.Markers` 가 p50 0.5 ms 쯤 남는다.
착수 조건: 게임 HUD 에서 마커가 2,000 개를 넘을 때. 지금 마커를 쓰는 곳은 `Source/Games/Empty` 벤치뿐이다.
남은 첫 일: 컴퓨트가 GPUScene 변환을 읽어 앵커 표를 쓰게 한다(마커 ↔ GPU 인스턴스 대응 필요, 렌더러 영역). 데미지 숫자처럼 시간 함수로만 움직이는 UI 의 GPU 애니메이션도 같은 길이다.
