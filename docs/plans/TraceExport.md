# 트레이스 내보내기 계획 — Chrome Tracing 형식으로 저장하고 열기

상태: X1(변환기와 저장)과 X2(긴 캡처 `profile.trace record`), X3(에디터 Timeline 탭에서 불러오기 · 겹쳐 비교 · 구간 검색)는 2026-10-11 에 들어갔다. 둘 다 Shipping 에서는 빠진다(`SW_PROFILER_TRACE_ENABLED`, 사용자 결정). 남은 단위는 아래 순서대로 진행한다.

## 왜 필요한가

프로파일러가 시간축을 보여 주는 곳은 둘입니다. 에디터 Timeline 탭은 최근 몇 프레임만 보이고 저장하지 못합니다. Tracy 는 깊이 있게 보지만 뷰어를 따로 깔고 같은 PC 에서 붙어야 하며 Shipping 에는 없습니다.
그래서 다음 일이 어렵습니다.

- CI 성능 회귀가 실패했을 때 "어느 스레드의 어느 구간이 늘었나"를 볼 파일이 없습니다.
- 운영 서버에서 느린 틱이 났을 때 그 틱의 시간축을 개발 PC 로 가져올 길이 없습니다.
- 버그 보고(`bugit`)에 시간축을 같이 붙일 수 없습니다.
- 서버와 클라이언트의 시간축을 한 화면에 놓고 비교할 수 없습니다.

Chrome Tracing 의 Trace Event 형식(JSON)은 사양이 공개돼 있고 `chrome://tracing` 과 Perfetto UI(Apache-2.0, 오프라인으로 빌드해 쓸 수 있다)가 읽습니다. **뷰어를 새로 만들지 않고 파일만 내면** 위 일이 풀립니다.

## 지금 있는 것

| 바닥 | 있는 것 | 한계 |
|---|---|---|
| 기록 | `ProfilerTimeline`(`Source/Engine/Profiling/ProfilerTimeline.h`) — 스레드마다 링 버퍼(8192 사건), 프레임 시작 시각 링 64 개, 스레드 이름 | 최근 몇 프레임만 남는다 |
| 보기 | 에디터 프로파일러 패널(`Source/Editor/Panels/ProfilerPanel.h`)의 Timeline · Call Tree 탭 | 저장 · 불러오기 없음 |
| 저장 · 열기 | `ProfilerTraceExport` — 저장 · 긴 캡처 · 읽기, 에디터 Load Trace | 여러 프로세스 합치기는 아직 |
| 외부 | Tracy(`Source/Engine/Profiling/README.md`) | 뷰어 설치 · 같은 PC · Shipping 없음 |
| GPU | 패스마다 GPU 시간, Tracy 로 내는 `GPUTimelineExporter` | JSON 으로는 안 나간다 |

## 단위 (위가 아래의 바닥)

### X4 여러 프로세스 합치기

서버와 클라이언트의 트레이스를 한 타임라인에 놓습니다.

- 각 파일의 머리말(벽시계와 단조 시계 쌍)로 시간 오프셋을 맞추고 프로세스마다 줄 묶음(`pid`)으로 합친다. 같은 PC 면 거의 정확하고, 다른 PC 면 시계 차이 한계를 화면에 적는다.
- 서버 디버깅 계획의 S1(멀티 프로세스 재생)이 프로세스마다 트레이스를 모으고, 이 단위가 합친다. 한 입력이 클라이언트에서 서버 틱 처리까지 가는 시간을 한 화면에서 보는 것이 목표다.
- 흐름 이벤트(`s` · `f`)로 메시지 하나가 보낸 프로세스에서 받은 프로세스로 가는 화살표를 그릴 수 있다 — 네트워크 메시지 id 가 양쪽 계측에 있으면.

### X5 자동 첨부

사람이 누르지 않아도 트레이스가 남게 합니다. `bugit` 은 타임라인 기록이 켜져 있으면(`profile.trace on`) 같은 폴더에 `trace.trace.json` 을 담는다(끝났다). 남은 것:

- 성능 회귀 스크립트가 실패하면 트레이스를 아티팩트로 올린다(CI).
- 서버 운영 계획 O1 의 "느린 틱 자동 캡처"가 이 형식을 쓴다 — 틱이 예산을 넘으면 그 틱 앞뒤의 링 버퍼를 저장.

## 순서

X5(`bugit` 첨부는 끝났다) → X4(X1 ~ X3 은 끝났다). X4 는 서버 디버깅 계획(`docs/plans/ServerDebug.md`) S1 · S5 와 함께 정한다.

## 정한 것 · 지키는 것

- 뷰어는 만들지 않는다. 외부 뷰어(Perfetto UI · `chrome://tracing`)가 읽는 파일을 낸다. Tracy 는 깊은 분석 도구로 그대로 둔다 — 둘은 역할이 다르다(이식성 · 공유 대 정밀).
- 서드파티 JSON 라이브러리를 들이지 않는다. 이미 쓰는 JSON 기록기로 쓴다.
- Shipping 에서는 내보내기 코드를 컴파일하지 않는다(사용자 결정 2026-10-11 — `SW_PROFILER_TRACE_ENABLED`). 운영 서버의 느린 틱 캡처(X5)는 Shipping 서버가 아니라 Dev 구성 서버나 별도 진입점으로 풀 것인지 X5 에서 다시 정한다.
- 단위마다 확인은 자동 시나리오와 단위 시험으로 한다.
