# 이름 변경 리다이렉트 계획 (2026-10-17)

> 상태: 끝 · 선행: 없음 · 영역: engine · 옛번호: 없음 · 진행: 해당없음

세이브 · 에셋 · 씬(A 형식)을 읽을 때 이름이 바뀐 열거자 · 열거형 · 필드를 호출부 변환 함수 없이 읽게 하는 설계입니다. R1~R5 가 모두 끝났고(R5 의 `SW_SCHEMA_MIGRATION` 등록은 2026-10-23 첫 출시 전 규칙으로 지웠다), 정한 내용은 [결정 기록](../09_Decisions.md) 5-4 "이름 변경 리다이렉트" 에 있습니다.
"엔진 데이터에는 별칭을 두지 않는다"는 5-4 의 옛 결정은 지금 이관할 출시 데이터가 없다는 사실에 기댄 것이고 영구 금지가 아닙니다(사용자 확인). 출시한 데이터가 생겼을 때 바로 쓰도록 기능은 미리 갖춥니다.

## 1. 지금 동작

근거: `Source/Engine/Serialization/Format/BinarySerializer.cpp`, `Base/SerializerUtil.cpp`, `Base/SchemaMigrate.cpp`, `Engine/Reflection/ReflectionTypes.h`(`EnumInfo`).

| 변경 | 선언 | 선언이 없을 때 |
|---|---|---|
| 필드 추가 | 없음 | 선언한 기본값으로 채웁니다. |
| 필드 이름 변경 | `PROPERTY( Alias = "old" )` | 엄격한 읽기가 실패합니다. soft 읽기는 orphan 으로 남기고 버린 이름을 경고합니다. |
| 필드 삭제 | 없음 | 위와 같습니다. 모르는 칸을 받는 문맥(오브젝트 상태)은 그 칸만 건너뛰고 한 번 알립니다. |
| 열거자 이름 변경 | `ENUM( ValueAlias = "Old:New" )` | 그 칸의 읽기가 실패합니다(값은 그대로). |
| 열거자 삭제 | `ENUM( Removed = "Old:Replacement" )` | 위와 같습니다. |
| 열거형 타입 이름 변경 | `ENUM( Alias = OldName )` | 기록 타입을 몰라 그 칸의 읽기가 실패합니다. |
| 열거자 값 · 순서 변경 | 없음 | 안전합니다(이름이 정체성입니다). |
| 구조 변환(값 계산이 불가피한 경우) | 없음 — 이관 함수를 두지 않는다(2026-10-23, 첫 출시 전 규칙) | 판이 다르면 읽지 않고 오류로 멈춥니다. 저장소의 데이터를 다시 씁니다. |

## 2. 설계

상용 엔진의 장점을 합칩니다.

- 유니티 `FormerlySerializedAs`: 이력이 선언 바로 옆에 있습니다.
- 언리얼 `CoreRedirects`: 읽기 때 옛 이름을 현재 이름으로 바꾸고 호출부는 모릅니다.

규칙:

1. 이력은 헤더 선언에 적습니다(열거자 · 열거형 · 필드). 코드 생성기가 읽습니다. 값의 정본은 데이터이고 코드는 형식만 가집니다.
2. 생성기가 등록 때 리다이렉트 표를 채웁니다. 표는 그 이름의 주인(`EnumInfo::_mapRedirectNameToValue`, `PropertyInfo::_listAlias`, `TypeRegistry` 별칭 표)이 듭니다.
3. 읽기는 지금 이름을 모두 본 뒤에만 표를 봅니다. 바이너리와 텍스트가 같은 표를 씁니다.
4. 삭제는 대체를 명시합니다(`Removed` 에 대체 열거자). 선언이 없으면 오류로 멈춥니다. 조용한 기본값은 두지 않습니다.
5. 리다이렉트는 읽기 호환용이라 바이트 배치와 무관합니다. **B 스키마 해시의 정규 문자열에 넣지 않습니다**([리플렉션 형식 계획](ReflectionFormats.md) 3.11).
6. 잘못 적은 선언(꼴이 틀림, 대상이 지금 열거자가 아님, 옛 이름이 지금 이름과 겹침, 같은 옛 이름 두 번)은 생성 오류입니다.

## 3. 같은 결함이 다른 곳에 있을 수 있는가

- 필드 삭제는 열거자의 `Removed` 같은 선언이 없습니다. 모르는 칸을 받는 문맥(오브젝트 상태)은 선언 없이도 건너뜁니다. 지운 필드를 선언으로 받게 할지는 지운 필드를 받아야 하는 출시 데이터가 생길 때 정합니다.
- 리다이렉트 검사는 같은 타입 안만 봅니다. 기반 클래스의 지금 필드 이름과 겹치는 옛 이름은 생성기가 모르고, 읽기가 지금 이름을 먼저 보는 순서로만 막습니다(`ReflectionSerializationTest.CurrentFieldNameWinsOverAnOldName`).
