# 이름 변경 리다이렉트 계획 (2026-10-17)

**보류(2026-10-17).** 옛 이름 표는 "엔진 데이터에는 별칭을 두지 않는다"는 [결정 기록](../09_Decisions.md) 5-4 와 충돌합니다. 사용자가 그 결정을 바꾸기 전에는 구현하지 않습니다. 구현 브랜치 `wt/renameredirect`(R1~R3, 옛 R4 포함)는 병합하지 않고 남겨 두었습니다. 별칭이 아닌 R4(필드 추가 · 삭제 · 이름 변경 왕복 테스트)와 R5(변환 함수 자동 연결)는 따로 떼어 끝냈습니다(2026-10-17, `SchemaMigrationRegistry`).

세이브 · 에셋 · 씬(A 형식)을 읽을 때 이름이 바뀐 열거자 · 열거형 · 필드를 호출부 변환 함수 없이 읽게 하는 설계입니다. 구현은 [리플렉션 형식 계획](ReflectionFormats.md) 단계 1 이 병합된 뒤에 시작합니다(생성기의 열거형 등록과 파일이 겹칩니다).

## 1. 지금 구멍

조사 근거: `Source/Engine/Serialization/Format/BinarySerializer.cpp`, `Base/SerializerUtil.cpp`, `Base/SchemaMigrate.cpp`.

| 변경 | 지금 동작 |
|---|---|
| 필드 추가 | 기본값으로 채웁니다. |
| 필드 삭제 · 이름 변경 | (타입, 기록된 버전)에 등록된 변환 함수(`SW_SCHEMA_MIGRATION`)가 없으면 오류로 멈춥니다. 기본은 데이터를 다시 쓰는 것이고, 값 계산이 불가피한 예외만 변환 함수를 씁니다(경로는 `ReflectionSerializationTest.BinaryFieldAddRemoveRenameRoundTrip` 이 고정). |
| 열거자 이름 변경 · 삭제 | 이름 해시가 저장돼 있어 필드 읽기가 실패합니다. 변환 함수도 닿지 않습니다. |
| 열거형 타입 이름 변경 | 기록된 FQN 이 레지스트리에 없어 변환할 수 없습니다. |
| 열거자 값 · 순서 변경 | 안전합니다. |

변환 함수는 타입 옆 .cpp 에 한 줄로 등록하고 읽기가 `SchemaMigrationRegistry` 에서 찾습니다. 호출부는 함수를 넘기지 않으므로 빠뜨릴 자리가 없습니다.

## 2. 설계

상용 엔진의 장점을 합칩니다.

- 유니티 `FormerlySerializedAs`: 이력이 선언 바로 옆에 있습니다.
- 언리얼 `CoreRedirects`: 읽기 때 중앙 표 한 곳에서 옛 이름을 현재 이름으로 바꾸고 호출부는 모릅니다.

규칙:

1. 이력은 헤더 선언에 적습니다(열거자 · 열거형 · 필드). 코드 생성기가 읽습니다. 값의 정본은 데이터이고 코드는 형식만 가집니다.
2. 생성기가 등록 때 중앙 리다이렉트 표를 채웁니다. 키는 옛 이름 해시, 값은 현재 대상입니다.
3. 읽기는 정상 경로가 실패할 때만 이 표를 한 번 찾습니다. 정상 경로 비용은 없습니다.
4. 삭제는 대체를 명시합니다(`Removed` 에 대체 열거자). 선언이 없으면 지금처럼 오류로 멈춥니다. 조용한 기본값은 두지 않습니다.
5. 리다이렉트는 읽기 호환용이라 바이트 배치와 무관합니다. **B 스키마 해시의 정규 문자열에 넣지 않습니다**([리플렉션 형식 계획](ReflectionFormats.md) 3.11).

## 3. 구현 순서

| 단계 | 내용 | 건드릴 파일 |
|---|---|---|
| R1 | 열거자 옛 이름 · 열거형 옛 FQN 선언, 중앙 표, 읽기 연결 | 생성기 열거형 등록, `SerializerUtil.cpp`, `SchemaMigrate.cpp`, `EnumName.*` |
| R2 | 필드 옛 이름 | 생성기 필드 등록, `BinarySerializer.cpp` |
| R3 | 열거자 `Removed`(대체 명시) | 위와 같음 |

검증: 옛 이름으로 쓴 바이트를 새 타입이 읽는 테스트, 선언 없는 삭제가 오류로 멈추는 테스트, 정상 경로가 표를 찾지 않는지, 스키마 해시가 이력 선언 유무와 무관한지.

## 4. 같은 결함이 다른 곳에 있을 수 있는가

텍스트 형식(XML · 데이터 파서)이 열거자 이름 문자열을 읽는 경로(`_mapNameToValue`)도 같은 이름 변경에 약합니다. R1 에서 같은 표를 쓰게 합니다.
