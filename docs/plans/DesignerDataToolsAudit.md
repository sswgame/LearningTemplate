# 디자이너용 데이터 도구 점검

> 상태: 구현대기 · 선행: 없음 · 영역: editor · 옛번호: D3-13 · 진행: 1/6

스크립팅 층을 두지 않으므로([결정 기록](../09_Decisions.md) 2절) 코드 없이 로직 · 재질 · 효과를 짜는 도구가 중요하다. 2026-10-22 에 코드로 지금 상태를 확인했고(D0), 빠진 것을 단위로 쪼갰다.

## 1. 지금 있는 것(D0, 코드 확인)

| 도구 | 있는가 | 근거 |
|---|---|---|
| 노드 그래프 위젯 | 있음 | `Editor/Common/Widgets/EditorNodeGraph` (imgui-node-editor, 규칙 `EditorNodeGraphRules`). 애니메이션 그래프 · 대화 그래프 · 기믹 회로 그래프가 쓴다 |
| 애니메이션 상태 머신 | 있음 | `AnimationGraphPanel`(노드 · 조건 전이 · 레이어와 마스크 `AnimationGraphLayerEditor`) |
| 게임플레이 논리 회로 | 있음 | `GimmickGraphPanel`(GameFramework 에디터 플러그인 Base, 기믹 회로 데이터) |
| 대화 그래프 | 있음 | `DialogueGraphPanel` |
| 머티리얼 편집 | 값 편집만 | `MaterialPanel` 은 마스터 머티리얼 XML 의 값과 미리보기 구다. 노드로 셰이더를 짜는 그래프는 없다 — 셰이더 논리는 HLSL 이다 |
| 행동 트리 | 실행기만 | `GameFramework/Base/Actor/AI/BehaviorTree.h` — 코드로 `addNode` 해 짓는다. 데이터 형식(파일)도 편집기도 없다 |
| 파티클 | 보기 + 표 편집 | `VfxPreviewPanel` 은 보기 전용(같은 파일을 두 편집기가 쥐지 않게), 효과 파일(`*.vfx.xml`, 데이터 종류 `vfx`)은 카탈로그 편집기(`CatalogPanel`)의 표 편집으로 고친다. 곡선 · 그래디언트 전용 편집은 없다 |

## 2. 단위

| 단위 | 내용 | 상태 |
|---|---|---|
| D0 | 지금 상태 점검(1절) | 끝남 |
| D1 | 행동 트리 데이터 형식 — 데이터 종류 `behaviortree`(`*.bt.xml`)와 로더가 `BehaviorTree::addNode` 로 짓는다. 노드 종류 · 블랙보드 조건 · 중단 규칙의 이름표는 리플렉션 열거형에서. 코드로 짓는 게임(RTS 지휘관 AI)을 데이터로 옮긴다 | 남음 |
| D2 | 행동 트리 편집기 — `EditorNodeGraph` 위의 트리 편집과 플레이 중 활성 노드 표시(언리얼 Behavior Tree 에디터 디버그) | 남음 |
| D3 | 머티리얼 그래프를 둘지 결정 — 노드 → HLSL 생성과 셰이더 캐시 · 쿠킹의 비용 대비, 마스터 머티리얼 + 값(지금)으로 충분한지. 결정 기록에 적는다 | 남음 |
| D4 | VFX 곡선 · 그래디언트 편집 — 카탈로그 표 편집 안의 칸 위젯으로(미리보기 창은 보기 전용 규칙을 지킨다) | 남음 |
| D5 | 일반 게임플레이 상태 머신이 기믹 회로 그래프로 갈음되는지 판단 — 갈음되면 이 줄을 지우고, 아니면 데이터 형식부터 단위로 | 남음 |

## 남은 것

- 순서: D1 → D2(데이터가 먼저), D3 은 결정만이라 따로, D4 · D5 는 병렬.
- 함정: D1 의 로더는 모르는 노드 종류 · 칸을 오류로 멈춘다(폴백 금지) — 데이터 주도 계획의 읽기 규칙(`readRequiredAttribute`)을 쓴다.
