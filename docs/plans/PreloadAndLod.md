# 프리로딩 · LOD · 사전 준비

> 상태: 구현중 · 선행: 없음 · 영역: gameplay · 진행: 10/11

컷이나 레벨 전환에서 LOD · 텍스처 · 셰이더가 바뀌는 게 보이지 않도록 미리 로드하고 준비한다. 남은 것은 GPU 인스턴스 LOD(P9, 셰이더 작업)뿐이다.

## 진행

| 단위 | 내용 | 상태 |
|---|---|---|
| P1 | 프리로드 세트 `PreloadSet` — 경로 목록을 동시 요청 상한 안에서 스트리밍 큐에 요청, 진행률 · 완료 · 실패 목록 | 끝 |
| P2 | 에셋 고정 `PreloadSet::enablePinning` — 읽은 바이트 수 비용, 예산 초과 시 가장 오래 안 쓴 것부터 놓는다(`AssetPinSet`, LRU) | 끝 |
| P3 | 프리팹 풀 `PrefabPool` — 돌려받은 인스턴스를 끄고 쉬게 했다가 다시 내준다(`prewarm`) | 끝 |
| P4 | 컷 준비 LOD — 대기 뷰 카메라를 프레임마다 `AnimationSystem` · `MeshLODSystem` 에 넣는다 | 끝 |
| P5 | 메시 LOD — 임포트 규칙 `lods` → `meshopt_simplify` → `.mesh` 의 `LODS` 덩어리, `MeshLODSystem` 이 화면 크기로 단계 선택 | 끝 |
| P6 | PSO 미리 만들기 — 고정한 머티리얼의 PSO 를 기록 전에 만든다(`FrameRenderer::warmPinnedMaterialPSOs`) | 끝 |
| P7 | 텍스처 밉 스트리밍 — 아래쪽 밉 먼저, 위쪽 밉은 프레임당 둘씩 교체(`TextureCache::updateStreaming`) | 끝 |
| P8 | 자동 수집(`<씬>.preload.json`)과 시퀀서 사전 스폰(`Spawn` 항목) | 끝 |
| P9 | GPU 인스턴스 LOD 와 디더 크로스페이드 | 남음(셰이더) |
| P10 | 텍스처 밉 요청 우선순위(`TextureStreamingSystem`), 그림자는 미리 맞출 상태가 없어 불필요 | 끝 |
| P11 | 확인 — 테스트 묶음 작성, 눈 확인은 남음 | 끝 |

## 설계 요약

- **에셋 고정.** 텍스처는 디바이스가 있어야 요청하므로 그것을 쓰는 머티리얼의 고정이 붙든다.
- **메시 LOD.** `Mesh` 는 LOD 0 을 CPU 정점으로 두고(물리 · 내비 · 피킹은 LOD 0) 낮은 단계를 정점 흐름 뒤에 잇는다. 고운 쪽 전환은 10 % 여유를 둔다. 모프 · 구간이 있는 메시는 LOD 를 받지 않는다. LOD 없는 파일은 바이트 그대로다.
- **PSO.** 씬에 있는 머티리얼은 렌더러가 배치마다 PSO 를 만들어 이미 준비돼 있다. 고정한 머티리얼(다음 레벨 · 컷)만 등장 디더 변형까지 미리 만든다.
- **밉 스트리밍.** 옛 GPU 자원은 이미 만든 패킷이 끝날 때까지 미룬다. 시나리오 스크린샷은 위쪽 밉이 다 들어올 때까지 기다린다. 끄기 `-gv_textureStreaming=0`.
- **자동 수집.** 쿠킹이 씬마다 옆에 `<씬>.preload.json` 을 굽는다. 씬 문서를 런타임과 같은 길로 지어(프리팹 스폰 · 중첩 포함) 컴포넌트의 에셋 경로 프로퍼티를 리플렉션으로 모은다. `SceneManager::requestLoadFuture` 가 목록으로 `PreloadSet`(고정 켬)을 열고, 로드가 끝난 뒤 `gv_scenePreloadHoldFrames` 프레임 붙들었다 놓는다. 진행률은 `tryGetLoadProgress` 로 로딩 화면 슬라이더가 그린다. 끄기 `gv_scenePreload`. 머티리얼이 쓰는 텍스처는 싣지 않는다. 쿠킹 전 Dev 실행은 목록이 없어 에셋을 잡을 때 읽는다.
- **시퀀서 사전 스폰.** `Spawn` 항목이 구간 시작 프리롤 앞에 프리팹을 꺼 둔 채 스폰해 첫 포즈 · 머티리얼 · PSO 를 준비하고, 구간 동안 켜며 끝나면 지운다.
- **밉 요청 우선순위.** 위쪽 밉을 기다리는 텍스처가 있을 때만 메시 컴포넌트마다 화면 크기를 구해 텍스처에 가장 큰 값을 알리고, 큰 것부터 올린다. UV 밀도는 모르므로 화면 크기만 쓴다. 끄기 `gv_textureStreamByScreenSize`.
- **그림자(P10).** 캐스케이드는 매 프레임 뷰-투영에서 새로 맞추고 이력 · 캐시가 없으므로 미리 데울 것은 에셋과 PSO 뿐이다.

## P9 — GPU 인스턴스 LOD 와 크로스페이드 (남음)

지금은 컴포넌트마다 CPU 에서 단계를 고르고(`MeshLODSystem`), 단계가 바뀌면 배치 키가 달라져 그 프레임은 다시 나누고 정렬한다. 목표는 GPU 컬링(`gpucull.hlsl`)이 인스턴스마다 단계를 고르고 단계 사이를 디더 크로스페이드로 넘기는 것이며, 컷 프레임과 대기 뷰는 크로스페이드를 끈다.

**왜 안 했나.** 셰이더 소스를 커밋하면 빌드한 `App --cook-shaders` 로 전 백엔드 바이너리를 구워야 하는데, 빌드 · 테스트 없이 건드리면 안 되는 불변식이 겹친다. 단계 임계값은 `Mesh::selectLOD` 가 이미 정하므로 CPU 쪽 선행은 없다.

**처음 볼 곳:**
1. `GPUSceneSnapshot::appendBatch` 는 배치 인스턴스 구간이 앞 배치 끝에서 빈틈없이 이어진다고 단언하고, 가시 목록 버퍼는 인스턴스 수 길이다. 단계마다 구간이 필요하면 단계 수만큼 곱한 용량이나 그룹 안 압축이 필요하다.
2. `GPUBatchInfo`(32 B)는 `_pad2` 한 칸, `InstanceData` 는 `_reserved1` 한 칸만 남았다. 단계 그룹(첫 배치 번호 · 단계 수 · 임계값)은 별도 표가 필요하다.
3. 배치 분할 지점은 `DrawCandidate::hasSameBatchKey`(현재 CPU 가 고른 단계의 메시 구간이 키에 있다)이고, 같은 키를 쓰는 증분 경로(`refreshInstancesInPlace` · `swapSingleInstanceBatchMeshes` · `GPUTransparentSorter`)가 모두 새 그룹 구조를 따라야 한다.
4. 스키닝 · 모프 · VAT 는 단계마다 정점 풀 구간이 달라 `_sectionVertexOffset` · `_morphVertexBase` 도 단계별이어야 한다. 1차는 정적 불투명 메시만 그룹으로 만들고 나머지는 CPU 단계로 남기는 것이 현실적이다.
5. 크로스페이드는 전환 중 인스턴스를 두 단계 목록에 모두 쓰므로 가시 기록이 인스턴스당 둘이 될 수 있다.

**이번 세션 조사(구현은 하지 않았다 — 빌드 · 테스트 없이 아래 불변식 여럿을 동시에 바꿀 수 없다):**
- 크로스페이드를 CPU 에서 하려면 컴포넌트 하나가 전환 중 후보 둘(새 단계 + 옛 단계)을 내야 하는데, `GPUSceneBuilder` 의 후보 목록은 프리미티브 슬롯과 1 : 1 이다(`_listScratchCandidate` · `_listCandidateToInstance` · 증분 경로의 더티 슬롯이 모두 그 가정). 유령 컴포넌트를 만드는 길은 소유 오브젝트 · 스킨 · 머티리얼 인스턴스 수명을 다시 설계해야 해서 택하지 않았다.
- 디더 크로스페이드의 셰이더 쪽은 작다: `_appearance`(0..1, `Appearance::clipDither`)에 `[-1, 0]` 을 "상보 패턴" 으로 쓰면(`visible = threshold >= appearance + 1`) 새 단계(`p`)와 옛 단계(`p - 1`)가 같은 임계값 격자에서 겹침 없이 화면을 나눈다. `usesAppearanceDither()`(`_appearance < 1`)는 이미 그 값을 디더 변형으로 보낸다. 투명 배치는 디더 대상이 아니다.
- GPU 단계 선택의 최소 구조: 그룹의 단계 배치들은 인스턴스를 복제하지 않고 **한 번만** 두고(인스턴스 `_meshBatchIndex` = 그룹 첫 배치), `gpucull.hlsl` 이 화면 크기로 단계 `k` 를 골라 배치 `first + k` 의 `instanceCount` 를 올리고 그 구간의 가시 칸에 쓴다. 그러려면 (a) 단계 배치마다 인스턴스 수만큼의 가시 구간(구간 합 = 인스턴스 수 × 단계 수), (b) `appendBatch` 의 "구간이 이어진다" 단언을 인스턴스 구간과 가시 구간으로 가르기, (c) 그룹 표(첫 배치 · 단계 수 · 임계값 — `GPUBatchInfo` 의 `_pad2` 하나로는 모자란다), (d) DX11 처럼 GPU 컬링이 없는 백엔드는 CPU 단계 선택을 그대로 두는 두 갈래(폴백 금지 원칙과 부딪히므로 능력 플래그로 가른다)가 필요하다.
- 착수 순서 제안: ① 가시 구간과 인스턴스 구간 분리(동작 변화 없음) → ② 그룹 표 + `gpucull` 단계 선택(정적 불투명만, `gv_` 로 끔) → ③ 상보 디더 + 전환 상태(전환 중 인스턴스만 두 구간에 쓴다, 가시 기록 둘).

## P11 — 확인

- 자동: PreloadSet · PinSet · `PrefabPool` · 애니메이션 LOD 대기 뷰 · `.mesh` LOD 왕복 · LOD 단계 선택 · 임포터 LOD 규칙 · 씬 프리로드 목록 · 씬 쿠킹 · 시퀀서 Spawn · 로딩 화면 테스트와, GPU 의 비동기 텍스처 밉 · 화면 큰 순서 업로드 테스트.
- 눈 확인(남음): 시퀀서 컷 프리롤 시나리오로 컷 첫 프레임 포즈가 튀지 않는지, `-gv_meshLodForce=N` 으로 단계마다 캡처해 그려지는지. LOD 가 든 실제 모델과 스폰 항목을 쓴 시퀀스가 아직 없다.
