# 규칙 예외 감사에서 정한 일의 적용

> 상태: 구현대기 · 선행: 없음 · 영역: project · 옛번호: C-11 · 진행: 2/4

2026-10-07 규칙 예외 감사에서 정한 넷([결정 기록](../09_Decisions.md) 5-2 "규칙 예외 감사에서 정한 넷")의 적용 상태다. 결정과 근거는 결정 기록에 있고 여기는 적용 단위만 적는다.

## 1. 단위

| 단위 | 내용 | 상태 |
|---|---|---|
| E1 | 백엔드 명령줄 철자는 `-dx12` · `-dx11` · `-vk` · `-gl` 하나씩(쿠킹 표 `command_line_name` 이 정본) | 끝남(결정 기록 5-2 "App 의 백엔드 명령줄 철자는 백엔드마다 하나입니다", 2026-10-07) |
| E2 | `(void)` 와 이유 주석은 `[[nodiscard]]` 를 붙인 실패 가능 함수에만 요구한다 | 끝남(`CheckDiscardReason` 이 실패 가능 동사의 결과만 보고 그 밖의 `(void)` 는 규칙 밖 — `lint/DiscardReasonRules.py`, `RunDiscardReasons`) |
| E3 | 두 플랫폼이 같은 명시적 경고 목록을 쓴다. 결정 때의 근거는 "clang-cl 의 `-Wall` 은 `-Weverything`" 이었다. 지금 `cmake/Modules/Compiler/Clang.cmake` 는 clang · clang-cl 모두 GNU 철자 `-Wall -Wextra` 와 `-Wno-*` 목록이고 `GCC.cmake` 는 `-Wall -Wextra`, 둘이 겹치는 `-Werror=*` 는 같다. 남은 것: (1) clang-cl 이 GNU 철자 `-Wall` 을 `-Weverything` 으로 받는지 `clang-cl -### -Wall` 의 출력으로 확인한다(빌드 아님). 받지 않으면 이 단위는 이미 만족이다 — 결정 기록의 "아직 적용 전" 을 지운다. (2) 받으면 `-Wall -Wextra` 를 `Clang.cmake` 한 곳의 명시 목록으로 바꾸고 두 플랫폼 경고 수를 견주는 전체 빌드가 필요하다 | 대기(컴파일러 호출 확인부터) |
| E4 | 출처를 모르는 리소스를 저장소에서 생성한 것이나 CC0 로 확인한 것으로 바꾼다. 먼저 `Resource/` 의 에셋별 출처(라이선스 메타)가 없는 파일을 `py -3 -m Scripts` 의 에셋 검증으로 모은다 — 목록이 없으면 이 단위의 첫 일은 그 목록이다 | 대기 |

## 2. 정리

- 결정 기록 5-2 의 "규칙 예외 감사에서 정한 넷(…아직 적용 전…)" 줄은 E3 · E4 가 끝나면 "적용함" 으로 고친다. E1 · E2 는 이미 적용됐다.
