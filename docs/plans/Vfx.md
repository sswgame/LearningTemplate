# 파티클 · VFX 구현 단위 (`D2-11`)

> 상태: 구현중 · 선행: 없음 · 영역: graphics · 옛번호: D2-11 · 진행: 2/7

결정은 [결정 기록](../09_Decisions.md) 5-12 의 `D2-11` 두 행과 옛 `D2-11` 본문의 사용자 결정이 원본입니다. 이 문서는 그 결정을 구현 단위로 나눈 계획과 단위마다의 계약을 적습니다.
단위가 끝나면 그 단위의 절을 지우고, 남는 교훈은 코드의 헤더 주석으로 옮깁니다.

## 1. 정한 것

- 시뮬레이션은 CPU 와 GPU 를 둘 다 만듭니다. 개발 빌드는 `gv_vfxSimulation` 으로 고르고, Shipping 은 GPU 로 고정하며 CPU 경로와 변수를 두지 않습니다.
- 데이터 형식(`*.vfx.xml`)과 렌더 입력 형식은 하나이고, 두 시뮬레이션이 같은 형식을 냅니다.
- 첫 모듈 형식은 고정 모듈과 값 커브(`FloatCurve`)입니다. 다형 목록과 그래프는 뒤로 미룹니다.
- 방출기 하나가 투명 정렬 후보 하나입니다. 입자 단위 정렬은 하지 않습니다.
- 서버는 시뮬레이션하지 않습니다(외형 전용). 2D 픽셀 퍼펙트 입자는 P1 에 넣지 않습니다.

## 2. 단위

| 단위 | 내용 | 선행 |
|---|---|---|
| V0 | 데이터 형식: `VfxEffectDef`(방출기 목록), `VfxEmitterDef`(생성률, 버스트, 수명, 초기 속도 범위, 중력, 크기와 색의 `FloatCurve`, 텍스처, 블렌드), 리플렉션 로드와 검증(필수 값이 없으면 로드 실패) — **들어감**(`VfxEffectDefTest` · 리소스 종류 `vfx`) | 없음 |
| V1 | CPU 시뮬레이션 `VfxCPUSimulation`: 고정 크기 풀, 결정적 난수(방출기 씨앗), 단계 하나 = 생성, 적분, 수명 제거(뒤쪽과 바꾸기). 출력은 렌더 입력 `GPUParticle`(float4 셋: 위치와 크기, 색, 회전과 수명 비율) — **들어감**(`VfxCPUSimulationTest`) | V0 |
| V2 | 렌더 경로: 방출기마다 빌보드 배치 하나를 GPUScene 투명 후보로 냅니다. 정점 셰이더가 `SV_VertexID` 와 입자 버퍼로 사각형을 만듭니다(캔버스 사각형과 같은 방식) | V1 |
| V3 | `VfxComponent`(효과 경로, 재생, 정지, 씨앗)와 에디터 미리보기 창(`EditorPreviewPanel`) | V2 |
| V4 | GPU 시뮬레이션 `vfxsimulate.hlsl`: 같은 모듈 의미를 컴퓨트로, 생존 수는 원자적 카운터, 간접 드로우 인자. DX11 은 구조 버퍼와 간접 인자를 한 버퍼로 못 쓰므로 복사 단계 하나를 더합니다 | V2, `D2-6.3` 슬롯 지도 |
| V5 | CPU 와 GPU 비교 테스트: 같은 씨앗, 같은 단계 수에서 입자 수가 같고 위치가 허용 오차 안입니다(hostgpu) | V4 |
| V6 | 메시 입자, 리본, 충돌(물리 레이캐스트), 파티클 라이트(`D2-13` S5) | V3 |

### V2 계약

- 입자 버퍼는 SRV 슬롯이 꽉 차 있어 `D2-6.3` 의 지도 재작성 전에는 캔버스 사각형 슬롯(t15)처럼 패스 전용 슬롯을 다시 쓰는 방법을 검토합니다. 결정은 그 단위에서 결정 기록에 남깁니다.
- 착수 전 확인한 현황(2026-10-20): 투명 후보는 메시 배치(`GPUMeshBatch`, `GPUSceneBuilder::emitTransparentBatches`)뿐이라 입자 배치는 스냅샷 형식 · 업로드 · 드로우(`FrameRendererDraw`) · PSO 를 새로 더해야 합니다. 슬롯은 `bindingslots.hlsli` 가 t0..t11(`SW_SRV_SLOT_COUNT` 12, 캔버스 사각형이 t11)이고 머티리얼 텍스처가 t12..t27 입니다(위 t15 는 낡은 번호). 셰이더 굽기 · 네 백엔드 · `hostgpu` 확인이 필요해 GPU 없이는 닫을 수 없습니다.
