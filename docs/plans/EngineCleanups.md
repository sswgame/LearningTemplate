## 1. 끝난 것

- `ConfigManager::isWithinRange` 삭제(호출부 없는 죽은 코드, 범위 검사는 `readConfigXMLElement` 와 `ConfigRangeUtil::collectRangeErrors` 한 곳).
- **StableAddressMap**: `sw::unordered_map` 은 원소를 밀집 배열에 두어 삽입이 모든 원소를 `erase` 가 마지막 원소를 옮긴다. `&it->second` 를 오래 쥐는 자리를 전수로 봤다 — 매달릴 수 있던 곳은 `LiveReloadManager::_mapModule` 의 `ModuleContext*` 하나(연쇄 리로드가 포인터를 쥔 채 `onAfterReload` 안의 모듈 등록이 새 키를 넣을 수 있다)였고 형식을 `Core/Container/stable_unordered_map.h`(값을 힙에 하나씩 두고 주소를 고정)로 바꿨다. 나머지는 반환 즉시 쓰는 조회다. 정본 규칙은 `unordered_map.h` 머리 주석 5-1: 다른 삽입 · 삭제를 거쳐 주소를 쥐어야 하면 `stable_unordered_map`(주소를 내주는 API 를 없앨 수 없어 이름이 다른 형식으로 갈랐다).
- **VectorAliasLoops**(코드 끝, 측정 대기): 1 바이트 타입(`char` 는 무엇과도 별칭)의 저장이 벡터 멤버 `_pData` 와 겹쳐 보이는 곳이 문제다. `DynamicBitset` 은 고쳤고 `sw::vector` 의 채우기(`assign( count, value )` · `resize( count, value )`)는 `fillConstructRangeInternal` 하나로 모아 버퍼 포인터를 지역으로 뜨게 했으며 `operator==` 도 두 포인터를 지역으로 뜬다. 읽기만 하는 비교 루프는 이득이 없을 수 있다 — `ContainerBenchTest.VectorBulkFillAndCompare` 를 변경 전후 바이너리로 번갈아 3 판 돌려 이득이 없는 쪽은 되돌린다.
- **StlContainerConfig**: 결정은 [결정 기록](../09_Decisions.md) 5-4 의 "`SW_ENABLE_STL_CONTAINER` 가 구성마다 바꾸는 것은 컨테이너 기본 할당자 하나" 줄(옵션 설명이 "엔진 할당자 대신 `std::allocator`" 라서 목적을 할당자로 읽었다 — 표준 컨테이너 비교가 목적이면 사용자가 되돌린다). `Memory.h` 에 `ContainerAllocator<T>` 별칭을 두고 `vector` · `array` · `pair` · `map` · `set` · `span` 은 두 구성 모두 자체 구현, `string` · `list` · `deque` 는 두 구성 모두 `std::*` 를 상속한 경합 탐지 클래스(기본 할당자만 구성별 — 별칭으로 줄이면 디버그 경합 탐지를 잃는다)로 했다. `InlineAllocator` 도 두 구성이 같다. STL 구성에서만 건너뛰던 케이스 열 곳은 두 구성에서 돈다(남은 STL 건너뜀은 `MemoryTagTest` 셋).
- **ReadNameAudit**: 근본 원인은 `XMLReadUtil::readName` 이 빈 이름으로 "적지 않음" 과 "잘못 적음" 을 가르지 못해 필수 이름의 빈 값 확인을 잊으면 조용히 지나가는 것이었다. `readName` 을 `readOptionalName` 으로 바꿔 필수가 이 이름으로 읽히지 않게 하고 `GameDataXML::readRequiredName`(`[[nodiscard]]`, 원소 · 속성 이름과 함께 오류) · `AppearanceXMLUtil::readRequiredName`(보고서에 오류)을 더해 `GameDataXML::readName` 35 곳 · `AppearanceXMLUtil::readName` 약 100 곳이 필수 · 선택을 고르게 했다. 조용히 지나던 곳(타이밍 창 `grade`, 어빌리티 이펙트 `<Execution class>` · 어빌리티 세트 항목, 퀘스트 단계 id · 목표, `AreaGraph::<Link>` 끝점, 외형 `<Morph>` · `<Material>` · `<HideRegion>`, 캐릭터 값 `name`/`option`)이 이제 오류로 나오고 이름 목록(`appendNameList` · `readNameList`)은 글 `none` 이 빈 이름으로 들어가던 것을 오류로 알린다. 경로 글로 바꿔 쓰는 빈 이름의 `.c_str()`("None")는 형식으로 막지 못한다.
- **EditorCommandIdForm**: 에디터 명령 id 의 선언 형식(`SW_EDITOR_COMMAND( 이름, "id", … )` 25 곳과 원본 표 `_s_arrCommandRow`)은 이미 있어 형식은 안 바꾸고 린트가 읽게 했다 — `CheckNameReferences` 의 `NameReference/EditorCommand` 가 시나리오 `<DevCommand line="editor <id>">` 의 id 를 두 선언의 id 와 견준다(첫 실행에서 `emptyscene.scenario.xml` 이 `scene.new` 를 `editor scene.new` 없이 불러 실행 때야 드러날 결함이 잡혀 고쳤다). 입력 액션 기본값은 `NameReference/InputAction`, 나머지 카탈로그 안 id 는 에셋 검증 규칙(`Config/Editor/AssetValidationRules.json` 의 `interaction-ids` · `appearance-preset-ids` · `camera-preset-ids` · `ability-set-ids` 등)이 본다.
- **AnimationUpdateAnomalies**(계측 끝, 측정 대기): 세 이상(본 150 → 300 의 2.5 배, 후처리 리그 300 본의 p99 3 배, 네 발 60 본의 실행 사이 흔들림)은 Release 측정이 있어야 원인을 가른다. `AnimationSystem::evaluate` 의 `BasePose` · `Attachment` · `PostProcess` · `SkinPalette` 단계마다 프로파일 구간(`GT.Animation.basePose` · `attachment` · `postProcess` · `skinPalette`)을 두었고 `SyntheticRigBenchTest` 가 가장 느린 프레임의 번호를 로그에 남긴다(처음 몇 프레임에 몰리면 첫 접근 비용, 흩어지면 스케줄러 · 판 사이 흔들림). 판 사이 흔들림은 이 기계의 일반 잡음(프레임 8 ~ 12 ms)일 수 있어 [결정 기록](../09_Decisions.md) 의 `crowdBuckets` 항목과 같은 방법(전후를 번갈아 5 판 이상)으로 본다. 원인이 나오면 그 단계의 코드를 고치는 것이 이 단위의 나머지다.
