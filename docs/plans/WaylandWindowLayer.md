# Wayland 창 계층

> 상태: 구현중 · 선행: 없음 · 영역: engine · 옛번호: D1-6 · 진행: 1/2

`Engine/Window/Linux` 가 X11 뿐이었다. 컴포지터 없이 지을 수 있는 백엔드 코드는 들어갔고(W1) 컴파일 확인은 없다.

## 1. 설계

- **고르기.** 환경 변수 `SW_WINDOW_BACKEND` = `x11`(없을 때도) | `wayland`. 모르는 값 · 짓지 않은 계층은 오류로 멈춘다(`IWindow::createPlatformWindow`).
- **짓기.** `SW_ENABLE_WAYLAND`(기본 끔, `cmake/Config/BuildOptions.cmake`)를 켜면 리눅스 클라이언트가 wayland-client · wayland-cursor · xkbcommon 을 pkg-config 로 찾고 wayland-protocols 의 `xdg-shell.xml` 을 wayland-scanner 로 C 코드로 만들어(`sw_wayland_protocols`, `cmake/Modules/Platform/Linux.cmake`) `SW_WITH_WAYLAND` 를 정의한다. 하나라도 없으면 구성이 선다.
- **표면의 종류는 타입에 있다.** `IRenderSurface::getSurfaceKind`(`NativeSurfaceKind` — Win32 · X11 · Wayland)가 핸들의 뜻을 말하고 스왑체인 서술(`RHISwapChainDesc::_surfaceKind`)이 싣는다. Vulkan 은 Wayland 면 `VK_KHR_wayland_surface` 만 받는다(X11 확장으로 대신하지 않는다). GL 은 GLX 라 X11 이 아닌 표면을 오류로 거절한다(EGL 길이 없다). 핸들은 종류 확인과 값 확인이 한 함수인 `tryGet*` 로만 얻는다(`IWindow::tryGetX11Surface` · `tryGetWin32Handle`, `[[nodiscard]]`, 다른 종류면 nullptr; `X11Window::tryCast` · `WaylandWindow::tryCast`) — 핸들만 꺼내는 `getNativeDisplay` · `getNativeHandle` 과 파생 클래스의 override 는 보호 구역이라 Wayland 의 `wl_display*` 를 `Display*` 로 읽는 호출을 바깥에서 쓸 수 없다. RHI 도 같은 모양이다(`RHISwapChainDesc::tryGetWin32Handle` — DX11 · DX12 · WGL · Windows Vulkan 은 Win32 표면이 아니면 오류로 멈춘다). 에디터 ImGui 뷰포트의 `PlatformHandle` 도 `IImGuiPlatformBackend::tryGetViewportX11Surface` · `tryGetViewportWin32Handle` 로만 읽고, 아니면 Vulkan 은 표면 생성을, OpenGL 은 그 뷰포트의 GL 자원 만들기를 오류로 거절한다(`glXGetCurrentDisplay()` 로 대신하지 않는다). X11 창이 아닌 창이 오면 X11 판 개발 콘솔은 만들지 않고(Wayland 창은 서브표면 판 `WaylandDevConsoleWindow`), 에디터 ImGui X11 백엔드는 오류로 멈추고(Wayland 창은 `ImGuiWaylandPlatformBackend` 가 팩토리에서 골라진다), 클립보드는 `isAvailable` 이 false 이며, 커서 모양은 한 번 알리고 건너뛴다.
- **창.** `WaylandWindow`(`Engine/Window/Linux/Wayland`)가 xdg-shell 최상위 창을 만들고 첫 configure 를 기다린다. 크기는 컴포지터가 준 값(0 이면 클라이언트), 닫기는 `xdg_toplevel.close` → `tryBeginClose`, 전체 화면 · 최소 크기 · 제목도 xdg-shell. 이벤트는 막지 않고 읽는다(prepare_read · poll 0 · read_events). 창 자리 · 숨기기는 Wayland 클라이언트가 할 수 없어 자리 함수는 비고 숨기기는 오류다. 화면 배율은 컴포지터가 `wp_fractional_scale_v1.preferred_scale`(1/120 단위)을 알렸으면 그 값이고, 그 프로토콜이 없는 컴포지터(정상)는 창이 걸친 `wl_output` 의 정수 배율 최댓값이다(버퍼 배율은 바꾸지 않는다 — 알려 주기만 하고 컴포지터가 확대한다). 선택 확장 넷(소수 배율 · 커서 모양 · pointer-constraints · relative-pointer)은 판 1 로 바인드하고 기동 로그 한 줄(`Wayland extensions: …`)에 있는지 없는지를 남긴다. 판이 오르면 바인드 상수와 리스너를 함께 올려야 한다(컴파일러가 알려 주지 않는다). 클립보드는 `wl_data_device` 선택 — 쓰기는 마지막 키 · 버튼 · 들어옴의 일련번호로 `wl_data_source` 를 내놓고(포인터 움직임에는 일련번호가 없다. 입력 없이 복사를 시키는 자동화 가상 입력만 일련번호가 없어 `PlatformClipboard::writeText` 가 경고와 false 를 돌려주고 `UIClipboardService::setText` 가 글 입력 칸에 전해 사용자 알림 경고를 올리며 잘라내기는 글을 지우지 않는다 — 시나리오가 그 경고를 처리해야 한다. `send` 는 막지 않는 쓰기로 200 ms 안에 못 쓰면 포기), 읽기는 선택 제안의 `text/plain;charset=utf-8`(없으면 `text/plain`)을 파이프로 받는다. 끌어다 놓기는 받지 않는다.
- **입력.** 리스너가 키보드(xkbcommon) · 포인터 · 포커스를 `WaylandInputEvent` 하나로 모아 `NativeWindowEvent::kMessageWayland` 로 넘긴다. 입력 관리자(`InputManagerX11.cpp`)는 창 종류를 가르지 않는다 — X11 서버 호출(보조 폴링 · 가운데 되돌리기 · AccessX 억제)은 `tryGetX11Surface` 가 true 일 때만 하고, 창이 스스로 하는 동작(커서 모양 · 포인터 묶기 · 커서 숨기기)은 `IWindow` 의 가상 질의 · 동작(`supportsCursorShape`/`setCursorShape` · `supportsPointerLock`/`setPointerLock` · `setCursorVisible`, 기본은 지원 안 함)으로 가른다. 청했는데 안 되면 입력 관리자가 오류를 한 번 남긴다(조용히 다른 길로 가지 않는다). 새 확장은 창에 질의 하나와 동작 하나를 더하면 된다(keysym 은 X11 KeySym 과 같은 번호라 키 표를 함께 쓴다). 커서 숨기기는 `wl_pointer_set_cursor`(보이기는 커서 모양 확장이 있으면 기억해 둔 모양, 없으면 커서 테마의 `left_ptr`). 커서 모양은 `wp_cursor_shape_manager_v1`(판 1)의 `set_shape` 이고(생성 코드가 `zwp_tablet_tool_v2` 를 가리켜 `tablet-unstable-v2.xml` 도 목록에 있다) 포인터가 들어올 때마다 다시 정하며, 확장이 없으면 기본 화살표 외 모양 요청에 오류 한 번을 남긴다. 포인터 잠금은 `InputManager::applyMouseLockMode` 가 `IWindow::setPointerLock` 으로 청한다 — `ConfinedToWindow` 는 `zwp_confined_pointer_v1`, `LockedInCenter` 는 `zwp_locked_pointer_v1`(둘 다 영속 수명)이고 잠긴 동안 `zwp_relative_pointer_v1` 의 가속 없는 이동량이 `PointerRelative` → `makeMouseRawDelta` 로 간다(`PointerMove` 는 오지 않고 가운데로 되돌리지도 않는다). 확장이나 포인터 장치가 없으면 false 와 오류 한 번이고 잠그지 않는다.

## 2. 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| W1 | 위 설계의 코드 — 빌드 옵션 · 프로토콜 생성 · `WaylandWindow` · 입력 갈래 · 표면 종류 · Vulkan WSI · GL 거절 | 코드 완료(빌드 안 함) |
| W3 | 코드 완료(컴파일 확인 없음): 클립보드(`WaylandWindow::readClipboardText` · `writeClipboardText` — `PlatformClipboard` 는 창 종류를 모르고 `IWindow::supportsClipboard` 로 잇는다. 데이터 장치가 없는 Wayland 창은 지원 안 함이라 UI 가 엔진 안 클립보드를 쓴다), 화면 배율(소수 배율이 있으면 그 값, 없으면 `wl_output.scale` 정수 배율 최댓값), 포인터 잠금 · 가둠(`setPointerLock`), 커서 모양(`setCursorShape`). 프로토콜 XML 은 `sw_wayland_protocols` 의 목록(`cmake/Modules/Platform/Linux.cmake`, wayland-protocols 1.32 이상)에 더했다. 에디터 ImGui 플랫폼 백엔드 · 스플래시 창 · 개발 콘솔 창도 코드 완료(컴파일 확인 없음 — 한 번도 컴파일되지 않은 Linux 코드이고 이 PC 에서는 글을 읽어 맞췄다): `ImGuiWaylandPlatformBackend`(`Editor/Common/Backend/Platform`, 팩토리 `createPlatformBackendFor( window )` 가 Wayland 창이면 이것을 고른다 — 키 · 포인터 · 휠 · 포커스 · 클립보드 · 커서 모양, 멀티 뷰포트는 안 켜서 패널은 메인 창 안에서만 도킹한다), `WaylandSplashWindow`(자기 연결 · xdg 최상위 창 · 공유 메모리 버퍼 — `SW_WINDOW_BACKEND` 를 메인 창과 같이 읽는 `tryReadLinuxWindowBackend` 가 고른다, 이제 순수 Wayland 에서도 스플래시가 뜬다), `WaylandDevConsoleWindow`(게임 창 표면의 서브표면 `wl_subsurface` 에 줄을 그린다). 글은 X11 의 서버 글꼴이 없어 `WaylandTextPainter`(엔진 `IFontRasterizer` 의 SDF 글리프 + `SystemFontLocator`)로 그리고, 공유 메모리 버퍼 묶음(`WaylandShmBufferPool`)은 둘이 함께 쓴다. 남음: EGL 로 GL(RHI 영역). 클립보드 왕복 시나리오는 weston headless 에 `wl-copy`/`wl-paste` 가 있어야 만들 수 있다 | 코드 완료(컴파일 확인 없음), EGL 만 남음 |

## 남은 것

- W1 코드는 들어가 있고 컴파일 확인은 없다(이 PC 에서는 리눅스를 빌드하지 않는다). 서버 빌드에 Wayland 코드가 새지 않게 하는 정적 게이트는 `CheckX11Isolation` 4번 규칙이다.
- 소수 배율 · 커서 모양 · 포인터 잠금 코드(W3)도 한 번도 컴파일되지 않았다 — 컴파일이 실패하면 생성 헤더 이름(`<XML 이름>-client-protocol.h`, 커서 모양은 `tablet-unstable-v2` 가 함께 링크돼야 한다)과 판 상수부터 본다. 잠금 왕복(잠그면 `PointerMove` 가 멎고 `PointerRelative` 가 오는지)은 weston headless 에 가상 포인터가 있어야 볼 수 있어 시나리오로 만들지 못했다.
- W3 의 에디터 백엔드 · 스플래시 · 콘솔 코드도 같은 첫 컴파일을 기다린다. 컴파일에서 볼 곳: `WaylandShmBuffer.cpp`(`memfd_create` 는 glibc 2.27 이상 `<sys/mman.h>`), `WaylandSplashWindow.cpp` · `WaylandDevConsoleWindow.cpp`(리스너 구조체 값 초기화, `wl_subcompositor` 바인드 판 1), 헤더에 선언만 둔 `struct wl_*`(`WaylandWindow.h`). 글꼴은 후보 파일 이름 목록이 `WaylandTextPainter.cpp` 에 있어(`editortooldefaults.json` 의 `_listBaseFont` · `_listKoreanFont` 와 같은 이름 — 에디터 설정을 엔진이 못 읽어 따로 둔다, 바뀌면 함께 고친다) 라틴 고정폭 글꼴이 하나도 없는 기계에서는 콘솔을 세우지 않고 스플래시는 글 없이 그림과 막대만 그린다. 스플래시 창 자리는 컴포지터가 정한다(가운데 보장 없음). Wayland 에디터는 패널을 OS 창으로 떼어 낼 수 없다(xdg-shell 이 창 자리를 못 정한다). 에디터의 GL 렌더러는 EGL 이 없는 한 Wayland 에서 못 쓴다(Vulkan 만).
- `X11Window::getContentScale` 은 `Xft.dpi` 를 연결을 연 때의 값으로 읽는다. 실행 중 배율 변경을 따르려면 루트 창의 `RESOURCE_MANAGER` 속성 변경 알림을 받아 캐시해야 한다 — 지금은 하지 않는다.
- 리스너 구조체는 값 초기화한 뒤 이름으로 채웠다(설치된 wayland 헤더 판이 바인드한 판보다 새로우면 남는 칸은 비어 그 이벤트는 오지 않는다).
