# 조용한 폴백과 남은 같은 결함 감사 (2026-10-22)

> 상태: 구현중 · 선행: 없음 · 영역: engine · 옛번호: 없음 · 진행: 13/14

병합 뒤 감사에서 나온 조용한 폴백과 같은 모양의 결함을 모았습니다. 원칙은 [CLAUDE.md](../../CLAUDE.md) "원칙" 1 — 필수 값이 없으면 오류로 멈추고 같은 결함을 쓸 수 없게 형식 · API 를 바꿉니다.

## 1. 정한 것과 고친 곳

- **머티리얼 숫자 값**: 패커(`MaterialUtil::packPropertyIntoBuffer`)는 못 읽는 숫자 글(Range · 숫자 벡터)을 0 으로 쓰지 않고 거절한다(칸을 모두 읽은 뒤 한 번에 써 반쯤 쓴 값도 남기지 않는다). 로드(`parsePropertyNode`)는 같은 패커로 확인해 멈춘다 — 규칙이 하나다.
- **셰이더 필드를 머티리얼이 적지 않음**: `Material::syncPropertiesFromReflection` 이 셰이더 구조체의 필드마다 머티리얼 프로퍼티가 있는지 보고 없으면 오류와 false(스키마가 없는 셰이더도 오류). `ensureShaderLayout` 이 결과를 돌려준다. 데이터를 먼저 채웠다(forwardlit 머티리얼 여섯이 `metallic`, 셋은 `albedoMap` 도 적지 않았다 — 텍스처 인덱스를 적지 않은 칸은 0 이었고 0 은 Vulkan 의 첫 실제 텍스처다).
- **블렌드 모드**: `parseBlendMode` 는 모르는 이름이면 오류와 false(적지 않은 것은 불투명).
- **추가 뷰 그림자**: 그리는 추가 뷰의 그림자는 게임 스레드가 늘 채운다(`ShadowSetupUtil::makeViewShadowFor`). 비었으면 주 시점 것을 빌리지 않고 그 뷰를 그리지 않는다(`FrameRenderer::prepareExtraView`).
- **Vfx 시뮬레이션 대상**: 모듈이 한 곳만 허락하면 데이터가 정한 그곳이고 둘 다 허락할 때만 빌드(`gv_vfxSimulation` · Shipping GPU)가 고른다(`selectSimulationTarget`). 오류로 바꾸지 않았다 — 물리 충돌 · 라이트는 CPU 전용이고 기본값과 Shipping 이 GPU 라 오류면 그 방출기가 모두 멈춘다.
- **텍스처 임포트 형식**: `TextureImportRule::_format` 은 이름이 아니라 `TextureImportFormat` 이고 이름은 설정을 읽을 때 한 번 푼다(`resolveFormatInternal` 은 실패가 없다).
- **빌린 DLL**: `HardwareProbe` 는 dxgi.dll 을 `LoadLibraryExW` 로 참조를 가지고 `RenderDocCapture` 는 주입된 renderdoc.dll 을 고정(`GET_MODULE_HANDLE_EX_FLAG_PIN`)한다.
- **함수 안 정적 컨테이너**: 엔진 `DebugDrawCanvas` · `ModuleTypeRegistry` · `SystemFontLocator`, 에디터 여덟, 게임 프레임워크 `ServerBus` · `OnlinePushRelay` · `MeshModifiersVisualizer` 를 `ScopeOwned<T>` 로 옮겼다(엔진 수명 범위가 소유하니 종료 누수 보고 전에 비고 범위가 닫힌 뒤 `getOrCreate()` 는 nullptr 라 그 호출은 건너뛴다). 등록 표(`NavGeometryContributor` · `ISceneService` · `BuiltInAssetCache` · `NetSimGameRegistry` · `EditorExtensionRegistry`)는 정적 초기화에서 채워 프로세스 끝까지 살아야 해 옮기지 않았다.
- **에디터 리소스 id → 디스크 경로**: `CatalogPanel` · `ContentBrowserPanel` · `InspectorPropertyManager` · `EditorDevCommands` · `EditorSceneFileCommands` · `LocalizationTools` 는 루트에 id 를 직접 붙이지 않고 읽기는 `ResourcePaths::findLooseFile`, 쓰기는 `resolveWritePath` 를 쓴다(못 정하면 빈 문자열이라 건너뛴다). 디스크 루트 자체가 필요한 자리(임포터 · 폴더 목록 · 리소스 색인 · 감시자 · 글꼴)는 남겼다.
- **외형 데이터베이스 수명**: `CharacterAppearanceState` · `CharacterAppearanceComponent` · `AppearanceDataWatcher` 가 `AppearanceDatabase` 를 날 포인터로 쥐지 않는다. 데이터베이스가 `getInstanceID()`(1부터 세는 원자 번호, 복사 금지)를 갖고 상태는 번호만 기억하며 갱신 때마다 지금 데이터베이스를 인자로 받는다 — 번호가 달라지면 스스로 다시 만들어 서비스가 내려갔다 올라와도 허공을 가리키지 않는다(빌려 쥐던 것을 쓸 때 건네는 값으로).

- **렌더 타깃 포맷(RenderTargetFormat)**: `fillPassRenderTargetFormats` 는 RGBA8 로 짐작하지 않는다 — 고정 포맷 · 출력 선언 · 렌더 타깃 0 개 중 하나가 없으면 false 이고 `createPSOForPass` 가 오류와 PSO 0 을 낸다. 포맷 근거가 없는 패스 종류(파이프라인에 없는 패스)는 엔진 PSO 를 아예 만들지 않는다(`hasRenderTargetFormatSource`). 주 출력에 그리는 패스는 `RenderPassTraitFlag::kOutputPass`(Present · Canvas · UpscaleRcas)로 표시해 대상 포맷마다 `createOutputPSOVariants` 로만 만들고, 그 밖의 패스가 Swapchain 을 쓰면 파이프라인 검증이 오류다. `collectColorOutputFormats` 는 넘긴 수로 물러나지 않는다(출력 목록이 비었을 때만). 재측정: 일곱 파이프라인 XML 에서 Swapchain 을 쓰는 패스는 Present · Canvas 뿐이었다.
- **PSO 없는 드로우(네 백엔드 계약)**: 등록된 그래픽스 PSO 없이 그리면 백엔드가 오류로 멈춘다(`SW_FATAL`). 대신 그리던 길을 지웠다 — Vulkan 의 기본 파이프라인(`_pipeline` · `_offscreenPipeline`, 만드는 곳이 없어 늘 비어 있었다), D3D11 의 전역 깊이 상태, GL 의 기본 프로그램(`_shaderProgram`)과 텍스처별 FBO 대체(합성 FBO 를 못 만들면 멈춘다), D3D12 의 조용한 건너뛰기. 등록되지 않은 핸들을 건 `setPipelineState` 는 앞 PSO 를 남기지 않는다(D3D11 · GL). Vulkan 파이프라인 생성 실패는 빈 레코드가 아니라 핸들 0 이다. 생성 결과 미검사도 같은 모양이라 전수로 고쳤다 — Vulkan 셰이더 모듈(정점 · 픽셀), D3D11 입력 레이아웃 · 래스터 · 블렌드 · 깊이 상태 · 그래픽스 PSO 의 컴퓨트 셰이더 · 정적 샘플러, D3D12 간접 서명 셋, D3D12 그래픽스 PSO 생성 실패(빈 레코드를 등록하던 것)는 오류와 핸들 0 · 초기화 실패다. GL 의 면마다 · 깊이 텍스처 FBO(`_listSliceFbo` · `findSliceFbo`)는 쓰는 곳이 없어 지웠다(복사용 0 번 면 FBO 만 남는다). 같은 모양이 다시 생기지 않게 결과는 `isVkSuccess` · `requireVk` · `enumerateVk`(`VulkanResultCheck.h`)와 `isHrSuccess` · `requireHr`(`RHIDxResultCheck.h`)로 받고, SDK 형식에 `[[nodiscard]]` 를 붙일 수 없는 틈은 게이트 `CheckDiscardedDeviceResult` 가 막는다(그래픽스 · 에디터 백엔드의 결과 버림 0 — 명령 버퍼 리셋 · 시작 · 끝, D3D12 Close · Reset, 메모리 바인드, 서피스 · 열거 질의, ImGui Vulkan 세트 해제, DXC 기본 include 처리기를 옮겼다). 식 안에서 결과를 받고 실패를 오류 없이 건너뛰던 모양(`if ( SUCCEEDED( Map ) )` 로 상수 업로드가 조용히 빠지던 D3D11 세 곳, 로그 없이 돌아가던 D3D11 · D3D12 Map, Vulkan 상수 버퍼 Map, 파이프라인 캐시 읽기, 슬롯 세트 할당)도 실패 이유를 남기게 했고, 게이트의 둘째 규칙이 D3D 장치 메서드를 `SUCCEEDED` · `FAILED` 로 바로 감싸는 것을 막는다(59 곳을 `isHrSuccess` 로 옮겼다 — 선택 기능 질의 `CheckFeatureSupport` · `As` · `GetDesc*` 는 실패가 정상 응답이라 뺐다). 고갈되면 앞 것을 다시 쓰던 두 곳도 지웠다 — Vulkan 슬롯 세트 풀 묶음은 상한(16 풀)을 없애 한 번의 기록이 쓴 만큼 자라고 만들지 못하면 멈춘다(앞 세트로 그리던 것), 패스 상수 링(`PassConstantRing`)은 모자라면 마지막 슬롯을 공유하지 않고 false 를 돌려줘 그 패스 · 그림자 타일 · 쿠키 칸을 그리지 않는다(다음 프레임이 사용량으로 키운다). 재측정: D3D12 온라인 디스크립터 블록 고갈은 이미 드로우를 건너뛰었다(로그 문구만 고쳤다). 라이트 상한 · 쿠키 아틀라스 · 오디오 보이스는 넘친 것을 버린다(재사용 아님). 메시 모프 · 정점 애니메이션 풀은 이미 사용량으로 다시 만들어 자란다(모프 레스트는 `repackMorph` 가 살아 있는 정점의 1.5 배로, 결과 · VAT 표는 `ensureCapacity` 가 키우고 옛 버퍼는 프레임 지연으로 놓는다). 남아 있던 대체 — 상한(`kMaxPoolVertices` · `kMaxElementCount`) 초과와 버퍼 생성 실패 때 바인드 · 레스트 포즈로 그리던 것 — 는 오류와 "그 메시를 그리지 않음"으로 바꿨다: 풀은 결과를 채울 수 있을 때만 구간을 내주고(`baseOf` 가 `isDispatchable` · `isSkinDispatchable` 을 본다), 구간을 못 받은 변형 메시의 배치는 `GPUMeshBatch::_bDeformRefused` 로 표시되어 `drawsBatchInPass` 가 거른다. 백엔드가 GPU 변형을 못 하는 경우(능력 질의 `_bGPUMeshMorph`)는 실패가 아니라 그대로 레스트 포즈다. 렌더러는 PSO 가 0 이면 드로우를 건너뛰므로(`drawFullscreen` · `drawGPUBatches`) 여기 닿는 것은 부르는 쪽 결함이다.

- **거절 이유를 버리고 고정 문구로 덮는 읽기(Core · Games 재측정, 2026-10-28)**: `GlobalVariableInfo::setValueFromCommandLine` 은 `outError` 와 `[[nodiscard]]` 로 이유(숫자 거절 · 이름 없는 열거자 · 이름표 없음 · 타입 불일치)를 돌려주고 부르는 둘(`registerVariable` · `applyPendingEnumText`)이 그대로 잇는다(전에는 같은 실패에 안쪽 로그와 바깥 고정 문구 두 문장이 나왔다). `NileCityPlanner` 의 `parseCell` · `findBlockPopulation` 도 틀린 칸과 이유를 돌려준다. 두 파일 · 조건을 `||` 한 줄로 묶거나 "읽지 못함" 과 "비어 있음" 을 한 문구로 알리던 게임 데이터 읽기(`ParkDirector` · `ShooterDirector` · `BenchSceneRig` · `FarmDirector` · `FarmVillageDirector`)는 읽기마다 나눴다. 재측정으로 그대로 둔 것: `NetAddress::parse` · `StringUtil::parse*` 는 틀린 값 자체를 부르는 쪽이 이름과 함께 알리는 한 가지 이유의 원시 읽기이고, `readOptionalBoolArgument` 는 콘솔이 사용법으로 거절하는 약속이며, `CommandLineManager::setValue` 의 "Using 0" 은 경고를 남기는 문서화된 선택이다. `NetStatsReport` · `NetEmulationReport::tryParseLine` 은 로그 줄에서 보고 줄을 가려내는 읽기라 "보고 줄이 아님" 이 정상 응답이다.

**확인 대기(통합에서 확인):** 매니페스트 id `appearance-database-lifetime-tests`(`AppearanceTest.StateRecognizesItsDatabaseByInstanceID` 포함). 컴파일 확인이 필요한 파일은 위 세 항목의 파일 전부이고 빌드는 통합의 `debug-full-build` 가 돈다. 렌더 타깃 포맷 · PSO 없는 드로우는 네 백엔드 시나리오 실행(`RenderPassTest.PipelineValidationCatchesInconsistencies` 3-1-1 포함)으로 확인한다.

## 2. 남은 단위

남은 둘은 화면으로만 맞는지 알 수 있는 셰이더 일과 다른 계획의 단위다(2026-10-24 판단, 2026-10-27 재측정).

### SilentFallbackAudit.EmulatedSlotTable
에뮬 백엔드(DX11 · GL)의 엔진 텍스처 슬롯 표가 두 곳이다 — `binding.hlsli` 의 `Bindless::sampleIndex`(11-2 절)와 `FrameRenderer::commitBindlessTextureBindings`. 표를 C++ 상수(`ShaderBindingSlots`) 하나에서 내고 셰이더는 생성된 정의를 읽게 한다. 셰이더 패치와 DX11 · GL 화면이 한 묶음이다. 2026-10-27 재측정 · 처리: 표에 없는 인덱스를 셰이더가 슬롯 0 으로 읽던 대체는 `sampleIndex` · `sampleIndexWith`(DX11 · GL) 셋 모두 오류 색 `kUnmappedEngineTextureColor`(자홍)를 내게 고친다 — 셰이더를 고친 커밋은 구운 바이너리를 함께 커밋해야 해(사전 커밋 린트) 소스 패치는 wt/errh 작업 트리에 커밋하지 않고 남겼고 통합이 쿠킹과 함께 커밋한다. C++ 쪽은 끝냈다: 표는 `getEmulatedTextureSlot`(`RenderPassInputSignature.h`, 역할 → `EmulatedTextureSlot`) 하나이고, 파이프라인 로드(`RenderPipelineAsset` 의 입력 계약 검사)가 한 패스의 선언 입력이 같은 슬롯의 두 역할을 읽으면 오류로 거절한다. `commitBindlessTextureBindings` 의 우선순위 사슬은 "슬롯마다 하나" 단언(`SW_ASSERT`)으로 바꿨고(코드가 거는 쿠키 · 노출 · TAA 이력도 이 단언이 지킨다), t3 에 깊이 대신 그림자를 걸던 대체를 지웠다. 재측정(일곱 파이프라인 XML): 계약이 있는 풀스크린 패스 중 같은 슬롯을 둘 읽는 패스는 없다(겹치는 것은 메시 패스 ForwardOnlyOpaque 의 LitColor · ShadowMap 뿐이고, 메시 패스는 선언 입력을 바인딩하지 않는다). 남은 것: 셰이더가 이 표를 생성된 정의로 읽게 하는 것(지금은 손으로 맞춘 같은 표)과 위 셰이더 패치의 쿠킹 · 커밋(통합).

### SilentFallbackAudit.ClientCodeGuard
렌더러 밖에서 `SW_WITH_CLIENT_CODE` 없이 클라이언트 전용 코드를 부르는 곳. 구조로 막는 길은 서버 타깃이 렌더러 폴더를 짓지 않게 하는 것이고 그러면 남은 호출을 컴파일러가 찾는다 — [DedicatedServerNoRenderer](DedicatedServerNoRenderer.md) 의 단위다.

## 3. 맡기지 않은 것

동기 `acquire` 호출처(Ragdoll · Socket · MaterialInstance · Canvas 텍스처)는 [결정 기록 5-4](../decisions/5-4_DataConfig.md) 의 비동기 로드 작업과 같은 파일이라 그 작업이 끝난 뒤 그 계획에서 옮긴다.
