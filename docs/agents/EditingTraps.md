> 질문: 파일을 스크립트로 고칠 때 무엇이 반복해서 깨졌는가?
> 독자: 스크립트나 셸로 파일을 고치는 에이전트와 사람.
> 결론: heredoc 으로 여러 줄 스크립트를 만들지 않고 Write 로 파일을 만들어 돌린다. 글 교체는 `py -3 -m Scripts edit-file` 을 쓴다. CRLF 와 UTF-8 을 보존한다.

## Editing traps (편집 함정)

- 한 함수에서 **여러 구간을 빼낼 때는 뒤쪽 구간부터** 한다. 앞쪽을 먼저 빼면 뒤쪽 줄 번호가 밀린다.
- 파일을 스크립트로 고칠 때 CRLF 를 보존한다. 이 저장소는 CRLF 다.
- **여러 줄 스크립트는 Bash heredoc(`cat > x.py <<'EOF'`)으로 만들지 않는다. 파일 쓰기 도구(Write)로 임시 폴더에 `.py` 를 만들고 `py -3 <파일>` 로 돌린다.**
  heredoc 은 세 가지로 반복해서 깨졌다. ① 본문에 따옴표 · 백틱 · 한글이 길게 섞이면 셸이 `unexpected EOF` 로 스크립트를 아예 만들지 못한다.
  ② `\n` · `\0` · `\\` 같은 이스케이프가 사라지거나 실제 줄바꿈이 된다(C++ 문자열의 `"\n"` 이 두 줄이 되어 컴파일 오류가 났고, `'\0'` 은 널 바이트가 됐다).
  ③ CRLF 파일을 읽고 쓰며 줄바꿈이 바뀐다. 파이썬 안에서 백슬래시는 `chr(92)` 나 raw 문자열로 쓰고, 파일은 `newline=''` 으로 읽어 `\r\n` 을 보존하며,
  고친 직후 그 줄을 `grep -n` 으로 확인한다. Bash 는 한두 줄짜리 명령에만 쓴다.
  **파일 안의 글을 바꾸는 일은 `py -3 -m Scripts edit-file <경로> --old-file <파일> --new-file <파일>`(여러 곳은 `--changes <JSON>`)을 쓴다.** 바꿀 글은 한 번만 나와야 하고, 줄 끝 · BOM 은 보존되며, NUL 은 거부되고, 틀리면 아무것도 쓰지 않는다.
- **파서를 고친 뒤 "`.gen.cpp` 가 다시 만들어졌나" 를 산출물 시각으로 판단하지 말 것.** 내용이 같으면 파일을 다시 쓰지 않는다.
  다시 만들었는지는 옆의 `<이름>.gen.cpp.stamp` 시각으로 본다.
- `grep -v` 로 거를 때 이름이 비슷한 다른 것(`TestArchive` 등)까지 걸러지지 않는지 본다.
- **`py -3 -` 처럼 표준입력을 기다리는 파이썬을 띄우지 않는다.** 본문이 비면 입력 대기로 코어 하나를 계속 쓴다. 스크립트는 파일로 만들어 돌린다.
- **Windows PowerShell 5.1 의 `Get-Content` · `Set-Content` 로 소스를 고치지 말 것** — UTF-8 한국어 주석을 CP949 로 읽어 되돌릴 수 없게 깨고 BOM 을 붙인다. 파이썬(`encoding='utf-8'`)으로 고친다.
- **실패한 커밋 뒤에는 스테이징이 남는다** — 다음 커밋 전에 `git status`.
- 패치 스크립트를 다시 돌릴 때 바꿀 글(old)이 새 글(new)의 접두이면 같은 내용이 두 번 들어간다 — 멱등하게 짠다. 큰 if-체인을 접을 때는 잘라낸 구간의 타입을 grep 으로 세어 사이의 다른 분기가 같이 잘리지 않았는지 본다.
- `rm -rf` 할 폴더 안에 셸의 작업 디렉터리가 있으면 반쯤 지워지고 뒤의 `cp -r` 이 그 안에 중첩 복사된다 — 저장소 루트로 옮긴 뒤 지운다. 옛 코드로 App · 벤치를 돌릴 바이너리는 전체 빌드로 만든다(테스트 타깃만 빌드하면 모듈 DLL 이 새 ABI 로 남는다).
