# 5-4. 데이터, 직렬화, 설정

> 질문: 5-4. 데이터, 직렬화, 설정 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **엔진 데이터에는 별칭을 두지 않습니다**(2026-10-03). 출시한 게임 데이터가 없으므로 이름을 바꾸면 데이터를 다시 씁니다. 옛 `SaveGame` 파일도 읽지 않습니다(계약은 Serialization README). 이 결정은 이관할 데이터가 없다는 사실에 기댄 것이지 영구 금지가 아닙니다(사용자 확인, 2026-10-17). 출시한 데이터가 생겼을 때 쓰도록 별칭(`Alias` · `ValueAlias` · `Removed`)은 미리 갖추되 제품 데이터 · 게임 코드에는 두지 않습니다(2026-10-18 사용자 결정).
- **첫 출시 전에는 이관 없이 데이터를 다시 쓰고 판은 정확히 같을 때만 읽습니다**(2026-10-23 사용자 결정). 옛 판 리더 · 이관 함수 · 판 범위 읽기를 두지 않고 판이 다르면 오류로 멈춥니다(근본 원인은 판 번호를 범위로 받는 API 였음 — `SchemaMigrationRegistry` · `deserializeVersioned` · `readHeaderInRange` 등은 지움). 남긴 것은 계약이거나 출시 뒤에도 필요한 것: `BinaryWireVersion`, orphan 정책(`SchemaOrphanPolicy` — 텍스트 Ignore · 바이너리 Reject), 네트워크 `combine` 버전, 서버 레코드 판 거절, SQL 마이그레이션 번호, 팩 형식 거절, 쿠킹 기록의 "옛 형식은 읽지 않고 다시 굽는다", 사용자 설정 `<Upgrade>` 체인. 호환 의무는 출시를 자르는 순간부터이고 그때 판 번호를 기준값으로 굳힙니다. 같은 버전에서 지운 필드를 버려도 되는지는 호출부가 컨텍스트로 정합니다(`setAllowUnknownProperties`, 오브젝트 상태만 켬).
- **사용자 설정의 형식 값은 등록 때 푼 `UserSettingKey<T>` 로만 읽습니다**(2026-10-27, 감사 SA #8). `getBoolValue` · `getIntValue` · `getFloatValue` 는 글 id 를 받지 않고 `resolveKey<T>` 가 모르는 id 와 타입이 다른 id 를 오류(`UserSettings.KeyUnresolved`)로 거절합니다 — 글 id 로 읽던 때는 둘 다 조용히 false · 0 이었습니다. 사용자 파일의 깨진 값은 경고(`UserSettings.ValueInvalid`) 후 스키마 기본값이고 엔진 핸들러 · 파일 쓰기도 해석 실패를 false · 기본 수로 바꾸지 않습니다(`tryParseBool`). 언리얼 `TConsoleVariableData<T>` · Godot `ProjectSettings` 의 형식 있는 핸들과 같은 자리이고 값 저장은 글 그대로 둡니다(메뉴 · 파일 · 프리셋이 글로 오가므로). 게임 쪽 정적 파사드 `GameStrings`(언어 기본 인자 · 빈 글 폴백)는 지우고 `LocalizationManager` 를 게임 서비스로 부릅니다. 사용자 파일의 모르는 키는 읽을 때(플레이어 데이터) 경고 후 버리고, 쓸 때(프로그램이 만든 목록)는 키 대신 설정 정의(`UserSettingsWriteEntry::_def`)를 받아 모르는 키를 만들 수 없게 했습니다. **지역화 조회는 `getString`(없으면 빠진 키 경고 `Localization.MissingKey` 후 키 이름을 보임) 과 `findString` · `findStringByText`(없으면 nullptr, 부르는 쪽이 대체 글을 정함)로 나누고 기본 인자 `pDefaultText = ""` 는 지웠습니다** — 빠진 번역이 빈 글로 숨지 않고 언리얼 FText 처럼 키로 보입니다.
- **설정 파일에는 기본값과 다른 값만 적습니다**(2026-10-06, 언리얼 `Default*.ini`). `ConfigFileSchemaTest` 가 막습니다.
- **설정 값의 출처는 하나씩입니다**(2026-10-06). 시작 씬은 팩의 `gamesettings.xml`, 창 제목은 `GameConfig::_windowTitle`, 고정 스텝은 `EngineConfig::_fixedDeltaTime` 이고 물리는 그 위에 서브스텝 수만 둡니다(유니티 `Time.fixedDeltaTime`). 기본 RHI 도 한 곳에만 적습니다. 앱이 다시 쓰는 에디터 상태는 `Saved/Editor/`, `Config/Editor/` 에는 사람이 쓰는 설정만 둡니다. 텍스처 · 모델 임포트 설정은 키 테이블이고 엔진 타입에 키트 설정 필드를 두지 않습니다(키트 설정은 팩 데이터).
- **자체 JSON 로더를 리플렉션 구조체로 옮기는 기준**(2026-10-12). 옮긴 것: 모듈 매니페스트 · `AnimationLODSettings` · `MemoryBudgetFile` · `FacialRig` · `LipSync`. 옮기지 않는 것: "적지 않음(부모 프리셋을 따름)" 의미가 필요한 `TextureImportConfig` · `ModelImportConfig` · `CultureInfo`(리플렉션은 "없음" 과 "0" 을 못 가름), 동적 JSON(`CrashReportService`), 외부 형식(JWT · Chrome 트레이스 · VRM), 키가 데이터인 표(`LocalizationDocuments`), 노드마다 필드가 다른 그래프(`AnimationGraphAsset`). 자체 포맷 에셋 로더 넷(`SpriteClipAsset` · `SequenceAsset` · `DialogueGraphAsset` · `Skeleton`)은 리플렉션으로 읽고 쓰며(2026-10-17, C-19 R4) 키가 PROPERTY 이름이고 데이터는 새 키로 다시 썼습니다. "적지 않음" 을 초기값으로 읽으면 안 되는 칸은 `PROPERTY( Required )` 라 빠지면 오류이고(`readConfigJSON` 이 목록 원소 안까지 봄) 종류는 열거자 이름이며 모르는 종류를 건너뛰거나 Dialogue 로 읽던 폴백은 없앴습니다.
- **`sw::vector<bool>` 은 쓰지 못하고 불 목록은 `DynamicBitset` 입니다**(2026-10-17, A-18). 같은 이름이 구성마다 다른 의미(바이트 vs 비트 묶음)였고 STL 구성에서 리플렉션 래퍼가 원소 주소를 못 잡아 컴파일이 멈췄습니다. `VectorElementCheck` 가 막고 언리얼도 `TArray<bool>` 과 `TBitArray` 를 따로 둡니다.
- **`SW_ENABLE_STL_CONTAINER` 가 구성마다 바꾸는 것은 컨테이너 기본 할당자 하나(`ContainerAllocator<T>`)입니다**(2026-10-24). 목적은 "엔진 할당자 대신 `std::allocator`"(메모리 추적 빼기)로 읽었고 `vector` · `map` · `set` · `unordered_*`(밀집 배열 구현, A-20) 등은 두 구성 모두 자체 구현이며 `string` · `list` · `deque` 는 두 구성 모두 경합 탐지를 얹은 `std::*` 파생입니다. 같은 이름이 구성마다 다른 형식이면 한 구성에서 맞는 코드가 다른 구성에서 달라지기 때문입니다(`vector<bool>` · 해시 순회 순서). 표준 컨테이너 비교나 디버그 STL 검사가 목적이었다면 되돌립니다 — 사용자 확인을 기다립니다.
- **메모리 태그 통계의 해제는 센 블록만 뺍니다**(2026-10-18, A-24). 할당기가 센 블록 헤더에 기록기 번호를 적어 그 기록기에만 해제를 넘깁니다(추적을 켜기 전에 잡은 블록을 켠 뒤 풀면 태그 바이트가 음수로 어긋났음). 언리얼 LLM 도 같습니다. **누수는 "창 안에서 태어나 닫힐 때 살아 있는 블록" 으로 잽니다**(2026-10-24, [LeakDetection](../plans/LeakDetection.md)) — 기준선 뒤 차이로 재면 창 밖 오래된 블록을 풀 때 새 누수가 상쇄됩니다. `AllocationRecord::_windowStamp`(uint32)를 블록 헤더 패딩에 두고(헤더 48 B 유지) `Memory` 는 스탬프를 돌려주기만 하며 창은 `MemoryProfiler::beginLeakWindow` · `endLeakWindow` 가 맡습니다.
- **범위는 인스펙터와 읽기가 한 함수(`PropertyMetadata::computeAllowedRange`)로 풀고 소프트 읽기는 실패를 둘로 가릅니다**(2026-10-18, C-56 · C-60 · C-62). 설정 JSON · 데이터 XML · 세이브가 같은 `Min` · `Max` 를 한 계약으로 지킵니다. `deserializeSoft` 는 `SoftReadResult`(`NotParsed` · `Rejected` · `Read`)를 돌려줍니다 — `bool` 일 때는 범위 밖 값에서 바로 돌아가 같은 파일의 모르는 키를 못 알렸고 "JSON 이 아니다" 로 잘못 알렸습니다.
- **이름 읽기(`XMLReadUtil::readOptionalName`)는 글 `none` 을 오류로 알립니다**(2026-10-18, C-59). `hashed_string` 은 `none` 을 빈 이름과 같게 보고 빈 이름의 `c_str()` 은 "None" 이라 `align="none"` 이 "적지 않음" 이 되고 적지 않은 경로가 "None" 이 됐습니다. 이름 형식을 바꾸면 씬 · 프리팹 100 곳 넘게 바뀌므로 읽기 창구가 그 글을 오류로 막고 그런 속성은 글로 읽습니다.
- **열거자 이름의 정본은 리플렉션 `ENUM()` 입니다**(2026-10-15, 10-12 의 "enum 이름 테이블 유지" 를 뒤집음). 손 이름 표 · `toString( Enum )` 은 지우고 `getEnumName( value )` 로 읽습니다(언리얼 `UENUM`, Godot ClassDB 방향). 손 표는 `static_assert` 가 개수만 지키고 순서 · 철자 어긋남을 못 막았습니다. 남기는 것: 철자가 다른 와이어 · 데이터 · 지표 문자열(`EnumNameTable`)과 Core 의 열거형(리플렉션 아래 티어). 값이 빈틈없으면 생성된 이름 배열 인덱스이고(열거자마다 `static_assert` 로 libclang 값과 대조) 캐시는 타입 테이블 세대가 같을 때만 씁니다.
- **같은 빌드끼리만 읽는 바이트는 고정 배치형(B) 코덱이고 생성기가 모든 적격 `REFLECT` 타입에 만듭니다**(2026-10-17, [고정 배치형 코덱 계약](../../Source/Engine/Serialization/Fixed/README.md)). 사용자는 B 를 선언하지 않고 세이브와 에셋은 자기 기술형(A)입니다. 언리얼 `NetSerialize` · Iris 처럼 선언(`UPROPERTY`)에서 와이어 형식을 도출하고 손 버전 상수 대신 정규 문자열 해시가 형식 변경을 잡습니다(`FixedLayout::kVersion`). 수학 타입은 `kArrMathType` 목록으로 정하고(구조에서 추측하면 핸들까지 적격이 됨) 가변 길이가 두 겹인 타입은 `MaxCount` 하나로 정할 수 없어 부적격이며 코덱 없는 타입을 진입점에 넘기면 이유를 로그에 남기고 멈춥니다(0 해시 같은 대체 값은 핸드셰이크 해시에 섞임). 정수 경계는 float32 로 정확히 나타나야 합니다. 기각: 대상을 사용 자리에서 모으는 길(`.cpp` 를 생성기 입력에 넣기 — 계층이 거꾸로 되고 목록 원본이 둘), 필드 속성(`Replicated`)에서 도출(그 속성은 "보낼 필드" 만 말하고 롤백은 모든 필드가 필요).
- **이름 변경 리다이렉트는 선언 옆에 적고 표는 그 이름의 주인이 듭니다**(2026-10-17, R1~R4). 타입 · 열거형 옛 FQN 은 `REFLECT( Alias )` · `ENUM( Alias )`, 열거자는 `ENUM( ValueAlias = "Old:New" )`, 지운 열거자의 대체는 `ENUM( Removed = "Old:Replacement" )`, 필드는 `PROPERTY( Alias )` 입니다(유니티 `FormerlySerializedAs` 처럼 이력이 선언 옆, 언리얼 `CoreRedirects` 와 달리 전역 표가 아님 — 선언이 등록과 함께 오므로 주인에 붙어야 상속 · 핫 리로드 · 모듈 해제를 따름). 읽기는 지금 이름을 모두 본 뒤에만 옛 이름을 보고 옛 이름은 인스펙터 · 쓰기에 나오지 않습니다. 대상이 없거나 옛 이름이 지금 이름이거나 중복이면 생성 오류, 선언 없이 지우거나 바꾼 이름은 엄격한 읽기가 실패합니다(모르는 칸을 받는 오브젝트 상태만 건너뜀). 리다이렉트는 바이트 배치와 무관하므로 고정 배치형 정규 문자열에 넣지 않습니다.
- **`REFLECT` 타입은 비가상 베이스를 하나까지만 둡니다**(2026-10-17, 단계 7-b). 둘째 · 가상 베이스는 생성 오류입니다 — `castTo` 가 부모 사슬을 믿고 `reinterpret_cast` 로 내려가므로 부모가 offset 0 이 아니면 잘못된 주소가 됩니다.
- **`GameObject::getTypeInfo` 는 `StaticType()` 결과를 캐시하지 않습니다**(2026-10-17). 이득이 없고(이미 `TypeLookupCache` 를 거침) 함수 지역 정적 포인터는 엔진을 다시 만들면 해제된 `TypeInfo` 를 가리킵니다. **`isDerivedFrom` 은 조상 디스플레이 테이블을 그대로 두고 DFS 구간 번호는 채택하지 않습니다** — 이미 O(1) 이고 구간 번호는 타입 추가(DLL · 핫 리로드)마다 다른 번호가 바뀌며 코드 생성기는 모듈 하나만 봐 전역 번호를 못 정합니다. 남은 캐스트 비용은 타입 없는 핸들과 씬 전체 순회였고 타입별 컴포넌트 목록과 `TComponentHandle<T>` 로 풀었습니다(5-6).
- **테스트만 쓰는 공개 타입은 상용 엔진 대응으로 가릅니다**(2026-10-15). 대응이 있는 것은 남기고 테스트를 붙이며 대응이 없고 테스트를 돕기만 하는 타입(목 · 고정값 · 한 테스트만 부르는 `Util`)은 `Test/` 로 옮깁니다(일괄 삭제는 하지 않고 영역을 고칠 때 정리). **한 타입만 다루는 `Util` 은 그 타입의 메서드로, 한 파일만 쓰는 `Util` 은 그 `.cpp` 안으로** 옮깁니다(C-26 ②, 데이터가 자기 계산을 든다 — 언리얼 `FBuoyancyData`).
- **확장자 → 에디터 종류의 정본은 종류 표(`EditorAssetType.cpp`) 하나입니다**(2026-10-15, C-26 ④). 엔진 포맷은 그 타입이 `kExtension` 을 들고 표가 가리키며 씬 · 프리팹은 쿠킹 규칙을 따릅니다(`EveryEngineFormatMapsToItsKind` 가 대어 봄). 파일이 없던 맨 접미사(`.seq` · `.sprite` 등)는 별칭이라 지웠습니다. `UIStyleField` 서술자 표는 필드마다 플래그 한 칸이고 플래그를 PROPERTY `Meta` 로 옮기는 안은 커스텀 메타가 Shipping 에 없어 기각했습니다. 이벤트(`MulticastDelegate` 필드)가 받는 애노테이션은 필드 표의 Emit 열이 `Display` 인 줄입니다.

- **이름 읽기는 필수와 선택이 서명에서 갈린다 — `readName` 을 `readOptionalName` 으로 바꾸고 필수는 `readRequiredName` 이 오류까지 낸다**(2026-10-24, 엔진 정리 ReadNameAudit). 근본 원인은 `XMLReadUtil::readName` 이 빈 이름으로 "적지 않음" 과 "잘못 적음" 을 가르지 못해 필수 이름의 빈 값 확인을 잊으면 조용히 지나가는 것이었다. `readName` 이라는 이름을 없애 필수가 이 이름으로 읽히지 않게 하고 `GameDataXML::readRequiredName`(`[[nodiscard]]`, 원소 · 속성 이름과 함께 오류) · `AppearanceXMLUtil::readRequiredName`(보고서에 오류)을 더해 `GameDataXML::readName` 35 곳 · `AppearanceXMLUtil::readName` 약 100 곳이 필수 · 선택을 고르게 했다. 조용히 지나던 곳(타이밍 창 `grade`, 어빌리티 이펙트 `<Execution class>` · 어빌리티 세트 항목, 퀘스트 단계 id · 목표, `AreaGraph::<Link>` 끝점, 외형 `<Morph>` · `<Material>` · `<HideRegion>`, 캐릭터 값 `name`/`option`)이 이제 오류로 나오고 이름 목록(`appendNameList` · `readNameList`)은 글 `none` 이 빈 이름으로 들어가던 것을 오류로 알린다. 경로 글로 바꿔 쓰는 빈 이름의 `.c_str()`("None")는 형식으로 막지 못한다.
- **텍스트 형식은 역할마다 하나다 — 저작 에셋은 XML, 시작 때 읽는 설정과 사용자 상태는 JSON 이고 등록이 막는다**(2026-10-20 ~ 22, 구조 단순화 TX1 ~ TX7). 근본 원인은 텍스트 형식을 필요할 때마다 새로 골라(`.meta` · 에디터 상태는 `key=value`, JSON 에셋 19 종이 XML 에셋과 섞임) 같은 사실의 원본이 둘이 되는 것이었다. 규칙: 저작자가 편집하고 리소스 id · GUID 로 참조되며 쿠킹 대상이면 XML, 시작 때 `ConfigManager` 가 읽는 호스트 · 도구 설정과 사용자 상태는 JSON 이다. 형식은 등록이 막는다(TX7): `AssetTypeRegistry::isSuffixFormatAllowed` 가 `.json` 접미사를 쿠킹 입력(`CookSource`, 지금은 `.prefab.json` 하나)으로만 받고(`AssetTypeRegistryTest.JSONSuffixIsOnlyACookSource`) 에셋 로더는 `XMLDocument` 만 받으며 JSON 읽기는 `ConfigManager`/`IConfig` 에서만 닿는다. 에셋 폴더 코드가 `JSONSerializer` 를 직접 부르는 틈만 린트 게이트로 둔다. `.meta` 는 XML(`<AssetMeta guid sourcePath imported/>`)이고 `toXML` · `parseXML` 로만 읽고 쓰며 깨진 `.meta` 를 새 GUID 로 덮어쓰지 않는다(167 개 재작성 · GUID 동일 확인). 에디터 · 사용자 상태(`EditorPanelVisibility` · `EditorViewportOverlayFile` · `UserAppearancePresetFile` 판 3)는 리플렉션 + JSON 이고 옛 형식 리더는 두지 않는다. `KeyValueFile` 은 지웠다. 외부 규격(`.po` · `.xlf` · glTF · VRM · `imgui.ini`)과 `assetregistry.txt` 는 건드리지 않고 임포터가 쓰는 JSON 은 XML 을 쓰게 바꿔 다시 임포트한다. JSON 유지는 `editor/theme/*.tokens.json`(에디터 표시 데이터)과 도구 데이터(`*.sources.json` · `models_raw/**/*.clips.json` · `allowedlogs.json`)뿐이다. 변환 스크립트는 종류마다 하나씩 만들고 변환 뒤 지웠다(범용 변환기 없음). 기각: `KeyValueFile` 만 지우고 JSON 에셋 유지(로더가 형식을 고르는 구조가 남음), 전부 JSON(에셋 XML 은 직렬화 · 마이그레이션 · 참조가 이미 XML), `.meta` 를 JSON(에셋 곁에 놓이는 에셋의 일부). 지역화 XML 은 130 ~ 300 KB 로 커서 팩에서도 원본을 읽는지 먼저 확인하고 나쁘면 그 종류만 쿠킹본을 둔다. 하지 않는 것: 셰이더 바이너리 커밋 중단(계속 커밋, PK3 스탬프 검사가 소스와 맞는지 본다), 백엔드 등급제(네 백엔드를 같은 기능으로 유지).
