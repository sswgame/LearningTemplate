# 5-10. 전용 서버

> 질문: 5-10. 전용 서버 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **전용 서버는 별도 실행 파일 `Server` 입니다**(2026-10-06). App 의 모드가 아닙니다. Shipping 프리셋은 Client 타깃이고 Dev 기본은 Game 타깃입니다.
- **서버 설정은 Shipping 에서도 디스크에서 읽고 없으면 기동이 실패합니다**(2026-10-06). Windows 서비스 모드도 있습니다.
- **서버 전용 쿠킹은 하지 않고 패키징할 때 타깃별로 에셋 종류를 뺍니다**(2026-10-06). 처음 빼는 종류는 텍스처 · 셰이더 바이너리 · 오디오이고 메시와 애니메이션은 충돌 · 소켓 · 히트박스 · 루트 모션 때문에 남깁니다. 패키징과 런타임이 같은 테이블(`Config/Engine/CookContract.json` 의 `target_excluded_asset_kinds`)을 읽습니다.
- **지형 레이어 가중치는 텍스처가 아닌 데이터 에셋(`.layerweights`)이고 클라이언트와 전용 서버가 같은 파일을 CPU 로 읽습니다**(2026-10-16, F-1 — 사용자가 "상용 엔진 기준 최선" 으로 위임). 옛 스플랫은 DDS 텍스처라 서버 패키지에서 빠져 서버의 레이어 질의(발소리 · 표면 재질 · 이동 속도)가 말없이 레이어 0 이었습니다. 상용 엔진도 가중치를 게임플레이 데이터로 서버에 둡니다(언리얼 랜드스케이프, 유니티 `TerrainData`). 정본은 `LayerWeightsData` 하나이고 GPU 텍스처는 읽은 바이트로 만듭니다. 기각: 쿠커가 서버용 사본을 따로 뽑기(정본이 둘), 쿠킹 표에서 스플랫 DDS 만 예외(서버가 텍스처 로더를 타 "텍스처는 서버에 없다" 가 깨짐). 폴백은 없습니다 — 경로를 정했는데 못 읽으면 오류로 `reloadTerrain` 이 실패합니다.
- **App · Server 가 같이 하는 호스트 일은 최상위 `Source/ModuleHost` 한 곳에 둡니다**(2026-10-10 사용자 결정, 옛 `AppHost`; 2026-10-22 확장). 방향은 `CheckEngineLayers` 가 지킵니다(App · Server → ModuleHost → Engine). 호스트 범위 세우기, 핫 리로드(`ModuleReloadDriver` — `module.reload` · 탐침 `Module.*`), 표준 입력 명령 채널(`quit` · `stop`)이 여기 있어 Server 도 얻습니다. 고정 스텝 시간 정책 `FixedTimestep` 은 Core(`Core/Time`)에 두고 기본값은 만들 때 받습니다(출처 하나). 리로드 단축키는 입력을 아는 App 이 정하고 구동기에는 요청만 넘깁니다. `ModuleHost` 는 게임 모듈만 다루고 에디터 몫은 App 의 파생 `EditorModuleHost` 가 맡습니다(언리얼 `UGameEngine`/`UEditorEngine` 방향) — 전용 서버는 기반 클래스만 쓰고 모드 플래그가 없으며 RHI 를 받았는지가 "디바이스가 있어야 게임을 만든다" 를 정합니다.
- **"지금 도는 것" 을 정적 포인터로 내주는 창구(`static T* findActive()`)를 두지 않습니다**(2026-10-22). 소유자가 객체를 범위에 빌려 걸고(`SubsystemScope::bind`) 쓰는 쪽이 `findSubsystem<T>()` 로 찾습니다. 정적 칸은 둘째 인스턴스 · 내려간 인스턴스를 가리킬 수 있고 수명이 숨습니다. `CheckServiceAccess` 가 헤더의 모양을 막고 남는 것(Core 층 · 잠금 없이 읽는 칸 · 창 소유권 전달)은 규칙 데이터의 예외 표에 이유와 함께 둡니다.
- **"N 번째 프레임에 무엇을 한다" 명령줄 스위치를 두지 않고 시점은 시나리오 단계가 고릅니다**(2026-10-22). `-gv_reloadGameAtFrame` · `-gv_rhiSwapAtFrame` · `-gv_userSettingsApplyFrame` 을 지우고 같은 일을 단계 `DevCommand` · `SwapBackend` · `Variable` 이 합니다.
- **에디터 뷰포트 격자는 카메라 높이로 1 · 10 · 100 m 간격을 고르고 경계에서 섞습니다**(2026-10-10). 화면 공간 셰이더 격자(Unity 2019+ · Godot 4)는 렌더 패스를 하나 더 들여야 해 ImGui 선 그리기를 유지합니다.
- **`UserSettingsHost` 는 엔진으로 옮기지 않고 App 에 둡니다**(2026-10-10). 설정 정책은 이미 엔진의 `UserSettingsManager` 이고 이 파일은 App 이 소유한 창과 `App::onResize` 의 스왑체인 경로에 적용하는 창 소유자의 단계입니다. 옮기면 창 접근과 리사이즈 순서가 두 곳으로 갈립니다.
- **느린 틱 트레이스는 Shipping 서버에 넣지 않고 Dev 구성 서버(`Ninja-Release`)에서 켭니다**(2026-10-11, X5 — 사용자 결정: 내보내기 코드는 Shipping 에서 빠진다). `-gv_traceSlowTickMs=N` 으로 띄우면 틱 본문이 N ms 를 넘을 때 링 버퍼(앞뒤 63 프레임)를 저장합니다(30 초 쿨다운 · 프로세스당 20 파일). Shipping 서버는 지표(`server_tick_seconds` 히스토그램 · 밀린 틱 경고)로 알리기까지만 합니다. 여러 프로세스 트레이스는 첫 파일을 기준으로 같은 호스트면 단조 시계 그대로, 다른 호스트면 벽시계로 맞추고 시계 차이를 줄 묶음 이름에 적습니다(X4).
- **서버 디버깅의 방향**(2026-10-11, 사용자가 추천안 수용). 여러 프로세스 재생(S1)을 먼저 하고 한 프로세스 가상 서버(S8)는 다중 월드가 들어온 뒤에 합니다. 디버그 채널은 읽기 전용과 개발 콘솔 명령 실행까지만 엽니다 — 임의 프로퍼티 쓰기를 열면 에디터가 서버 권위를 우회하므로 값을 바꿀 일은 게임이 정한 개발 명령을 거칩니다. 디버그 채널과 원격 명령은 Dev 전용이고 루프백과 토큰을 요구하며 서버 코드는 에디터에 의존하지 않습니다([서버 디버깅 계획](../plans/ServerDebug.md)).
- **디버그 채널은 개발 명령을 나르는 한 줄 TCP 프로토콜이고 새 읽기 기능은 개발 명령으로 더합니다**(2026-10-15, S3). 요청은 `<토큰> <명령 한 줄>`, 응답은 `OK|ERR <바이트 수>` 줄과 본문입니다. I/O 스레드는 줄을 쌓기만 하고 게임 스레드의 `pump` 가 실행하므로 씬을 읽는 명령이 안전하고 `pause` 중에도 응답합니다. 채널 전용 명령 체계를 만들면 콘솔 · 표준 입력 · 채널이 갈라지므로 `scene.tree` · `object.dump` · `scene.poses` · `state.hash(es)` 를 `SW_DEV_COMMAND` 로 둡니다. 채널이 받는 쓰기는 게임이 정한 개발 명령과 `pause` · `resume` · `step` 뿐이고 토큰이 틀리면 연결을 닫습니다. 에디터 Inspector 탭은 세션이 띄운 서버에 늘 채널을 열고(세션마다 난수 토큰) 요청은 누를 때만 보냅니다 — 클라이언트가 동기라 프레임마다 물으면 서버 틱이 에디터 프레임을 붙잡습니다.
- **어긋남 찾기의 해시는 씬 트랜스폼을 이름 순으로 접은 값이고 이력은 `-gv_stateHashHistory` 일 때만 남깁니다**(2026-10-15, S7). 오브젝트 ID 는 프로세스마다 달라 넣지 않고 같은 이름은 값으로 정렬해 순회 순서를 지웁니다. **권위 고스트는 서버의 `scene.poses` 를 채널로 읽어 이름으로 맞춥니다**(S6) — 복제 키트가 알린 자세는 공통 원천이 없고 이 값이 서버의 진짜 위치라 복제 지연 · 보간 · 예측 오차가 모두 이 차이에 듭니다.
- **게임의 네트워크 역할은 게임 코드가 아니라 실행 인자가 정합니다**(2026-10-11, S1). `GameInstanceBase` 가 `GameNetSession` 을 들고 `-gv_netListenPort` · `-gv_netConnectAddress` 로 엽니다 — 모든 게임이 서버 · 클라이언트로 뜹니다. 리슨 호스트(App)는 기본이 꺼짐입니다. **전용 서버는 서버 설정의 게임 포트(`ServerConfig::_gamePort` · `_listenAddress`)를 늘 엽니다**(2026-10-17 고침 — Shipping 서버에는 테스트 변수가 없어 포트를 못 열었음). 개발 빌드의 `-gv_netListenPort` 는 설정보다 우선하고 받는 주소는 `127.0.0.1` · `0.0.0.0` 만, 다른 주소 · 샤드 2 개 이상은 오류입니다. **고른 역할을 열지 못하면 게임 인스턴스가 기동을 멈춥니다**(2026-10-21, `GameNetLaunch::Invalid`) — 전에는 경고만 남기고 혼자 하는 게임으로 떠 멀티 프로세스 테스트가 시간 초과로 졌습니다.
- **개발 실행의 게임 UDP 소켓은 기본으로 127.0.0.1 에만 묶습니다**(2026-10-11, `gv_netLoopbackOnly` 기본 1). 0.0.0.0 에 묶으면 Windows 방화벽이 실행 파일 경로마다 "허용" 창을 띄웁니다. 다른 기계와 붙을 때만 `-gv_netLoopbackOnly=0` 을 줍니다. 클라이언트는 서버 주소가 정하고 `gv_netConnectAddress` 는 Shipping 에도 등록합니다(2026-10-21). 운영 서버는 `ServerConfig::_listenAddress`(기본 0.0.0.0)가 정합니다.
- **전용 서버 로그 줄에는 `[tick=N]` 을 수준 꼬리표 뒤 · 문맥 꼬리표 앞에 붙입니다**(2026-10-11). 값은 Core `Logger` 의 프로세스 전역 틱 번호이고 `pause` · `step` · 상태 줄의 번호와 맞춰 봐야 해 언리얼처럼 자르지(`% 1000`) 않습니다. 정하지 않은 프로세스의 줄은 그대로입니다.
- **에디터의 멀티 프로세스 재생은 자식 프로세스의 표준 입력으로 제어하고 트레이스는 종료할 때 쓰게 합니다**(2026-10-11, S1). 클라이언트(App)도 `-gv_standardInputCommands=1` 이면 `quit` · 개발 명령을 받습니다 — Windows 의 Ctrl+Break 는 창 프로그램인 에디터에서 쓸 수 없고 강제 종료는 트레이스를 잃습니다. 트레이스는 `-gv_traceSaveOnExit=<경로>` 로 엔진 종료 첫머리에 쓰고 에디터가 이름표를 달아 `mergeTraceJSON` 으로 합칩니다. 정상 종료를 먼저 기다리고(시한 15 초) 넘으면 강제 종료합니다.
