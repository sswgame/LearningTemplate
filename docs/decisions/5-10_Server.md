# 5-10. 전용 서버

> 질문: 5-10. 전용 서버 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **전용 서버는 별도 실행 파일 `Server` 입니다**(2026-10-06). App 의 모드가 아닙니다. 기존 Shipping 프리셋은 Client 타깃이고 Dev 기본은 Game 타깃입니다.
- **서버 설정은 Shipping 에서도 디스크에서 읽고 없으면 기동이 실패합니다**(2026-10-06). Windows 서비스 모드도 있습니다.
- **서버 전용 쿠킹은 하지 않고 패키징할 때 타깃별로 에셋 종류를 뺍니다**(2026-10-06). 처음 빼는 종류는 텍스처 · 셰이더 바이너리 · 오디오이고 메시와 애니메이션은 충돌 · 소켓 · 히트박스 · 루트 모션 때문에 남깁니다. 패키징과 런타임이 같은 테이블(`Config/Engine/CookContract.json` 의 `target_excluded_asset_kinds`)을 읽습니다.
- **지형 레이어 가중치는 텍스처가 아닌 데이터 에셋(`.layerweights`)이고 클라이언트와 전용 서버가 같은 파일을 CPU 로 읽습니다**(2026-10-16, F-1 — 사용자가 "상용 엔진 기준 최선" 으로 위임). 옛 스플랫은 비압축 RGBA8 DDS 였고 텍스처 종류라 서버 패키지에서 빠져 서버의 레이어 질의(`computeLayerWeightsAt` — 발소리 · 표면 재질 · 이동 속도)가 말없이 레이어 0 이었습니다. 상용 엔진도 가중치를 게임플레이 데이터로 서버에 둡니다(언리얼 랜드스케이프, 유니티 `TerrainData` 알파맵). 정본은 하나(`LayerWeightsData` — 매직 `SWLW` · 판 · 너비 · 높이 · 레이어 수 4 · 텍셀마다 4 바이트)이고 GPU 텍스처는 지형이 읽은 바이트로 지형마다 하나 만듭니다(`TextureCache::createCPUTexture`). 버린 안: ① 쿠커가 DDS 에서 서버용 사본을 따로 뽑기 — 정본이 둘이 되고 경로 규약에 기대며 클라이언트는 여전히 DDS 포맷(BC 압축이면 CPU 가 못 읽음)에 묶임. ② 쿠킹 표에서 스플랫 DDS 만 예외로 남기기 — 서버가 텍스처 로더를 타고 "텍스처는 서버에 없다" 는 표의 뜻이 깨짐. 그림은 바뀌지 않습니다(쇼케이스 바이트 동일). 폴백은 없습니다 — 경로를 정했는데 읽지 못하면 오류를 남기고 `reloadTerrain` 이 실패하고 경로가 비면 레이어를 칠하지 않는 지형입니다. 지킴이: `TestServerPackExclusion.testServerPackKeepsTerrainData`, `TerrainTest.DedicatedServerAnswersLayerQueries`.
- **App · Server 가 같이 쓰는 모듈 호스트는 최상위 폴더 `Source/ModuleHost` 입니다**(2026-10-10, 사용자 결정 — 옛 이름 `AppHost`). `CheckEngineLayers` 가 방향(App · Server → ModuleHost → Engine · RuntimeAPI)을 지킵니다. 고정 스텝 시간 정책 `FixedTimestep` 은 Core(`Core/Time`, `GameTimer` 옆)에 두고(언리얼도 고정 시간 값을 모듈 관리자 밖에 둠) 기본값은 만들 때 받습니다(App 이 `EngineConfig` 초기값을 넘김 — 출처 하나). 2026-10-13 에 `Engine/Config` 에서 옮겼습니다.
- **App 과 Server 가 같이 하는 호스트 일은 `Source/ModuleHost` 한 곳에 둡니다**(2026-10-22, `AppStructure`). 호스트 범위 세우기(`ModuleImageHostSubsystem::initializeHostScope`), 핫 리로드 소유(`ModuleReloadDriver` — `LiveReloadManager` 수명 · 씬 뒤 훅 · 개발 명령 `module.reload` · 탐침 `Module.*`), 표준 입력 명령 채널(`StandardInputCommands` — 종료 낱말 `quit` · `stop`)입니다. 그래서 Server 도 `module.reload` 와 `Module.*` 를 얻습니다. 등록 매크로는 호스트가 부르는 클래스의 `.cpp` 에 두어 정적 라이브러리에서도 오브젝트가 링크에서 빠지지 않습니다. 리로드 단축키는 입력을 아는 App 이 정하고(`App::pollReloadHotkeys`) 구동기에는 요청만 넘깁니다.
- **"지금 도는 것" 을 정적 포인터로 내주는 창구(`static T* findActive()`)를 두지 않습니다**(2026-10-22). 소유자가 객체를 범위에 빌려 걸고(`SubsystemScope::bind`) 쓰는 쪽이 `findSubsystem<T>()` 로 찾습니다 — App 의 교체기와 리로드 구동기는 호스트 범위, 엔진의 셸 액션은 서비스 범위, 디버그 HUD 는 `UISystem::getDebugHUD`, 에디터 테마 설정은 `getPreferences<EditorConfig>()`. 정적 칸은 둘째 인스턴스 · 내려간 인스턴스를 가리킬 수 있고 수명이 숨습니다. 정적 함수는 형식으로 막지 못하므로 `CheckServiceAccess` 의 `ServiceAccess/ActiveWindow` 가 헤더의 모양을 막고 남는 것(Core 층 · 잠금 없이 읽는 칸 · 창 소유권 전달)은 규칙 데이터의 예외 표에 이유와 함께 둡니다.
- **"N 번째 프레임에 무엇을 한다" 명령줄 스위치를 두지 않고 시점은 시나리오 단계가 고릅니다**(2026-10-22). `-gv_reloadGameAtFrame` · `-gv_rhiSwapAtFrame`/`-gv_rhiSwapTo` · `-gv_userSettingsApplyFrame` 을 지웠습니다 — 같은 일을 단계 `<DevCommand line="module.reload SWGame"/>` · `<SwapBackend backend="…"/>` · `<Variable name="gv_userSettingsApply" …/>` 가 하고 스위치마다 따로 세던 프레임 카운터와 빈 프레임 관찰자 함수가 사라집니다. `gv_userSettingsApply` 의 명령줄 값은 첫 프레임에 들어갑니다.
- **`ModuleHost` 는 게임 모듈만 다루고 에디터 몫은 App 의 파생 `EditorModuleHost`(`Source/App`)가 맡습니다**(2026-10-10). 전용 서버는 기반 클래스만 쓰고 모드 플래그(`_bDedicatedServer`)가 없습니다 — RHI 를 받았는지가 "디바이스가 있어야 게임을 만든다" 를 정합니다. 에디터가 끼어드는 자리는 기반의 보호 가상 함수 다섯이고 내리는 순서(`suspendModules`)는 기반 한 곳에 남습니다(언리얼 `UGameEngine`/`UEditorEngine` 파생과 같은 방향).
- **에디터 뷰포트 격자는 카메라 높이로 1 · 10 · 100 m 간격을 고르고 경계에서 섞습니다**(2026-10-10). 굵은 선(5 칸마다)은 월드 좌표로 정하고 가장자리는 흐립니다. 화면 공간 셰이더 격자(Unity 2019+ · Godot 4)는 렌더 패스를 하나 더 들여야 해 ImGui 선 그리기를 유지합니다.
- **`UserSettingsHost` 는 엔진으로 옮기지 않고 App 에 둡니다**(2026-10-10). 설정 정책은 이미 엔진의 `UserSettingsManager` 이고 이 파일은 App 이 소유한 창과 `App::onResize` 의 스왑체인 경로에 화면 요청을 적용하는 창 소유자의 단계입니다. 옮기면 창 접근과 리사이즈 순서가 두 곳으로 갈리고 창이 없는 `Server` 는 쓸 일이 없습니다.
- **느린 틱 트레이스는 Shipping 서버에 넣지 않고 Dev 구성 서버(`Ninja-Release`)에서 켭니다**(2026-10-11, X5). 사용자 결정(내보내기 코드는 Shipping 에서 빠진다)을 그대로 두고, 운영에서 시간축이 필요하면 최적화된 Dev 서버를 `-gv_traceSlowTickMs=N` 으로 띄웁니다 — 틱 본문이 N ms 를 넘으면 3 틱 뒤 링 버퍼(그 틱 앞뒤 63 프레임)를 저장하고 30 초 쿨다운 · 프로세스당 20 파일 상한. Shipping 서버는 지표(`server_tick_seconds` 히스토그램 · 밀린 틱 경고)로 "느린 틱이 났다" 까지만 알립니다.
- **여러 프로세스 트레이스는 첫 파일을 기준으로 같은 호스트면 옮기지 않고 다른 호스트면 벽시계로 맞춥니다**(2026-10-11, X4). 같은 기계의 단조 시계(QPC · `CLOCK_MONOTONIC`)는 프로세스끼리 같아 정확하고 벽시계는 밀리초 해상도라 같은 기계에서 쓰면 오히려 틀립니다. 다른 기계는 시계 차이(NTP 수준)만큼 틀린 것을 줄 묶음 이름에 적습니다.
- **서버 디버깅의 방향**(2026-10-11, 사용자가 추천안을 받아들임). 여러 프로세스 재생(S1)을 먼저 하고 한 프로세스 가상 서버(S8)는 다중 월드가 들어온 뒤에 합니다(엔진 구조 변경이 먼저 필요). 디버그 채널은 읽기 전용과 개발 콘솔 명령 실행까지만 엽니다 — 임의 프로퍼티 쓰기를 열면 에디터가 서버 권위를 우회하므로 값을 바꿀 일은 개발 명령으로 게임이 정한 경로를 거칩니다. 전용 창은 Multiplayer 창 하나에 탭으로 모으고, 디버그 채널과 원격 명령은 Dev 전용이며 루프백과 토큰을 요구하고, 서버 코드는 에디터에 의존하지 않습니다. 남은 단위는 [서버 디버깅 계획](../plans/ServerDebug.md)에 있습니다.
- **디버그 채널은 개발 명령을 나르는 한 줄 TCP 프로토콜이고 새 읽기 기능은 개발 명령으로 더합니다**(2026-10-15, S3). 요청은 `<토큰> <명령 한 줄>`, 응답은 `OK|ERR <바이트 수>` 줄과 본문입니다. I/O 스레드는 줄을 쌓기만 하고 게임 스레드의 `pump` 가 실행하므로 씬을 읽는 명령이 안전하고 서버가 `pause` 로 멈춰 있어도 응답합니다(중단점에서 값을 보는 쓰임). 채널 전용 명령 체계를 따로 만들면 에디터 · 표준 입력 · 채널이 갈라지므로 `scene.tree` · `object.dump` · `scene.poses` · `state.hash(es)` 를 `SW_DEV_COMMAND` 로 두어 콘솔 · 표준 입력 · 채널이 같은 명령을 씁니다. 채널이 받는 쓰기는 `teleport` · `tag.add` 같은 게임이 정한 개발 명령과 `pause` · `resume` · `step` 뿐입니다. 토큰이 틀리면 그 연결에서는 아무것도 실행하지 않고 닫습니다(토큰 · 루프백 규칙은 운영 관리 채널 O4 가 그대로 씀). 에디터 Inspector 탭(2026-10-21)은 세션이 띄운 전용 서버에 늘 채널을 열게 하고(빈 TCP 포트 · 세션마다 난수 토큰) 요청은 누를 때만 보냅니다 — 채널 클라이언트가 동기라 프레임마다 물으면 서버 틱이 에디터 프레임을 붙잡습니다. 리슨 호스트(App)는 채널을 열지 않아 대상이 아닙니다.
- **어긋남 찾기의 해시는 씬 트랜스폼을 이름 순으로 접은 값이고 이력은 서버가 `-gv_stateHashHistory` 일 때만 남깁니다**(2026-10-15, S7). 오브젝트 ID 는 프로세스마다 달라 넣지 않고 이름이 같은 오브젝트는 값으로 정렬해 순회 순서를 지웁니다. 꺼져 있으면 해시를 계산하지 않습니다. 키트별 상태(파괴 해시 · 롤백 상태 바이트)는 같은 이력에 다른 이름으로 더하는 확장이고 여기서는 틱을 맞춰 두 프로세스를 비교하는 도구가 먼저입니다.
- **권위 고스트는 서버가 실제로 가진 위치를 채널로 읽어 이름으로 맞춥니다**(2026-10-15, S6). 복제 키트가 마지막으로 알린 자세는 키트마다 달라 공통 원천이 없어 서버의 `scene.poses` 를 고스트로 삼았습니다(복제 지연 · 보간 · 예측 오차가 모두 이 차이에 들어감). 디버그 드로우 큐는 에디터 씬 뷰의 ImGui 오버레이만 그려서 고스트도 거기에만 나오고 시나리오 스크린샷에는 잡히지 않아 눈 확인은 못 했습니다(차이 숫자는 `net.ghost` 로 확인).
- **게임의 네트워크 역할은 게임 코드가 아니라 실행 인자가 정합니다**(2026-10-11, S1). `GameInstanceBase` 가 `GameNetSession` 을 들고 `-gv_netListenPort`(서버 · 리슨 호스트) · `-gv_netConnectAddress`(클라이언트)로 엽니다 — 테스트 게임을 따로 세우지 않고 Empty 를 포함한 모든 게임이 서버 · 클라이언트로 뜹니다. 장르별 복제는 키트가 세션의 라우터에 처리기를 답니다. 리슨 호스트(App)는 기본이 꺼짐입니다. **전용 서버는 서버 설정의 게임 포트(`ServerConfig::_gamePort` · `_listenAddress`)를 늘 엽니다**(2026-10-17 고침 — 처음에는 `-gv_netListenPort` 로만 열어 Shipping 서버가 포트를 아예 열지 못했음). 설정은 `ServerServiceRegistry::findHostContext` 로 받고 개발 빌드의 `-gv_netListenPort` 는 설정보다 우선합니다(에디터 멀티 프로세스 재생이 고른 포트). 받는 주소는 `127.0.0.1` · `0.0.0.0` 만 받고 다른 주소 · 샤드 2 개 이상은 오류로 열지 않습니다. 한 기계에서 서버를 여럿 띄우는 테스트는 게임 포트 0(운영체제가 고름)인 설정을 줍니다(`TestServerBoot.cpp` `runServer`).
  **고른 역할을 열지 못하면 게임 인스턴스가 기동을 멈춥니다**(2026-10-21) — 두 인자를 함께 준 것 · 범위 밖 포트 · 풀리지 않는 주소 · 틀린 서버 설정이 `GameNetLaunch::Invalid` 이고 사용 중인 포트는 `openFromLaunch` 가 false 입니다. 전에는 경고만 남기고 혼자 하는 게임으로 떠서 멀티 프로세스 재생과 테스트가 접속 줄을 기다리다 시간 초과로 졌습니다.
- **개발 실행의 게임 UDP 소켓은 기본으로 127.0.0.1 에만 묶습니다**(2026-10-11, `gv_netLoopbackOnly` 기본 1). 0.0.0.0 에 묶으면 Windows 방화벽이 실행 파일 경로마다 "허용" 창을 띄우는데 워크트리 · 테스트 실행 파일 · 에디터가 띄우는 서버가 많은 개발 환경에서는 매번 뜹니다. 테스트의 UDP 전송(`UDPNetTransport::open( port, bLoopbackOnly )`)도 전부 루프백입니다. 다른 기계와 붙을 때만 `-gv_netLoopbackOnly=0` 을 줍니다(`-gv_netListenPort` 로 연 서버만 읽음, 둘 다 Shipping 에 없음). 클라이언트는 서버 주소가 정합니다 — 루프백 서버면 루프백, 아니면 모든 인터페이스. 배포 클라이언트도 붙어야 하므로 `gv_netConnectAddress` 는 Shipping 에도 등록합니다(2026-10-21). 운영 서버의 게임 포트는 `ServerConfig::_listenAddress`(기본 0.0.0.0)가 정합니다.
- **전용 서버 로그 줄에는 틱 번호 `[tick=N]` 을 수준 꼬리표 뒤 · 문맥 꼬리표 앞에 붙입니다**(2026-10-11, S1 ②). 값은 Core `Logger` 의 프로세스 전역 틱 번호이고 서버가 틱마다 정합니다(네트워크 · 로더 스레드 줄에도 지금 틱이 붙음). `pause` · `step` · 상태 줄의 번호와 맞춰 봐야 해 언리얼처럼 자르지(`% 1000`) 않습니다. 정하지 않은 프로세스(App · 테스트)의 줄은 바이트가 그대로입니다.
- **에디터의 멀티 프로세스 재생은 자식 프로세스의 표준 입력으로 제어하고 트레이스는 종료할 때 쓰게 합니다**(2026-10-11, S1). 클라이언트(App)도 `-gv_standardInputCommands=1` 이면 `quit` · 개발 명령을 받습니다 — Windows 의 Ctrl+Break 는 부모가 콘솔에 붙어 있어야 해 에디터(창 프로그램)에서 쓸 수 없고 강제 종료는 트레이스를 잃습니다. 트레이스는 `-gv_traceSaveOnExit=<경로>` 로 엔진 종료 첫머리에 쓰고 에디터가 프로세스 이름표(`Server` · `Client1`)를 달아 `mergeTraceJSON` 으로 합칩니다. 언리얼은 자식을 끌 때 프로세스를 죽이지만 여기서는 트레이스 때문에 정상 종료를 먼저 기다립니다(시한 15 초, 넘으면 강제 종료).
