# 5-5. 그래픽스와 RHI

> 질문: 5-5. 그래픽스와 RHI 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **RHI 의 완료 · 동기화 계약은 `IRHIDevice` 머리말의 한 표로 두고 네 백엔드가 같은 테스트로 지킨다**(2026-10-25). `waitIdle` 은 앞서 제출한 모든 GPU 작업이 끝난 뒤 돌아오고, `enqueueGPURelease` 콜백은 그 프레임의 작업이 끝난 뒤에만 불리며, GPU 는 `kMaxFrameCountInFlight` 보다 더 뒤처지지 못하고, `readReadbackBuffer` 는 읽기 버퍼가 아닌 핸들을 거절한다. DX11 은 프레임 끝 이벤트 쿼리 링, GL 은 `glFenceSync` 링으로 DX12 · Vulkan 의 펜스와 같은 모양을 만들었고 쿼리를 못 만들면 초기화를 실패시킨다(폴백 없음). 장치 제거 뒤 `waitIdle` 테스트는 Vulkan 에만 있다.
- **장치 손실의 저장소는 `RHITransferSerials` 의 손실 표시 하나이고, 전송 제출은 진입에서 `isLost` 를 보고 `Rejected` 를 돌려준다. 네 백엔드가 같다**(2026-10-25). 손실 표시가 호출 결과를 보는 자리마다 흩어져 빠지던 모양을 모았다. `GetDeviceRemovedReason` 은 `isDeviceRemoved`(묻고 표시) 한 함수만 묻고, 손실 로그는 처음 표시한 호출만 남긴다. `debugRemoveDevice` 는 표시만 하는 시험용 훅이다(D3D11 에는 `RemoveDevice` 가 없어 제거된 장치의 Present 실패 경로는 확인하지 못함).
- **스테이징 링의 할당 결과는 `RHITransferSerials::classifyStagingAllocation` 한 곳이 제출 결과로 옮기고 장치를 잃었으면 `Rejected` 다. GL 의 버퍼 구간 갱신(`updateConstantBuffer` 등)은 링으로 옮기지 않는다**(2026-10-25). 옮기는 안은 기각했다 — 프레임 경로 호출자는 모두 RT 이고 RT 는 프레임 내내 컨텍스트를 쥐어 줄어드는 점유가 없으며 링 장부 · 펜스 · GPU 복사만 더해진다(언리얼 GL RHI 도 작은 유니폼은 `glBufferSubData`). 큰 인스턴스 구간에서 드라이버 암묵 동기가 보이면 측정으로 다시 연다.
- **Vulkan 텍스처 전송은 그래픽스 큐에 기다리지 않고 내고(커맨드 버퍼 + 펜스 재사용), 스테이징은 업로드 · 되읽기 영속 매핑 링 둘이다. 전용 전송 큐는 쓰지 않는다**(2026-10-25, RhiAsyncUploads U6). 전송 큐는 소유권 이전 배리어 · 세마포어가 필요하고 이득이 큰 텍스처 스트리밍 중에만 있어 측정 전에는 하지 않는다. 링을 나눈 이유는 가져가지 않은 되읽기가 할당 순서 회수로 업로드까지 `Busy` 로 만들기 때문이다. 끝나기 전에 버린 되읽기 구간은 시리얼을 붙여 복사가 끝난 뒤 돌려받고, 전송 중 파괴한 텍스처의 해제는 시리얼 키 해제 큐에서 전송이 끝난 뒤 프레임 펜스 뒤로 넘긴다.
- **DX12 셰이더 가시 힙은 524288 칸(bindless 32768 + 온라인 블록 960 × 512)이다**(2026-10-23). 65536 칸은 미리보기 월드 넷을 그리는 한 프로세스 재생에서 바닥났다(언리얼 기본도 수십만 칸, 힙 메모리 16 MB).
- **RHI 디바이스 안은 서브시스템으로 만들지 않는다 — 부품은 타입 있는 멤버로 명시 소유하고 종료 순서는 `IRHIDevice::shutdown` 의 네 단계가 정한다**(2026-10-14, 백로그 C-26). 언리얼 RHI 도 같다. 컬렉션으로 옮겨도 남는 이득은 종료 순서뿐이라 대신 순서를 어기면 터지게 했다(`shutdown` 이 해제 큐가 비었는지 단언).
- **셰이더 쿠킹 스탬프의 도구 지문은 버전 상수로 만든다 — 컴파일 옵션 판 · Vulkan 타깃 판 · 컴파일러 버전 글(`ShaderCooker::kCompilerVersion`, vcpkg `directx-dxc` 포트 버전)**(2026-10-14). 컴파일러 라이브러리의 내용 해시는 Windows 에서 쿠킹한 스탬프를 리눅스에서 모두 낡게 만들었다(언리얼도 DDC 키에 컴파일러 버전 식별자). `TestShaderCompilerVersionPin.py` 가 상수와 vcpkg 설치 기록을 대조한다.
- **셰이더 쿠킹 스탬프(`cook.stamp`)는 쿠킹 기록(`.cookrec`) 형식으로 옮기지 않는다**(2026-10-18, C-42 K5). 스탬프는 커밋되는 산출물 곁의 계약이고 판정은 `ShaderCooker::verifyCookedShaders` 하나가 보는 반면 쿠킹 기록은 체크아웃마다의 `Saved/` 캐시다(언리얼도 셰이더 DDC 키를 에셋 쿠킹과 섞지 않음).
- **셰이더 쿠킹은 컴파일 · 리플렉션을 병렬로 돌리고 합치기는 요청 순서대로 직렬로 한다**(2026-10-25, `ShaderCookDriver::cookRequests`). 작업(요청 × 포맷)마다 자기 결과 칸에만 쓰고 합치기 · 스탬프 쓰기는 직렬이라 산출물은 직렬일 때와 바이트까지 같다. 같은 바이너리를 만드는 요청은 한 사슬이다.
- **쿠킹은 최신 바이너리도 매번 읽어 리플렉션을 다시 뽑는다 — 이전 매니페스트에서 가져오지 않는다**(2026-10-25, 검토 뒤 하지 않기로 함). ① `isCookedOutputCurrent` 는 매니페스트와 바이너리가 같은 쿠킹에서 나왔는지 보지 않아 병합이 둘을 다른 쪽 것으로 고르면 재사용한 리플렉션이 조용히 낡는다. ② 매니페스트(`kVersion` 2)에 정점 입력이 없어 계약 검사를 다시 돌릴 수 없다. ③ `reflect` 의미가 바뀌어도 소스가 그대로면 옛 값이 남는다. 재사용하려면 바이너리 내용 해시를 매니페스트 항목에 넣어야 한다.
- **런타임 UI 를 위해 RHI 에 R8 텍스처, 영역 업로드, 프리멀티플라이 블렌드, 가위 사각형을 더했다**(2026-10-06). 사각형 클리핑은 가위로 하고(Slate · Dear ImGui · Godot 과 같고 배치가 끊기지 않음) 둥근 모서리만 셰이더에서 한다.
- **머티리얼 XML 과 셰이더 구조체의 필드 불일치는 오류다 — 폴백 없음**(2026-10-23). 셰이더에만 있는 필드 · XML 에만 있는 필드 · 리플렉션 실패는 `Material::syncPropertiesFromReflection` / `ensureShaderLayout`(`[[nodiscard]]`)이 오류를 남기고 바이트를 비우며 `MaterialTest.EveryRepositoryMaterialMatchesItsShaderStruct` 가 모든 .material 을 검사한다.
- **프리멀티플라이 블렌드는 PSO 비트(`_bPremultipliedAlpha`)이고 머티리얼 블렌드 enum 에는 넣지 않는다**(2026-10-06). 언리얼도 `EBlendMode` 와 RHI 블렌드 상태가 따로다.
- **보기 모드는 뷰마다의 설정이다**(`RenderViewSettings::_viewMode`, 2026-10-10). 씬 뷰 툴바는 씬 뷰에만 걸고 게임 뷰는 Lit 이다(언리얼 View Mode 와 같다). Normals · Depth · Overdraw 는 후처리 · 톤맵을 건너뛴다. Overdraw 는 알파 0 프리멀티플라이로 더하며 깊이 테스트는 남기고 쓰기만 끈다(테스트를 끄면 Vulkan 이 깊이 첨부 없는 PSO 를 만든다).
- **디퍼드의 툰은 G버퍼에 칸을 더하지 않고 포워드로 그린다**(2026-10-21, `ForwardOnlyOpaque` · `MATERIAL_FORWARD_ONLY`). G버퍼 패스가 그 머티리얼을 빼고(`_pExcludedMaterialDefine`) 조명 패스 뒤 포워드 전용 패스가 같은 깊이에 그린다(유니티 URP 의 `UniversalForwardOnly` 와 같음). 셋째 G버퍼 타깃안은 기각 — 림 · 맷캡 · 발광 · 빛마다의 그림자색을 못 담아 그림이 갈리고 모든 머티리얼의 PSO 타깃 수 · 대역폭이 는다. 툰 표면은 SSAO 노멀에 들어가지 않는다. define 을 빠뜨린 머티리얼을 막는 toon.hlsl `#error` 는 셰이더 다시 굽기와 함께 넣는다(계획 GraphicsFormatBundle G2).
- **톤맵을 HDR 씬 컬러로 바꾸는 일은 하지 않았다**(2026-10-06). 바꾸면 골든 이미지를 모두 다시 떠야 한다. 어두운 게임은 데이터로 맞춘다.
- **점광 · 스폿 그림자는 큐브 · 배열 텍스처가 아니라 2D 그림자 아틀라스다**(2026-10-13). 유니티 URP · Godot 방식이고 RHI 를 바꾸지 않으며 DX11 · GL 의 텍스처 슬롯 네 개가 그대로다. 방향광 캐스케이드(최대 4)도 같은 아틀라스 타일이다. 칸이 모자라면 주 시점의 화면 크기 대리값(경계 구 반경 / 카메라 깊이)이 큰 빛부터 받는다(`ShadowSetupUtil::computeLocalShadowPriority`). 화면 크기별 칸 크기 변경은 하지 않았다.
- **깊이 패스(그림자 · 깊이 프리패스)는 모양을 머티리얼 코드가 정하는 배치만 머티리얼 셰이더로 그린다**(2026-10-17, `FrameRendererUtil::drawsDepthWithMaterialShader`). 알파 컷오프는 깊이 퍼뮤테이션(`SW_PASS_SHADOW` · `SW_PASS_DEPTH_PREPASS`)의 픽셀 스테이지(`clip` 만), 정점 변형(바람)은 그림자 패스만 정점 스테이지로 그린다. 나머지는 shadowdepth.hlsl 을 나눠 쓴다(언리얼도 Masked · WPO 만 자기 깊이 셰이더). shadowdepth.hlsl 이 머티리얼 값을 읽게 하는 안은 기각 — 머티리얼마다 구조체 배치가 달라 컷오프 값 · 텍스처 칸을 찾을 수 없다.
- **지형 쓰기는 "사본을 고쳐 사각형만 넘기는" 한 길이다**(2026-10-15, `D2-5` (7), `TerrainComponent::writeHeights` · `writeLayerWeights`). 지형은 읽기용 배열을 내주고 에디터 브러시(`TerrainBrush`)가 고친 배열에서 **바뀐 사각형만** 받는다. 샘플 세터나 브러시 타입은 Engine 에 두지 않고 되돌리기는 편집 전 사본을 같은 사각형으로 다시 쓴다(Undo 용 API 없음). 읽는 쪽(병렬 틱 · 배치 계산)과 겹치지 않게 하는 방법은 이중 버퍼나 락이 아니라 **호출 규칙**이다 — 틱 밖(`executeOrDeferPostTickOnComponent`)에서 프레임에 한 번만 부른다(락은 질의마다 비용이고 이중 버퍼는 높이를 두 벌 든다).
  높이를 쓰면 닿는 청크(노멀 때문에 한 샘플 바깥까지)의 메시 · 바운드를 다시 만들고 청크 세대(`getChunkGenerations`)를 올려 그 청크의 물리 바디만 다시 만든다(언리얼 랜드스케이프 컴포넌트별 충돌과 같음). 내비메시는 `SceneNavigation::invalidateArea`, 식생은 지형 세대가 0.3 초 그대로일 때 다시 뿌린다. 가중치는 CPU 스플랫 바이트를 고치고 바뀐 사각형만 `TextureCache::requestRegionUpdate` 로 올린다. 칠하는 텍스처는 **지형마다 자기 것**이다(`createCPUTexture`, 가중치 에셋 `.layerweights`, 5-10 절) — 같은 가중치 에셋을 쓰는 다른 지형은 칠해지지 않는다. 가중치 사각형은 스플랫 텍셀 좌표이고 정사각형 스플랫만 다룬다.
- **저장하지 않은 지형 편집은 상태 스냅샷으로 넘긴다**(2026-10-15). 교체 전에 묻는 대신(`setSaveBlockReason`) `GameInstanceBase` 가 `TerrainComponent` 를 `registerStatefulComponent` 로 올려 높이 · 스플랫을 싣는다. 렌더러를 바꾸는 일이 편집을 잃게 하면 안 된다.
- **`FrameRenderer` 는 "한 씬의 프레임을 그래프로 그린다" 만 들고 이미지를 꺼내는 일 · 진단 덮어쓰기 · 캔버스 렌더 텍스처 대상을 가른다**(2026-10-15, C-26 ⑤). 캡처 · 되읽기는 `FrameCapture`, 진단 덮어쓰기는 값 하나 `FrameDebugOverrides`(배포본 렌더러에는 칸도 세터도 없음), 렌더 텍스처 대상은 `CanvasRenderer` 가 맡는다. 추가 뷰(`ViewTarget`) · 미리보기 씬 렌더러 목록 · 정점 변형 컴퓨트 · PSO 는 더 가르지 않았다.
- **메시 없는 드로우의 슬롯 0 은 장치 공용 대체 정점 버퍼가 받고 크기는 계약 상수 `constant::kFallbackVertexCount`(6) 다**(2026-10-15). SV_VertexID 로 정점을 만드는 드로우(풀스크린 3, 캔버스 사각형 6)도 슬롯 0 을 읽는데 삼각형 셋만 담아 캔버스가 범위 밖을 읽었다. PSO 마다 레이아웃을 가르면 네 백엔드의 PSO 키 · location 계약을 다시 짜야 해서(언리얼은 빈 정점 선언) 내용(`arrFallbackVertex`)을 `RHITypes.h` 에 두고 캔버스는 `static_assert` 로 상수를 넘지 못한다.
- **Debug DX12 는 디버그 레이어 메시지를 나는 자리에서 로그로 내고 센다**(`ID3D12InfoQueue1::RegisterMessageCallback`, `getValidationMessageCount`, 2026-10-15). 큐는 장치 실패 때만 비워 경고가 조용히 쌓였다. 테스트가 "검증 경고 없음" 을 단언한다.
- **Vulkan 은 첫 `VK_ERROR_DEVICE_LOST` 뒤로 제출 · 펜스 · 큐 · 장치 대기 · 표시를 하지 않고 프레임을 건너뛴다**(2026-10-15). 손실로 제출하지 못한 프레임 펜스는 영영 신호되지 않아 `UINT64_MAX` 로 기다리면 멈춘다. Vulkan 에는 장치 제거 API 가 없어 `rhi.removeDevice` 는 이 손실 상태로 흉내 낸다.
- **디퍼드 그림의 기준은 `ee6fff232`(디퍼드 블룸의 밝은 부분을 반해상도 `BloomDownsample` 로) 이후다**(2026-10-15). 성능 기준선 `D:\w\perfbase` 와 main 의 디퍼드 차이는 이 커밋에서 생겼고 의도된 변경이라 되돌리지 않는다. `40c13f841` 근처 구간을 다시 탐색할 때는 DX11 · GL 만 돌린다(DX12 DEVICE_HUNG · Vulkan 시간 초과, 반복 TDR 은 어댑터를 망가뜨림).
- **추가 뷰(CCTV · 백미러)의 예산은 뷰 수와 내부 해상도 픽셀 합의 결정적 비용 모형이고 보임은 모니터의 화면 크기다**(`RenderViewBudget` · `CameraRenderOutput::_minScreenSize`, 2026-10-20). 언리얼 SceneCapture · Godot 은 예산이 없고 유니티 HDRP 는 개수로 나눠 그린다. GPU 시간 되먹임은 타임스탬프가 프로파일러 빌드에만 있어 Shipping 예산이 될 수 없고 같은 입력에 다른 뷰를 고르게 해 쓰지 않는다. 예산은 렌더 텍스처 뷰만 받는다(화면 사각형 뷰는 주 화면의 일부라 미루면 멈춰 보임).

- **머티리얼 셰이더는 엔진이 가진 헤더 뼈대에 훅 다섯 개(표면 · 조명 모델 · 월드 위치 오프셋 · 사용자 보간 필드 · 외곽선)만 정의하는 구조다**(2026-10-23, 훅 H1~H7). 뼈대는 `materialshader.hlsli`(훅 선언 · 기본 선택) → `materialshadermain.hlsli`(정점 · 픽셀 진입점)이고 셰이더 파일이 훅을 정의하고 뼈대를 include 한다.

- **동기 업로드 대기는 "제출 → 티켓 → 폴링" 비동기 계약으로 옮기고 프레임 경로에는 `waitIdle` 을 새로 만들지 않는다**(2026-10-25, [RhiAsyncUploads](../plans/RhiAsyncUploads.md)). 텍스처 업로드 둘과 되읽기의 동기 가상 함수를 RHI ABI 를 한 번 올려 지운다(백엔드 DLL 이 같은 vtable 을 봐야 하고 옛 함수 위의 기본 구현은 폴백이 된다). 동기가 필요한 테스트 · 도구는 ABI 밖의 `AndWait` 헬퍼를 쓴다. 머티리얼과 PSO 는 준비 전 / 준비됨 / 실패 상태를 데이터로 두어 준비 전에는 그리지 않는다. - **DX11 즉시 컨텍스트는 런타임 다중 스레드 보호(`SetMultithreadProtected( TRUE )`)를 켜고 백엔드는 같은 임계 구역을 잡는 가드(`D3D11ImmediateContext::lock()`)로만 컨텍스트를 꺼낸다**(2026-10-25). 다른 스레드의 전송 · 폴링 · `waitIdle` 이 렌더 스레드의 프레임 스트림과 같은 컨텍스트를 락 없이 써 서로 막지 못했다. 렌더 스레드가 프레임마다 뮤텍스를 잡는 안은 기각 — 다른 스레드가 프레임 하나(백프레셔 · Present 포함)를 기다리고 재귀 잠금이 필요하며 `getNativeContext` 로 나가는 ImGui 백엔드는 막지 못한다. 언리얼 · 유니티 D3D11 은 즉시 컨텍스트를 RHI 스레드 하나만 쓰지만 여기 계약은 "어느 스레드에서나 제출" 이다.
- **GL 텍스처 되읽기는 영속 매핑 PBO 되읽기 링 하나로만 받는다**(2026-10-25, RhiAsyncUploads 2.2). 컨텍스트를 빌린 동안에는 `glGetTextureSubImage` 와 펜스 하나만 내고 바이트는 펜스 뒤 `takeTextureReadback` 이 컨텍스트 밖에서 매핑에서 복사한다. 장부는 업로드와 같은 `RHIStagingAllocator` 이되 구간은 가져갈 때나 버린 읽기의 펜스가 지날 때 돌아온다. 링보다 큰 읽기는 `Rejected`, 가져가지 않은 읽기로 차면 `Busy`, GL 4.4 가 없으면 모두 `Rejected`(동기 `glGetTexImage` 경로는 남기지 않음). 용량은 `gv_rhiReadbackRingMegabytes`(기본 64 MiB), RHI ABI 36. 읽기마다 버퍼를 만들면 GL 이름 생성 · 매핑이 컨텍스트 점유에 든다.
- **종류마다 뜻이 다른 `void*` 핸들은 종류 확인과 값 확인이 한 함수에 든 `[[nodiscard]]` 길로만 내보낸다 — `queryNativeHandles( 기대 백엔드, … )` · `tryGetNativeTexturePointer( 기대 백엔드, … )` · `NativeWindowEvent::tryGetWin32Window`**(2026-10-25, cifixl5). `getNativeDevice` · `getNativeContext` · `getNativeCommandQueue` · `getNativeTexturePointer` 와 이벤트의 창 핸들은 보호 · 비공개로 내렸다. 백엔드별 함수 대신 기대 백엔드를 인자로 받는 하나로 둔 것은 모듈 경계를 넘는 것이 버전 번호가 든 `RHINativeHandles` 하나라는 계약을 지키기 위해서다. 언리얼은 `GetNativeDevice()` 의 `void*` + `GetInterfaceType()` 두 단계라 같은 결함이 가능하고 유니티의 백엔드별 인터페이스가 이 결정에 가깝다.
- **Vulkan 서피스를 만드는 길은 정수 코드가 아니라 `VulkanWsiKind` enum class 로 넘기고 `createSurface` 는 모든 값을 나열한 switch 로 만들며 이 플랫폼에서 못 만드는 값은 오류로 멈춘다**(2026-10-25, vkwsi). `NativeSurfaceKind` 는 X11 안의 xlib · xcb 를 가르지 못해 Vulkan 폴더에 따로 뒀다.
- **DX11 의 큰 텍스처 업로드는 장치가 초기 데이터로 만든 `STAGING` 텍스처로 올리고 즉시 컨텍스트 잠금 안에서는 `CopySubresourceRegion` 과 이벤트 쿼리 `End` 만 한다**(2026-10-25). `UpdateSubresource` 는 소스 복사(수십 MiB)를 잠금 안에서 해 렌더 스레드의 `ExecuteCommandList` · `Present` 가 기다렸다. 스테이징 풀에 `Map( WRITE )` 로 쓰는 안은 기각 — `Map` · `Unmap` 이 즉시 컨텍스트 호출이라 잠금을 두 번 잡고 버퍼 → 텍스처 복사가 없어 풀이 크기 · 포맷마다여야 한다. 스테이징은 전송 큐 항목(`TransferProbe`)이 쥐어 워터마크가 지나면 놓고 합의 상한은 `gv_rhiStagingRingMegabytes`(64 MiB, 차면 `Busy`)다. `gv_rhiDirectUploadMaxKilobytes`(256 KiB) 이하는 `UpdateSubresource` 를 그대로 쓴다(두 값은 `RhiAsyncUploads` 측정 M1 이 정함).
- **DX11 업로드 스테이징 예산보다 큰 업로드 한 장은 `Rejected` 가 아니라 예산 전부를 잡고 혼자 들어간다. 텍스처 되읽기는 `Map` · `Unmap` 호출에만 즉시 컨텍스트 잠금을 잡고 버퍼 구간 갱신은 잠금 안의 `UpdateSubresource` 그대로 둔다**(2026-10-25). 코드가 만드는 업로드(에디터 뷰 첫 채우기 4K 31.6 MiB · 8K 126.6 MiB, 렌더 타깃 스냅샷 4096² 64 MiB)는 설정에 따라 예산을 넘고 예전 `UpdateSubresource` 는 이 크기를 받았다. 기본값을 올리는 안(상한 없음)과 한 장을 구간으로 쪼개는 안(앞 조각의 GPU 완료를 제출 안에서 기다려야 함)은 기각했다. 되읽기는 `Map` 포인터가 `Unmap` 까지 어느 스레드에서나 읽어도 되는 CPU 메모리라 행 복사를 두 잠금 사이로 뺐다. 버퍼 구간 갱신은 호출자(`GPUScene` · 정점 · 모프 풀)가 모두 렌더 스레드라 잠금 밖으로 빼도 프레임이 줄지 않는다.
- **DX11 업로드 스테이징 예산은 구간 장부(`RHIStagingAllocator`)에 합치지 않고, 총량만 세는 `RHIStagingBudget` 으로 두되 예산 전부를 잡는 요청의 예약만 장부와 같게 한다**(2026-10-28). 언리얼 D3D11 RHI 는 업로드 힙 · 링 없이 호출마다 `UpdateSubresource` 나 스테이징 `Map` 이고 링 · 힙 할당자는 D3D12 RHI 에만 있다. 유니티 SRP 의 업로드 버퍼와 Godot `RenderingDevice` 의 스테이징 블록(고정 블록 링, 프레임 단위 회수)도 링을 가진 백엔드(D3D12 · Vulkan)의 것이며 Godot 에는 D3D11 백엔드가 없다(기억에 기댄 비교). DX11 은 업로드마다 스테이징 텍스처를 드라이버가 따로 잡아 나눌 메모리 덩어리와 오프셋이 없으므로, 장부로 흉내 내면 합이 들어가는 업로드를 조각 남음으로 `Busy` 시켜 예전 카운터보다 나빠진다. 합치지 않은 대신 장부에만 있던 굶음 방지를 옮겼다: 예산 이상의 업로드는 복사 중인 것이 없을 때만 받고, 못 받으면 예약(250 ms, 장부의 `kSoloReservationMicroseconds` 와 같은 추정)을 남겨 작은 업로드를 `Busy` 로 돌려 복사 중인 합이 0 이 되게 한다. 규칙은 GPU 없이 `RHIStagingRingTest.UploadBudget*` 가 본다.
- **Vulkan 프레임 밖 구조 버퍼 갱신(`updateStructuredBufferRegions`)과 GPU 시계 읽기(`readGPUClockNanos`)의 `VulkanOneShotCommands::endSubmitAndWait` 는 비동기로 바꾸지 않고, `RhiAsyncUploads` 단위(U7 ~ U14)에도 넣지 않는다**(2026-10-28). 경계: `RhiAsyncUploads` 는 텍스처 전송 티켓(`RHITransferTicket`)과 `waitIdle` 호출 정리를 맡고, 이 둘은 U2 로 이미 큐 전체가 아니라 자기 제출의 펜스만 기다리며 프레임 안 구조 버퍼 갱신은 프레임 스트림에 기록해 기다리지 않는다. 프레임 밖 갱신은 초기 업로드와 테스트 경로이고 GPU 시계 읽기는 컨텍스트를 열 때 한 번에 값을 돌려받아야 해 기다림이 본질이다. 비동기로 하려면 스테이징 버퍼 수명을 전송 작업(`VulkanTransferJob`)처럼 펜스가 지난 뒤로 미루는 구조가 필요해 이득 없이 코드만 는다. 풀리는 조건: M1 측정에서 `RT.Upload.waitIdle` 가 프레임 경로(업로드가 없는 프레임)에서 보이면 그때 갱신 쪽만 전송 작업으로 옮긴다.
- **Vulkan 큐 소유권 이동(release/acquire 배리어)은 하지 않는다**(2026-10-28). 장치는 그래픽스 큐 패밀리 하나만 쓰고 모든 버퍼 · 이미지가 `VK_SHARING_MODE_EXCLUSIVE` 에 `VK_QUEUE_FAMILY_IGNORED` 배리어라 옮길 소유권이 없다. 전용 전송 큐를 도입하는 날(`RhiAsyncUploads` 2.2 가 측정 뒤로 미뤘다) 소유권 이동과 레이아웃 전이를 같이 설계한다.
- **GL `transitionBuffer` 의 `VertexOrConstant` · `Index` 는 SSBO 배리어 비트가 아니라 정점 · 유니폼 · 요소 배열 비트를 건다**(2026-10-28). Vulkan 이 같은 상태에 거는 접근(`VERTEX_ATTRIBUTE_READ` · `UNIFORM_READ` · `INDEX_READ`)과 짝이다. 호출처가 아직 없는 잠복 결함이었다. `createPersistentRingBuffer` 의 `uint32 mapFlags`(= `GLbitfield`)는 `glBufferStorage` · `glMapBufferRange` 가 같이 받는 `MAP_*` 비트만 담아 결함이 아니다.
- **엔진 밖으로 나가는 네이티브 컨텍스트는 잠금 안의 콜백(`IRHIDevice::withNativeContext( 기대 백엔드, 콜백 )`, `[[nodiscard]] bool`)으로만 주고 스레드끼리 나눠 쓰는 RHI 상태는 같은 락이나 atomic 으로 다룬다**(2026-10-25). `RHINativeHandles::_pContext` 는 지웠다(판 3). DX11 은 즉시 컨텍스트 임계 구역을 쥔 채 콜백을 부르고 나머지 백엔드의 컨텍스트는 렌더 스레드 전용이다. DX11 의 ImGui 렌더러는 텍스처 갱신과 보조 뷰포트 렌더를 렌더 스레드로 옮겼다(`requiresRenderThreadContext` — 호출마다의 런타임 보호는 파이프라인 상태를 지키지 못해 UI 스레드가 프레임 중간에 렌더 타깃을 바꿀 수 있었음).
  DX12 는 프레임 펜스의 Signal 과 값 올리기를 `_uploadSlotMutex` 안에서 한 덩어리로 한다(락 밖이면 Signal(V) 뒤에 실행된 복사가 V 를 받아 얼로케이터 Reset 이 도는 복사를 지울 수 있음). 텍스처 전송은 이 락 밖이다 — 전송마다 얼로케이터를 쥔 작업 · 전용 펜스 · 전용 제출 락(`_transferSubmitMutex`)이고 해제는 전송 시리얼에 건다. 펜스 대기 이벤트는 장치에 하나를 두지 않고 기다릴 때마다 만든다(자동 리셋 이벤트 하나를 두 스레드가 기다리면 남의 신호로 깨어남). 다른 스레드가 읽는 플래그(타임스탬프 스위치, 쿼리 준비 표시, 프레임 펜스 값 · 링 인덱스, Vulkan 프레임 슬롯)는 `atomic` 이다.
- **스테이징 링 장부(`RHIStagingAllocator`)는 할당 순서가 아니라 구간마다 돌려받고 빈 자리는 `SpanAllocator` 가 쥔다**(2026-10-25, RhiAsyncUploads 2.2). 순서로만 돌려받으면 가져가지 않은 되읽기 하나가 링 맨 앞을 막아 `readbackTexture2DAndWait` 가 시간 초과로 실패했다. 시리얼을 붙인 구간은 시리얼이 워터마크를 지나면 순서와 무관하게 돌아오고 쥔 구간들이 남은 자리를 다 차지할 때만 `Busy` 다. 기각: 가져가지 않은 읽기를 상한 뒤 자동으로 버리기(티켓 계약을 바꾸고 RHI 에 프레임 시계를 들이며 막힘은 그대로), `ScopedForbidBlockingTransfer` 로 "티켓 쥔 채 `AndWait` 금지"(같은 스레드만 막음).
- **티켓을 쥔 채 제출하는 `...AndWait` 는 `PendingReadback` 이 쥔 수로 Debug 에서 막는다**(2026-10-25). 쥔 티켓들이 스테이징을 다 차지하면 `submitWhileBusy` 가 시간 초과로 실패했다. `PendingReadback` 이 스레드마다 쥔 수를 세고 `...AndWait` 가 제출 전에 0 인지 단언한다. 한계: 다른 스레드가 쥔 티켓과 `PendingReadback` 에 넣지 않은 날 티켓은 세지 못한다.
- **스테이징 링보다 큰 전송 한 장은 장부가 링이 비었을 때만 단독 구간으로 내주고 백엔드는 그 크기의 일회성 버퍼에 받는다**(2026-10-25, RhiAsyncUploads 2.2). GL 이 링(64 MiB)보다 큰 업로드 · 읽기를 `Rejected` 해 에디터 6K+ 뷰 첫 채우기(77.7 MiB)와 ultra 그림자 스냅샷이 회귀했다. 링보다 크고 단독 상한(`gv_rhiStagingSingleMaxMegabytes`, 기본 512 MiB, 0 이면 받지 않음) 이하인 요청은 링에 산 구간이 0 일 때만 `_bSolo` 구간이 되고 그동안 다른 요청은 `Busy` 라 메모리 최고점은 max(링, 가장 큰 한 장)다. 상한을 넘으면 `Rejected`(`TooLarge`)이고 설정 이름을 로그로 알린다. GL 은 단독 구간마다 `glBufferStorage` 영속 매핑 버퍼를 만들고 장부가 돌려받은 뒤 `retireFinishedTransfers` 가 지운다.
  굶주림은 250 ms 예약으로 막는다 — `Full` 을 받은 단독 요청이 남긴 예약 동안 새 링 요청도 `Busy` 이고 다시 올 때마다 연장되며 단독 구간을 내주면 끝난다. 링이 빌 때까지 예약하면 가져가지 않은 되읽기가 링을 비우지 않아 작은 읽기가 영원히 `Busy` 이고 거절 횟수로 끝내면 호출자 수에 따라 뜻이 바뀐다. 기각: 기본 링을 키우기(한도 없는 크기가 남음), 한 장을 쪼개 여러 번 내기, 호출마다 단독 허용 플래그.
- **꺼진 후처리 효과는 패스를 기록하지 않고 출력이 입력을 가리킨다**(2026-10-27, Candidates-graphics PostEffectBypass). 블룸 · 외곽선 · 피사계 심도 · 모션 블러는 출력 이름이 원본에 이어지고(`kBypassesToSource`, 출력과 원본은 형식 · 나눗수가 같아야 한다 — 디퍼드 OutlineColor 를 RGBA16F 로 맞췄다), 원본이 없는 SSAO 는 출력이 없어 읽는 쪽이 AO = 1 을 쓴다(`kOmittedWhenOff`). 읽는 패스가 모두 빠진 풀스크린 패스(BloomDownsample)도 빠지고, 그런 패스의 타깃은 처음 돌 때 만든다(`FrameRenderer::applyViewPassSelection`, 뷰마다 셋업에서). 기각: 원본 복사 · 셰이더가 원본을 고르는 길(꺼져도 전 화면을 한 번 읽고 쓰고 타깃이 늘 메모리를 차지함), 뷰마다 그래프를 다시 컴파일하기(뷰 셋 · 프레임마다 컴파일 비용).

- **TAA 기록은 지난 프레임이 기록을 썼을 때만 섞는다 — 후처리를 다시 켠 첫 프레임은 TAA 컷이다**(2026-10-27, rgprune). 후처리를 끈 프레임의 TAA 는 기록을 쓰지 않아 다시 켠 프레임이 끄기 전 화면을 섞었다(가장자리에 옛 그림). `beginViewHistory` 가 `_bHistoryReset` 과 같은 자리에서 `_bTaaHistoryReset`(컷 또는 지난 프레임 미기록)을 정한다. 언리얼도 기록이 무효인 뷰는 `bCameraCut` 처럼 버린다. 기각: 뷰 상태 키(후처리 · 렌즈 · 품질 · 모션 블러)로 그래프 변형을 캐시하기 — 피사계 심도 · 모션 블러는 TAA 뒤라 기록과 무관하고, 출력 이름 잇기가 컴파일 없이 같은 결과를 낸다.

  **깊이 충돌**: 뷰마다 지난 프레임 장면 깊이의 R32 실수 사본(`_depthHistory*`, `depthhistory.hlsl`)을 컴퓨트 프리패스에서 만들고(깊이 텍스처는 RW 가 될 수 없다) 입자 월드 점을 히스토리 뷰-투영으로 투영해 그 텍셀 깊이보다 뒤이고 깊이 면에서 `_depthThickness` 안쪽이면 닿은 것으로 본다. 법선은 이웃 텍셀 둘의 깊이 점이 이루는 면, 튀기는 CPU 와 같은 식(띄움 `kSurfaceSkin`)이다. 한계(받아들였다): 화면 밖 · 카메라 뒤는 보지 않고, 가려진 면은 두께로만 가르며, 한 프레임 늦은 깊이라 빠른 면은 어긋나고, 주 시점만 본다. GL 장면 깊이는 0 행이 아래라 깊이 히스토리를 D3D 순서로 뒤집어 쓴다(GL 의 R32 실수 RW 읽기는 슬롯마다 형식을 적는 `SW_RW_SLOT<n>_GL_FORMAT` 로 고쳤다).
  **그리기 순서**: 방출기를 메시 투명 배치와 한 순서로 섞고(프리미티브 단위) 추가 뷰는 그 뷰의 순서로 그린다(`GPUTransparentParticleSlot`, `FrameRenderer::applyViewTransparentOrder`). 패스 끝에 붙는 다른 경로는 정렬 대상이 아니다: 캔버스 패스는 HUD(마지막이 의도), 월드 UI 는 렌더 텍스처를 메시에 붙여 메시 투명 배치로 정렬, `MeshOutline` 은 투명 앞의 불투명 배치만, `Outline` · 디버그 도형은 선택 · 에디터 겹침.
  **셰이더에서 얻은 교훈**: GPU 크기 · 색 커브(`evaluateCurve` — 반복과 이른 반환을 다섯 번 인라인)가 Vulkan · GL 에서 첫 키 값을 냈다. 끝에서 한 번에 고르는 꼴로 고쳐 네 백엔드가 통과했다. 처음 "SPIR-V 최적화 탓" 으로 봤으나 반증됐다(검증기 통과, 해석기 실행이 `-Od` 와 비트까지 같음) — 최적화된 모양을 컴파일하는 NVIDIA 드라이버 쪽으로 본다(확신 약 65 %). 같은 모양(반복 + 이른 반환 여러 번 인라인)이 다른 셰이더에도 생길 수 있어 백엔드끼리 그림을 견주는 GPU 테스트(`CPUAndGPUParticleSimulationsDrawTheSameImage` · `editor/vfxpreview`)가 마지막 그물이다.
  **라이트가 필요한 GPU 효과**(VfxGpuLights 이전의 우회, 지금도 유효): 본체(GPU)와 빛만 맡는 작은 CPU 방출기(빌보드 몇 개, `_light._maxLights` 몇 개, 같은 생성 일정 · 속도 범위)로 나눌 수 있다. 씨앗 규칙이 방출기 번호를 섞어 두 방출기의 입자는 같지 않으므로 빛은 본체의 대표 몇 개를 흉내 낼 뿐이다.
  **기각 · 미룬 것**: 다중 그룹 압축(풀이 수만 개일 때 디스패치 셋 — 그룹마다 생성 · 적분 · 개수, 개수의 접두사 합, 그룹마다 안정 압축)은 지금 방출기 하나를 그룹 하나(256 스레드)가 돌아 풀이 크면 느린 문제의 답이지만 단계마다 셋이라 단계 수 × 3 디스패치가 그룹 하나보다 빨라지는 풀 크기를 잰 뒤에 정한다(`Candidates-graphics.md` `VfxMultiGroupCompaction`).
- **GPU 로 시뮬레이션하는 방출기의 파티클 라이트는 라이트 버퍼의 GPU 구간에 쓰고 점광 · 그림자 없음 · GPU 생산자 전용이다**(2026-10-24, VfxGpuLights L1 ~ L5; 헤드라인은 5-12 `D2-11` 행에 이어). 옛 규칙(빛을 내면 CPU 전용)은 깊이 충돌(GPU 전용)과 한 방출기에 둘 수 없었고 이제 `VfxLightDef::getSupportedTargets` 가 GPU 를 허용한다(Niagara 의 라이트 렌더러는 CPU 시뮬레이션 전용이라 이 엔진의 확장이다). 구현에서 처음 제안(고정 위치 구간 + 그리드 생산자가 카운터를 읽는다)보다 단순해진 곳: (1) 라이트 버퍼는 `[CPU 라이트][GPU 구간][그림자 타일]` 순서이고 GPU 구간은 CPU 라이트 바로 뒤 프레임마다 정해진 위치(`GPULightBuffer::getGpuLightBase`)에서 시작하며 길이는 방출기들이 요청한 슬롯의 합이다(`VfxGPUSimulation::assignLightRanges`, 상한 `kMaxGpuLight` = 프레임 라이트 상한의 4분의 1). 고정 위치로 두면 버퍼가 늘 상한 크기여야 하고 조명 커서의 범위 검사(`lightIndex < g_SwLightCount`)에 구간을 따로 알려야 했다. 셰이더가 보는 라이트 수는 CPU + GPU 구간이고 그림자 타일 번호도 그대로 맞는다(CPU 라이트 수를 구간만큼 줄여 합이 `kMaxFrameLight` 를 넘지 않게 한다). (2) 그리드 생산자(`lightgrid.hlsl`)는 바뀌지 않는다 — 구간의 슬롯은 항상 유효한 `LightData` 이고 입자가 모자란 슬롯과 건너뛴 방출기의 슬롯은 **죽은 라이트**(점광, 반경 0)라 `classifyLight` 에서 범위 밖이고 그리드 없는 경로에서도 감쇠 0 이다(`GPULightBuffer::update` 가 구간을 죽은 라이트로 채워 올려 낡은 빛이 남지 않는다). (3) GPU 라이트는 GPU 생산자(`gv_lightCulling=GPU`, Shipping 은 고정)만 받는다 — CPU 생산자는 구간을 보지 못하므로 `selectGpuLightSlotCount` 가 0 을 주고 오류를 한 번 남긴 뒤 빛을 그리지 않는다. **조용히 GPU 생산자로 바꾸지 않는다**(폴백 금지). (4) 슬롯 i 는 살아 있는 입자 i 의 빛이다(앞의 `_maxLights` 개 — CPU 방출기와 같은 규칙). 색은 입자 색, 세기는 방출기 세기 × 입자 알파, 반경은 방출기 배율을 곱한다. (5) 빛이 있는 방출기는 밀린 단계가 없어도 매 프레임 디스패치한다(월드 좌표로 쓰이고 구간 위치도 프레임마다 바뀐다). 요청이 상한을 넘는 방출기는 빛이 없고 오류를 한 번 남긴다(`prepareFrame`). 시나리오 `vfxgpulights` 의 문턱은 Release 실측으로 정했다(0.009, 잰 값 0.0125 의 70 % 아래; away 를 순간이동 300 프레임 뒤에 찍고 바닥을 밝은 격자로 — 수명 2 초 불똥이 남거나 어두운 바닥의 빛 웅덩이가 화소 비교 하한(6)에 못 닿으면 진다). 슬롯 32 · 128 · 256 에서 컴퓨트 프리패스 GPU 시간은 기본 슬롯의 `RT.Vfx.Simulate` 기준값으로 재고 슬롯 상한(`kMaxGpuLight`)을 줄이는 일은 기준값이 크게 나올 때만 한다(`Candidates-graphics.md` `VfxGpuLightSlotSweep`).
