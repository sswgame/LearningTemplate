# 5-9. 온라인 서비스, 네트워크, 보안

> 질문: 5-9. 온라인 서비스, 네트워크, 보안 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **관심 영역 격자 하나**(2026-10-22): `NetInterestGrid` 는 칸 크기 · 두 반경 · 반경 관계 검사를 격자가 갖는 API 하나이고 MMO 복제기와 클라이언트-서버 키트(정책 `InterestReplicationPolicy`)가 함께 씁니다. `ReplicationServer` 안에 같은 거름을 내장하는 안은 반경 검사가 두 곳에 생겨 버렸습니다(언리얼 Replication Graph 의 격자 노드 방식).
- **DB 와 캐시**(2026-10-06, 사용자 결정): 영속 저장소는 PostgreSQL(서버)과 SQLite(개발용 단독 서버 · 클라이언트 로컬)입니다. 캐시는 RESP 드라이버 하나로 리눅스는 Valkey, 윈도우는 Garnet 입니다. Redis 7.4 이상은 RSAL/SSPL 이라 "오픈소스이고 무료" 조건 밖이고 Redis 8 의 AGPLv3 선택도 그 의무로 택하지 않았습니다. 전용 서버는 윈도우와 리눅스 둘 다 1 급입니다. 남은 일은 [후보 문서](../plans/Candidates-network.md) `D7-5`.
- **네트워크 서비스 계층**(2026-10-06, 사용자 결정): 로그인 · 채팅 · 거래처럼 MMO 가 아니어도 쓰는 서비스는 상태 복제(UDP)와 따로 순서 있는 신뢰 스트림 · 요청-응답 위의 키트로 만듭니다. 공통 기반은 GameFramework 기반 `Online/`(서비스 틀 · 요청 보호 · 신원 · 저장 계약 `IServiceStore`/`IEphemeralStore`/`ILocalStore` · 마이그레이션 · 감사 로그 · 서버 간 버스 · 예약 작업 · 원격 설정 · 관측)이고 목록은 코드가 정본입니다. DB 드라이버(`GF_SQLStore`, `GF_Server_SQLStore`, `GF_Server_CacheStore`)와 기능(`GF_Account` · `GF_Economy` · `GF_Trade` · `GF_Mailbox` · `GF_Chat` · `GF_Social` · `GF_Leaderboard` · `GF_Matchmaking` · `GF_LiveOps` · `GF_Admin` 등)은 키트입니다. 제품 이름은 드라이버와 제공자 폴더에만 쓰고(`CheckProductNames`) 서버 전용 모듈은 클라이언트 Shipping 에 넣지 않습니다. 캐시를 잃어도 영속 데이터는 맞아야 하고(거래의 원본은 영속 트랜잭션) DB 호출은 전용 워커 · 연결 풀 · 비동기 완료로 합니다.
- **네트워크 보안**(2026-10-06, 사용자 결정): 스트림은 TLS 1.3, 게임 UDP 는 연결 수립 때 X25519 로 키를 교환하고 패킷마다 AEAD(AES-GCM 또는 ChaCha20-Poly1305, nonce 는 패킷 번호 + 재전송 방지 창)를 겁니다. 세션 키는 로그인 키트가 발급한 토큰에 묶습니다(Valve GameNetworkingSockets · 언리얼 AESGCM PacketHandler 와 같은 구조). 암호 구현은 직접 짜지 않고 Core 인터페이스(`Network/Security/`) 뒤에 OpenSSL(vcpkg, Apache-2.0, Windows 는 DLL)을 둡니다. 비밀번호 해시는 Argon2id(OWASP 권장 19 MiB · 반복 2)입니다. 인증기 없는 UDP 암호화와 자체 서명 개발용 인증서는 개발 빌드에만 있고 Shipping 서버는 설정 파일의 인증서와 키 경로가 필수입니다.
- **UDP 패킷 압축은 끕니다**(2026-10-06, 사용자 결정). 켜는 규칙은 "15 % 이상 줄고 압축 + 해제가 패킷당 2 us 이하" 인데 `NetCompressionBenchTest`(Release)에서 레지스트리 코덱은 어느 흐름에서도 넘지 못했습니다(스냅숏 평균 1009 B: LZ4 1 %, zstd1 15 % · 11.7 us). 넘는 것은 학습 사전뿐(34 % · 6 us)이라 사전 배포(버전 · id 협상)를 하게 되면 다시 봅니다. 스트림 프레임 압축은 있지만 기본으로 꺼져 있고(`StreamEndpointConfig::_compression`) 받는 쪽은 푼 크기를 본문 상한으로 보고 풀기 전에 거절합니다.
- **후보 재측정과 설정 범위 거절**(2026-10-27): `Candidates-network` 의 측정 절(압축 · UDP 소켓 · 암호화 틱 · epoll · 실제 DB · 파괴 사건 지연)은 코드 일이 아니라 실행이 남아 매니페스트 id 로 둡니다. 코드 일인 `ConfigRangeRejectRemaining` 은 받는 쪽이 거절하는 기존 `ConfigRangeUtil` 방식을 그대로 따라 Uno · Matgo · Poker 설정을 `REFLECT` + `PROPERTY( Min · Max )` 로 옮기고, RunMap · PartyItemSpawner · BrFlightPath · CreatureTown · CitySimulation · HorrorEncounter · BrZone · MonsterStorage 의 `initialize*` 가 범위 밖 설정 · 크기를 `MathUtil::max` · `clamp` 로 맞추던 것을 `[[nodiscard]] bool` 거절로 바꿨습니다.
- **초기값 입력은 맞추지 않고 거절한다**(2026-10-27): Inventory · WorldClock · NavGrid · GridInventory · PlatformTileMap · MoveTimeline · InputMap 타이밍 · SpriteClipPlayable · PlacementTileSurface 등 `initialize`·`set*` 의 `max`·`clamp` 를 `[[nodiscard]] bool` 거절로 바꿨다. 값의 범위를 이미 다른 곳이 지키는 입력(사용자 설정 스키마의 카메라 흔들림, 호출부 속성의 Far Plane, 시네마틱 블렌드 시간)은 `SW_ASSERT` 전제 조건으로 바꿨다. 남긴 것: 컴포넌트의 런타임 세터(`LightComponent::setIntensity` 등 — `PROPERTY` 범위와 같은 포화이고 호출이 널리 퍼져 있다), 오디오 믹서의 음량 포화, 진행 중 값 한계, 0 나눗셈 보호.
- **UDP 일괄 보내기 · 받기와 스트림 지연 장식자**(2026-10-27): `INetTransport` 에 `sendBatch` · `receiveBatch` 를 두고(기본은 단건 반복) 리눅스 UDP 가 `sendmmsg` · `recvmmsg` 로 한 번에 처리합니다. Windows 는 단건 반복이고 RIO 는 리눅스 전후를 본 뒤로 남깁니다. 한 PC 에서 먼 망의 왕복을 재려고 `DelayedStreamTransport`(스트림 전송에 고정 지연을 거는 장식자, UDP 의 `NetEmulationTransport` 에 해당)를 더했습니다.
- **계정**(2026-10-06): 같은 계정으로 다시 로그인하면 새 로그인이 옛 세션을 밀어냅니다. 게스트를 정식 계정에 연동할 때 이미 쓰인 이름이나 플랫폼 계정은 거절합니다(자동 합치기 없음). 탈퇴는 30 일 유예 뒤 지우고 원장과 감사 기록에는 계정 id 만 남깁니다. PC 외부 로그인은 공개 클라이언트와 PKCE(S256)이고 서명은 RS256 과 ES256 만 받습니다. 로컬 저장의 봉인은 장치 키라 실수나 가벼운 변조만 막고 경쟁 데이터의 원본은 서버입니다.
- **경제**(2026-10-06): 거래는 맡김 없이 양쪽이 확정하는 순간 원장 분개 하나로 정산합니다. 경매와 우편 첨부는 맡김 방식입니다. 유상과 무상 재화의 차감 순서는 데이터이고 기본은 무상 먼저입니다. 환불 회수에만 음수 잔액(빚)을 허용하고 빚이 있는 동안 그 재화로 살 수 없습니다(PlayFab Subtract 와 같은 자리). 여러 키트가 한 트랜잭션에 넣는 쓰기(원장 · 우편 넣기 · 제재)는 기반 `Online/` 에 둡니다. 우편 만료: 운영 · 보상 우편은 첨부가 사라지고 플레이어 우편은 보낸 사람에게 돌아가며 보관은 30 일입니다.
- **응답 형식은 하나입니다**(2026-10-06). 업무 결과는 응답 본문의 첫 값이고 오류 코드는 공통 `OnlineError` 만 씁니다(gRPC status 와 본문 구분과 같음). 키트 클라이언트는 요청마다 완료 델리게이트를 받습니다.
- **운영 HTTP 엔드포인트는 기본으로 꺼져 있고(`_opsPort` 0) 켜면 `127.0.0.1` 에 바인딩합니다**(2026-10-06, Nakama 기본값과 같음). 지표와 상태 엔드포인트는 `Engine/Observability` 에 있어 전용 서버가 GameFramework 없이 씁니다.
- **매칭 권한은 모드마다 캐시 임대(10 초) 하나입니다**(2026-10-06). 순위표 점수는 서버만 제출하고 표마다 허용한 경우(`_bClientSubmit`)에만 클라이언트가 제출합니다. 길드는 소셜 키트 안에 있습니다. 부하 봇(`Tools/OnlineLoadBot`)은 Dev 구성에서만 빌드합니다.
- **외부 계정이나 비용이 드는 연동은 계약과 가짜 제공자까지만 둡니다**(2026-10-06). **2026-10-22 바꿈**: 실제 제공자 코드(FCM · 스팀 · 구글 · 애플)를 넣되 자격은 운영 비밀(환경 변수)에서만 읽고 설정이 없으면 그 제공자를 만들지 않으며 만들다 실패하면 서버 기동이 실패합니다(가짜로 대신 뜨지 않음). 확인은 가짜 HTTPS 서버로 하고 APNs(HTTP/2 필요)만 남았습니다([온라인 키트 마감 계획](../plans/OnlineKits.md) 4 절). 금칙어 목록은 테스트용 낱말만 저장소에 둡니다. 서비스 계정 OAuth(JWT 베어러 교환)는 FCM 과 구글 영수증이 함께 써서 기반 계층(`ServiceAccountTokenSource` · `OwnedHTTPClient` · `JSONWebToken`)이 갖습니다(키트끼리 include 하지 않으므로). 푸시 문구는 현지화 키(`title_loc_key`)라 기기가 풀어 언어 토픽을 두지 않고 라이브 이벤트 알림은 `liveops.<지역>`(없으면 `liveops.all`) 토픽으로 한 번 보내며 `liveops_push` 표를 "없어야 한다" 조건으로 써 한 서버만 보냅니다. 구글 환불은 RTDN(Pub/Sub 시설이 따로 필요) 대신 `voidedpurchases` 조회, 스팀은 `GetReport` 조회이며 지난 성공 시각보다 이틀 앞에서 읽고 겹친 주문은 환불 회수가 거래 id 로 한 번만 처리합니다. 애플 영수증은 JWS 의 `x5c` 사슬을 애플 루트까지 확인하고(`INetSecurityProvider::verifyCertificateChain`) 서버 알림(웹훅)은 바깥에서 받는 시설이 필요해 알림 기록 조회로 대신합니다. 애플 로그인의 연동 비밀은 `LoginSecretVault`(AES-256-GCM)로 봉인해서만 저장하고 탈퇴 · 연동 해제가 `login_revoke_queue` 로 옮겨 주기마다 철회하며(실패하면 남아 다시 함) 키가 없는 서버는 비밀을 버립니다(평문 저장 없음). 접속 티켓을 내미는 클라이언트는 실행 인자가 아니라 로그인 뒤 코드가 엽니다(`GameNetSession::makeTicketClientParams` — 서버 주소는 서버 배정이, 티켓은 계정 키트가 주므로). `-gv_netConnectAddress` 는 자격 없이 붙는 길로 남고(티켓 서버는 거절) 거절된 티켓은 세션이 지웁니다.
- **시간 · 바이트 단위와 온라인 · 스트림 상한은 정본 한 곳에 모읍니다**(2026-10-15): `Defines.h` 의 `constant` 와 `OnlineLimit.h`. 재시도 횟수 `kMaxConflictRetry = 4` 는 우연히 같던 값을 한 정책으로 묶은 것이라 서비스별로 다르게 하려면 다시 나눕니다. 스트림 큐 기본값은 보내기 줄과 받기 적체가 독립이라 상수가 둘입니다.
- **중단점에 멈춘 쪽은 패킷 비트로 알리고 상대가 시간 초과를 늘립니다**(2026-10-11, 서버 디버깅 S2). 전역 스위치(언리얼 `-NoTimeouts`)는 양쪽을 미리 맞춰 띄워야 하고 진짜 끊김도 가려서, 디버거가 붙은 쪽만 알리는 연결 단위 신호(`NetDebugHold`, 대기 시한 600초)를 골랐습니다. Shipping 은 알리지도 믿지도 않습니다. 디버거 없이 멈추는 길은 Dev 서버 콘솔 `pause` · `step N` · `resume` 이고 네트워크 스레드는 계속 돌아 연결이 삽니다.
- **키트 서버 조립의 옵션 · 메서드는 표 하나씩입니다**(2026-10-15, C-26 ①). 옵션은 키트가 (이름, 읽어 넣을 칸) 표로 `OnlineServerKitEntry::readOptions` 를 한 번 부르고 모르는 키 · 형식 오류는 키트 이름과 함께 거절합니다. 메서드는 `ENUM( Count = Count )` 열거형 하나가 와이어 번호(`OnlineMethodTable`)와 지표 라벨을 함께 정합니다. 옵션을 리플렉션 구조체로 옮기는 안은 기각 — 같은 키를 여러 번 적는 목록이 있고 키트마다 타입이 달라 고정 스키마로 못 읽습니다.
- **키트가 기반 표에 올리는 것(저장 드라이버, 로컬 저장 바닥, SQL 드라이버)은 정적 등록 객체가 모듈 로드 때 올리고 표는 모듈 언로드 리스너로서 내려가는 이미지의 항목을 지웁니다**(2026-10-17~18, D7-5 · 엔진 분할 E6). 묶기 함수를 부르는 곳이 없어 서버가 늘 기동을 멈췄고 "sqlite" 로컬 저장이 한 번도 오르지 않았습니다 — 등록 객체(`OnlineStoreDriverBinding` · `LocalStoreBackendRegistration` · `SQLDriverRegistration`)가 창구 하나라 "실렸는데 안 올림" · "처음 쓸 때 올림" 을 쓸 수 없습니다. 핫 리로드는 옛 이미지의 언로드를 미루므로 소멸자만으로 내리면 옛 항목이 남거나 새 이미지의 같은 이름을 지워, 표가 `IModuleUnloadListener` 로 이미지 범위의 항목을 지우고 소멸자는 자기 항목만 지웁니다. 표를 서브시스템으로 두는 안은 Shipping 정적 링크에서 등록이 `main` 전에 돌아 범위가 없어 기각했습니다. 저장 드라이버 표(`OnlineStoreDriverTable`)는 칸이 함수 하나라 소멸자가 칸을 무조건 비우던 것을 2026-10-27 에 바로잡았습니다 — 묶기가 `Subscription` 을 돌려주고 그 구독이 풀릴 때 비교 교환으로 자기 함수일 때만 비우며 칸이 언로드 리스너입니다.

FAT · 페이로드 · 스트링 풀은 4096 B 섹터 정렬) 항목 하나를 바꾸면(같은 크기 · +100 B) 항목 칸 밖 바이트와 뒤 항목 위치가 그대로이며 고정 1 MB 청크 4.0 %(None) · 7.4 %(Zstd), 내용 기준 청크(gear 해시, 평균 64 KB) 0.5 ~ 0.6 % 가 달라진다. 항목 하나를 추가 · 삭제하면 해시 순으로 뒤에 오는 항목 37 ~ 45 % 의 오프셋이 섹터 단위로 밀려 고정 1 MB 청크는 46 ~ 56 %, 내용 기준 청크는 0.9 ~ 1.3 % 가 달라진다. **팩 형식을 바꾸지 않는다** — 밀림은 가변 길이 이어 붙임 배치의 성질이고 없애려면 항목마다 청크 단위 패딩이나 슬롯 배치(형식 변경)가 필요하다. 스팀이 내용 기준으로 청크를 자르면(문서로 확인 못 함) 지금 배치로 충분하다. 실제 쿠킹 트리와 스팀의 실제 청크 경계로는 재지 않았다(`Candidates-network.md` `PackSlotLayout`). 낱개 파일 배포(`setAllowLooseFiles`)는 패치가 가리지 못한다. P6(목록 서명 · 팩 해시 확인, 배포 경로)는 스팀 밖 채널이 생길 때 다시 연다 — 서명 키 관리와 배포 경로는 계정 · 비용이 드는 연동이라 사용자 결정이 먼저다(`Candidates-network.md` `PackPatchSigning`). 설치 빌드 번호와 패치 방식의 출처는 위 `base.packbuild.xml` 줄이다.

R1: `MMOReplicator` 의 관심 영역 격자를 Core 부품 `NetInterestGrid`(`Core/Network/Replication`)로 빼 들어오는 · 나가는 반경 히스테리시스와 반경 관계 거절을 한 곳에 둔다. R2: 클라이언트-서버 키트의 정책 `InterestReplicationPolicy` 가 같은 `NetInterestGrid` 규칙을 쓰고 보이는 목록은 게임 스레드가 `updateRelevancy` 로 정하며 스냅샷 워커는 읽기만 한다(자리 없는 엔티티는 모두에게).
