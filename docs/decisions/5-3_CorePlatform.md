# 5-3. Core 와 플랫폼

> 질문: 5-3. Core 와 플랫폼 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **macOS 는 지원 대상이 아닙니다**(2026-10-04). 코드는 지웠고 `CheckTargetMacros` 가 `SW_PLATFORM_MACOS` 를 막습니다. `Vcpkg.cmake` 의 APPLE 분기와 레거시 스탬프 이관, `arm64-osx` · `x64-osx` 트리플릿은 사용자가 정리합니다.

- **파일 존재 술어는 `FileUtil::exists`(무엇이든), `isDirectory`, `isRegularFile` 셋입니다**(2026-10-06). `exists` 는 `std::filesystem::exists` 와 같은 뜻이고 경로 전용 타입(`FilePath`)은 만들지 않습니다. 파일 오류는 그 자리에서 경고하고 `[[nodiscard]] bool` 로 돌려주며, 실패를 알리지 않는 시도는 `FileUtil::tryRemoveFile` 하나입니다(언리얼 `IFileManager::Delete` 의 `bQuiet`).
- **`std::hash<fixed_string>` 은 대소문자를 구분합니다**(2026-10-06). `string` · `wstring` 의 해시와 같은 규칙입니다.
- **`fixed_string` 은 길이 필드 없이 배열 하나만 듭니다**(2026-10-11). `size()` 는 앞 N 칸의 경계 있는 검색이고, 길이를 정하는 연산이 꼬리를 0 으로 채워 바깥이 `data()` 에 널 없이 써도 길이가 맞습니다. 캐시하던 `mutable` 길이는 const `size()` 가 써서 읽기끼리 데이터 레이스였습니다. EASTL · folly 는 길이를 들지만 바깥이 버퍼에 직접 쓰는 계약이 없고, 이 저장소는 ImGui · `formatstring` · Win32 가 `data()` 에 쓰므로 C 배열과 같은 계약을 택했습니다. 넘침은 잘라 경고하고, 잘림이 틀린 값이면 `try_assign` · `try_append` 를 씁니다.
  Release 에서 옛 · 새 바이너리를 번갈아 세 번 돌린 중앙값(`FixedStringBenchTest`): `sizeof` `fixed_string<15>` · `<31>` · `<63>` · `<160>` 이 20 · 36 · 68 · 168 → 16 · 32 · 64 · 161, 같은 타입 대입이 8.4 → 2.0 ns, 나머지(`size()` · 대입 · 비교)는 같고, `clear()` + 짧은 `append` 는 `<64>` 7.9 → 5.5 ns · `<8192>` 10.1 → 68.7 ns 다. `clear()` 가 O(N)이 된 것이 유일한 손해이고 `fixed_string<8192>`(로그 줄 버퍼)를 되풀이해 비우는 호출처는 없습니다. 꼬리를 길이만큼만 채우는 안은 ImGui 가 널 뒤에 남긴 옛 글자를 지우지 못해 기각했습니다.
- **Win32 API 는 W 버전을 이름으로 부르고, A 버전도 막습니다**(2026-10-06). 전역 `UNICODE` 정의는 대상마다 정의가 빠지면 말없이 A 버전으로 돌아가서 택하지 않았습니다. 언리얼 · 유니티 · Godot 모두 Windows 경계에서는 W 버전만 씁니다. X11 창 제목은 `XStoreName` 과 `_NET_WM_NAME` 을 함께 적습니다(SDL2 · GLFW · Godot 과 같음).
- **벽시계는 `WallClock` 하나만 읽습니다**(2026-10-06). 서비스는 현재 시각을 매개변수로 받고, 테스트는 가짜 시각을 넣습니다.
- **문자열 타입은 담는 것으로 고르고, `string` 을 `fixed_string` 으로 일괄 치환하지 않습니다**(2026-10-10). 규칙은 [agents/NamingCpp](../agents/NamingCpp.md#function-names) 에 있습니다. `sw::string` 은 SSO 라 15 바이트까지 힙을 쓰지 않으므로 짧은 이름은 `fixed_string` 의 이득이 없고, 긴 텍스트는 잘리며 스택만 커집니다. 프레임 경로를 지나는 후보는 0 건이었고 프레임 경로의 이름은 `hashed_string` 이나 기존 저장소를 가리키는 `string_view` 로 넘깁니다. `fixed_string` 은 상한이 코드 상수이고 힙이 금지된 경로(크래시 · 로그 · 시그널)나 고정 버퍼가 필요한 곳(ImGui 입력)에만 씁니다. 언리얼도 `FString` 이 기본이고 `TStringBuilder<N>` 은 임시 조립에만 씁니다.
- **Engine 폴더 사이의 작은 고리는 "위층이 아래층 등록표에 등록" 과 "둘을 다 아는 층으로 옮기기" 로 풉니다**(2026-10-11, 엔진 분할 1 단계). 자동화 실행기는 UI 를 모르고 UI 가 단계 · 로딩 화면 시작 차단 조건(`SW_AUTOMATION_START_BLOCKER`)을 올립니다(언리얼 Automation 도 모듈이 등록). `MeshVertexAnimationBaker` 는 `Object/SceneAnimation` 으로, 물리 디버그 선 어댑터는 조립점 `Engine.cpp` 로 옮겨 `Graphics` 가 `Animation` · `Physics` 를 include 하지 않습니다.
- **엔진 내장 에셋 캐시는 기능 폴더가 등록하고 `AssetManager` 는 등록표만 봅니다**(2026-10-11, 엔진 분할). 캐시 .cpp 에 `SW_BUILT_IN_ASSET_CACHE( MaterialCache )` 한 줄을 두고(`Resource/Cache/BuiltInAssetCache.h`), 매니저는 생성자에서 표를 훑어 캐시를 만들고 종류 이름 순으로 올립니다. 타입으로 찾는 창구는 `getAssetCache<T>()` 입니다. 언리얼 서브시스템 · Godot `register_types` · 유니티 `ScriptedImporter` 와 같은 방향입니다. 모듈(게임 · 키트)의 캐시는 표가 아니라 `registerAssetCache` 로 올리고 내립니다.
  **에셋 캐시는 서브시스템으로 만들지 않습니다**(2026-10-14, C-27 ②). 캐시는 경로 → 에셋 표일 뿐 세울 것 · 내릴 것이 없고(`IAssetCache` 에 초기화 · 종료가 없다) 캐시끼리 기대는 순서도 없어 "수명 범위 · 초기화/종료 순서 · 의존이 있는 서비스" 기준에 들지 않습니다. 언리얼도 자산 캐시(`FStreamableManager` 등)를 서브시스템으로 두지 않는 것으로 압니다.
- **캐시는 `CacheStats` 레지스트리에 이름으로 올려 적중 · 실패 · 비우기 · 항목 수를 세고, 새 캐시는 상한과 넘칠 때의 동작을 선언합니다**(2026-10-25). 숫자 없이 캐시를 더하거나 키우지 않으려는 것입니다. 규칙: ① 상한(개수나 바이트)과 **넘칠 때의 동작**을 코드 주석에 선언하고 전체 비우기는 쓰지 않습니다(두 세대 교대나 LRU — 경계 항목이 한꺼번에 다시 계산되는 thrash 방지). ② 무효화 사유를 열거합니다. ③ `Core/Diagnostics/CacheStats.h` 에 이름으로 올리고 조회 자리에서 `recordHit` · `recordMiss`, 비울 때 `recordClear` 를 부릅니다(같은 이름 두 번은 거절).
  별도 레지스트리를 둔 까닭: 캐시가 `IAssetCache` 가 아니어도(텍스트 측정 · 물리 셰이프) 같은 길로 세려면 인터페이스 밖 레지스트리가 필요합니다. 카운터는 `relaxed` 원자 증가 하나(락 · 할당 없음, Shipping 에도 남음)이고 칸은 정적 고정 배열입니다. 보고는 `-gv_profileFrames` 측정 창 끝의 `[CacheStats]` 줄입니다.
  `TextMeasureCache` 는 "4096 개가 차면 전체 비우기" 를 세대 용량 4096 의 두 세대 교대로 바꿨고, 물리 셰이프 캐시(`PhysicsMeshShapeCache`)는 경로가 콘텐츠의 메시 파일 수로 닫혀 있고 씬 교체 때 비우면 재방문마다 다시 읽으므로 상한을 두지 않습니다.
- **`IAssetCache` 는 계측 선언 없이 지을 수 없고, 경로 캐시는 "없음" 도 기억하되 세대가 낡음을 막습니다**(2026-10-25). ① 위 항목의 "`IAssetCache` 를 고치지 않는다" 를 뒤집었습니다. 모든 구현이 계측을 따르게 하는 길은 형식뿐이라(손으로 지키면 새 캐시가 잊는다) 생성자가 `CacheTracking`(`counted( 종류 이름 )` 또는 `uncounted( 사유 )`)을 받습니다. 엔진과 게임 · 키트 모듈은 함께 다시 빌드합니다. ② `ResourcePaths::findLooseFile` 의 캐시는 음성 결과(디스크에 없음)를 같은 표에 둡니다. 낡음은 검색 목록 · 루트 · 마운트가 바뀌면 `clearPathCache` 가 올리는 **배치 세대**(해석 시작 때 잡은 세대가 달라졌으면 저장 불가)와, 이 프로세스가 파일을 만들면 오르는 **`FileUtil::getCreationEpoch`**(음성 칸은 같은 에포크일 때만 믿음)로 막습니다. 다른 프로세스(쿠커 자식 · git)가 만든 파일은 에포크가 못 보므로 그런 파일을 먼저 묻고 나중에 읽는 흐름은 `clearPathCache` 를 부릅니다. ③ `TextMeasureCache` 는 해시 단독 키를 버리고 **해시 후 원문 확인**(`TextMeasureKey`)입니다.
- **씬마다 하나인 기능 서비스는 기능 폴더가 등록하고 `GameObjectManager` 는 레지스트리만 봅니다**(2026-10-12, 엔진 분할 2 단계). 서비스 .cpp 에 `SW_SCENE_SERVICE( SceneNavigation, Navigation )` 한 줄을 두면 매니저가 생성자에서 만들고, 그 줄의 프레임 단계에서 `update` 를, `clear` 에서 `onSceneCleared` 를 부르며, 찾는 창구는 `getSubsystem<T>()` 입니다(`Object/GameObject/Service/ISceneService.h`). 씬 서비스는 서브시스템이고 매니저의 씬 범위(`SubsystemScope`, 부모는 엔진 범위)가 소유합니다(2026-10-14, C-27 ①). 프레임 단계 갱신은 서브시스템 계약 밖의 씬 서비스 몫입니다(초기화 · 종료는 수명이고 갱신은 프레임 단계 표의 자리). 언리얼 `UWorldSubsystem` · `UNavigationSystem` · 유니티 `NavMeshManager` 와 같은 방향이라 `GameObject/` 는 `Component/Navigation` 을 include 하지 않습니다.
- **`AABB` 는 Core 수학 타입입니다**(2026-10-11, 엔진 분할). `Engine/Physics/Collision/AABB.h` → `Core/Math/AABB.h` — 언리얼 `FBox` · 유니티 `Bounds` 도 수학 타입입니다. 레이어를 보는 겹침 질의 `queryOverlaps` 만 물리의 `CollisionLayers.h` 에 남습니다.

- **서브시스템(초기화 · 종료 짝 + 의존 순서)은 Core 의 계약입니다**(2026-10-14). `ISubsystem` · `SubsystemCollection` 은 `Core/Subsystem/`(티어 4 — 로그를 남기지 않아 Log 아래)에 있고, 호스트 종류는 Core 의 비트 마스크(`SubsystemHostMask`)이며 비트의 뜻(클라이언트 · 전용 서버)은 엔진(`EngineSubsystemHost`)이 정합니다. 언리얼은 `ShouldCreateSubsystem` 으로 호스트를 거르고 순서는 `InitializeDependency` 호출로 실행 중에 정합니다. 여기서는 같은 모양에 둘을 더했습니다: 의존은 선언 전체로 위상 정렬하고(동점은 이름 순), 의존 칸은 다른 서브시스템의 이름 상수(`kSubsystemName`)를 가리켜 철자 오류가 컴파일 오류입니다. 모르는 이름 · 순환 · 호스트 어긋남은 `EngineInitSequenceTest` 가 잡습니다. 목록은 로그를 남기지 않고 오류 글을 돌려줍니다(로거도 서브시스템이 될 수 있게). 낮은 층이 높은 층보다 늦게 서야 하면 높은 층이 역방향 의존(`getSubsystemDependents`)으로 적고(목록에 없는 이름은 건너뛰어 선택 의존을 겸함), 정방향 의존은 없으면 오류입니다.
- **서브시스템이 서비스를 소유하고, 컬렉션 하나가 범위 하나입니다**(2026-10-14, 정리 ④). 호스트(엔진 루프 · 테스트 하네스)는 세 범위를 듭니다 — 부트스트랩(진단 도구 · 이름 풀 · 로거 · 명령줄+전역 변수 · 크래시 핸들러 · 리소스 루트 · 메모리 예산 · 정적 저장소), 서비스(이벤트 · 지역화 · 커맨드 스택 · 디버그 도구 · 프로파일러 · 크래시 보고 · 백엔드 레지스트리), 엔진(기동 단계). 아래 범위가 다 선 뒤 위 범위가 서고 위 범위가 다 사라진 뒤 아래 범위가 내려갑니다. 메모리 예산은 추적만 부트스트랩에서 켜고 예산 표는 첫 프레임 끝에 읽습니다(표는 리플렉션으로 읽는데 타입 등록부가 엔진 범위, C-27 ③). 서비스 범위를 엔진 범위로 내리면 소멸자 · 종료 경로의 쓰임을 모두 찾아 의존을 적어야 해서 택하지 않았습니다.
  세 범위는 게임 · 에디터와 같은 `SubsystemScope`(5-8)이고 타입 해시로 찾습니다. 엔진 창구(`engine::getSubsystem<T>()`)의 칸은 소유 · 채우기 없이 **바인딩 때 한 번 찾아 둔 조회 캐시**입니다. 필수 행이 비면 호스트가 서지 않습니다. 서브시스템이 아닌 행은 호스트가 범위에 `bind` 하고, 테스트는 하네스 범위를 부모로 둔 범위에 같은 타입을 넣어 서비스를 갈아 끼웁니다(`test::ScopedEngineServiceOverride`). 하네스는 자기 호스트 비트(`kTestHarness`)로 서서 클라이언트 전용(글꼴 · UI · 텔레메트리 · 플레이어 설정)을 표의 자리로만 둡니다. 모듈(게임 · 에디터)이 받는 호스트 서비스도 범위입니다(`engine::bindModuleServices` — 게임 모듈에는 `GameVisible` 행만). 서비스 id 열거형 · id 배열 표 · 호스트 서비스 목록은 지웠고 찾는 열쇠는 타입 해시 하나입니다. 엔진 루프 · 부트스트랩 · 헤드리스 헤더는 호스트만 include 합니다(`CheckEngineLayers`).
- **서비스 접근은 소유 수명마다 한 창구, 한 어휘다 — `getSubsystem<T>()`(반드시 있음, `T&`) · `findSubsystem<T>()`(없을 수 있음, `T*`)**(2026-10-15, C-28). 엔진은 `engine::`, 씬은 `GameObjectManager::`, 게임은 `game::`(게임 범위 → 호스트), 에디터는 `editor::`(에디터 범위 → 호스트)이고 소유 객체(`EditorContext` · `GameInstanceBase`)의 멤버도 같은 두 이름입니다. 이름 붙은 엔진 접근자 서른 개 · `getBoundEngineServices` · `getService<T>` · `getSceneService<T>` · `isServiceBound<T>` 는 지웠습니다. 언리얼이 범위 객체마다 `GetSubsystem<T>()` 를 두는 것과 같고, 유니티 서비스 로케이터 · Godot `Engine::get_singleton( "이름" )` 의 이름 조회는 철자 오류가 실행 때에야 드러나 택하지 않았습니다.
  확장 셋: ① 엔진 칸은 바인딩 때 한 번 찾고 템플릿이 칸 색인을 컴파일 때 고릅니다 — 목록 밖 타입이나 빌 수 있는 행(`SW_ENGINE_SERVICE_OPT`)에 `getSubsystem` 을 쓰면 `static_assert` 입니다. ② `CheckServiceAccess` 가 옛 창구와 새 `static getInstance()` 를 막습니다(상태 없는 코덱 · 드라이버 · 링크 때 등록 표만 예외 표에 이유와 함께). ③ 목은 범위로 넣습니다(`test::ScopedEngineServiceOverride` · `game::ScopedGameScope` · `editor::ScopedEditorScope`). 호스트가 게임 서비스를 묶지 않은 실행(쿠커 · 테스트 하네스)에서 게임 창구는 엔진 범위를 봅니다(`Engine/Common/EngineScope.h`). ④ 이름 검사의 틈(`.cpp` 익명 접근자, 네임스페이스 수준 변수, `static inline` 멤버, `thread_local`, `ScopeOwned` 로 감싼 전역 칸)은 모양으로 막습니다: `CheckMutableStatics` 가 정적 저장 기간의 가변 변수를 장소 · 이름에 상관없이 위반으로 봅니다(예외는 `rules/CheckMutableStatics.toml` 에 `<파일>:<변수>` 와 이유). 신규 위반부터 막고 기존은 이전 대기 표(`[pending]`, 파일별 위반 총수 상한)로 줄여 갑니다(사용자 결정, 2026-10-25) — 표는 늘지 못하고 줄었으면 `--regen-baseline` 으로 줄여야 통과합니다.
  **단일체 게이트는 이름이 아니라 모양을 봅니다**(2026-10-25): 참조를 돌려주는 인자 없는 정적 접근자와 함수 안 정적 지역을 돌려주는 정의는 이름이 `instance()` · `shared()` 여도 잡고, 이름을 보는 것은 모양이 팩토리와 같은 포인터 · 스마트 포인터 반환뿐입니다. `.cpp` 안 익명 · `…Internal` 이름공간의 정적 지역 접근자와 헤더 선언만 있는 바깥 연결 자유 함수는 게이트가 못 보는 틈입니다(현재 0건).
- **`.cpp` 안에서 함수 안 `static` 지역을 참조로 돌려주는 가변 상태 접근자(`static T& getXxx() { static T s; return s; }`)는 쓰지 않고 소유 구조로 옮깁니다**(2026-10-25, Engine · Core · App · GameFramework · 에디터). `CheckServiceAccess` 가 헤더만 훑어 `.cpp` 에 숨은 전역 가변 상태가 남아 있었고(에디터 둘이나 병렬 테스트에서 섞이고 모듈 재로드 때 값이 남거나 사라지는 때가 정해지지 않음), 근본 원인은 "숨은 상태를 낳는 모양을 쓸 수 있다" 였으므로 접근자를 없애고 상태마다 소유자를 정했습니다. 소유자는 모양으로 고릅니다.
  ① **소유 객체가 있으면 그 멤버**: 시나리오 시작 백엔드는 `RHIBackendSwitcher`, enum 글 파서는 `GlobalVariableManager`. ② **새 엔진 서비스**: 스크린샷 요청 우편함 `ScreenshotMailbox`(선택 행 — 전용 서버에는 없고 정적 창구는 서비스가 없으면 요청을 오류로 알리고 버림). ③ **엔진 수명 범위(`ScopeOwned<T>`)**: 정적 함수가 부르는 캐시 · 표(메시 캐시 상태, 물리 메시 셰이프, 공유 에셋 표 `SharedAssetCache<T>`, 내장 도형 · 스프라이트 텍스처 캐시, 셰이더 리플렉션 매니페스트, 게임 데이터 캐시와 레지스트리, 일정 시스템 목록 등). 엔진이 내려가면 저장소째 사라지고 범위가 닫힌 뒤의 접근은 `getOrCreate` 가 단언합니다. ④ **"한 번만 알림" + 횟수**: 서버 버스 · 푸시 릴레이의 거절은 `LogOnce`(`tryClaim`)가 세고 한 번만 알립니다. 호출 지점마다 한 번이면 되는 줄은 `SW_LOG_ERROR_ONCE` · `SW_LOG_WARNING_ONCE`(키는 파일 × 줄). ⑤ **링크 때 등록 표**: `TickBatchRegistry` 는 등록 객체(`TickBatchRegistration<T>`)의 멤버를 침입 연결 목록으로 잇습니다(엔진 범위가 서기 전에 올라가고 엔진을 다시 세워도 남아야 함). ⑥ **호출 사슬 상태는 스레드가 소유**: 프리팹 펼치기의 순환 검사 스택은 `PrefabThreadChain` 한 `thread_local` 입니다. ⑦ **Core 의 아래 층 · 핫 경로 칸은 상수 초기화되는 이름공간 변수 하나**(접근자 없음): 단언 대화상자 상태, 모듈 위치 바꾸기, 네트워크 흐름 링, 시나리오 사본 횟수, 고른 게임 이름.
  **옮기지 않은 곳**: `RHIRenderResource` 의 살아 있는 리소스 표(엔진보다 오래 사는 정적 리소스가 있음 — 접근자를 둘에서 하나로 줄임), 링크 때 등록 표(`AssetTypeRegistry` · `DevCommandRegistry` · `DebugHUDRegistry` · `BehaviorTaskRegistry` 계열은 등록 목록 통합 작업의 몫), 크래시 경로 저장소, 카메라 흔들림 구독 델리게이트, 범위가 닫힌 뒤 빈 값을 내주는 폴백 정적(`Render2DSettings` · `ReflectionValidation`). `CheckServiceAccess` 의 모양 검사는 헤더만 보며, `.cpp` 로 넓히면 남은 같은 모양이 모두 실패하므로 그 영역을 옮긴 뒤에 넓힙니다.
  에디터 영역의 소유자 규칙: ① 값을 한 패널만 쓰면 패널 멤버이고 탐침은 `findPanel<T>()` 로 읽습니다. ② 이미 있는 서브시스템이 주인이면 그 멤버입니다(DPI 배율 → `EditorTheme`, 텍스처 캐시 → `MeshModifierSession`). ③ 한 파일 안에서만 쓰는 값은 **에디터 범위의 상태 저장소** `EditorStateStore` 가 소유합니다(`getEditorState<T>()` 가 타입마다 값 하나를 처음 물을 때 `T{}` 로 만들고, `EditorContext` 가 맨 먼저 만들어 함께 사라지며, 테스트는 `ScopedEditorStateService` 로 자기 몫을 건다). **EditorModule 안의 코드만 씁니다** — 확장 모듈은 내려갈 때 vtable 이 사라지므로 패널 멤버나 `SW_EDITOR_SUBSYSTEM` 을 씁니다. 상태 타입은 그 번역 단위의 `XxxInternal` 안에 둡니다. `EditorUIContext::getCurrent()` 는 ImGui · ImPlot 의 현재 컨텍스트를 묻습니다.
  이어서: (가) 환경설정 섹션 값은 등록자 `EditorSettingsRegistrar<T>` 가 멤버로 듭니다(모듈이 내려가면 값과 '파일 값 입힘' 표시가 함께 사라짐). 등록되지 않은 섹션을 읽으면 기본값 대신 멈추고(`getSettingsRegistration`) 고칠 때는 `editPreferences<T>()` 입니다. (나) 프로세스에 하나씩 둔 에디터 · 플러그인 재사용 버퍼는 소유 상태 구조체로 옮겼고, 저장소 없이 도는 테스트가 있는 기하 유틸은 중간 버퍼를 인자로 받습니다. (다) `thread_local` 이 소유자인 상태는 짝을 맞출 대상이 스레드가 아니면 옮깁니다(`EditorChrome` 스택은 상태 저장소로, `makeIconLabel` 은 값으로 돌려줌, X11 백엔드의 활성 포인터는 ImGui `BackendPlatformUserData`). (라) Internal 의 가변 `inline static` 은 쓰는 객체의 멤버나 번역 단위 `State` 로 옮겼습니다. 프로세스 단위가 성질인 값은 옮기지 않습니다 — ID 발급기 · 파일 열기 계수기, 디스크 마운트 · 경로 캐시(`ResourcePaths`), 쿠커 해시 · 스탬프 캐시, RenderDoc API 핸들, 모듈 리로드 세대(`ModuleShadowCopy`), `ScopeOwned` 캐시들.
- **스레드는 `sw::thread`, 백그라운드 잡의 상태는 한 번에 읽는다**(C-24). `Source/` 에서 `std::thread` 를 직접 만들면 `CheckStdThread` 가 막습니다(예외: 래퍼 자신 · 크래시 재현 테스트, `Test/` 의 쓰고 버리는 스레드). `sw::thread` 는 합류 대기를 잠금 관찰자에 알려 `join` 순환을 교착 검출기가 보게 하고, 로더 락 안의 `join`(`DllMain` · 모듈 정적 소멸자)은 단언합니다. `EditorBackgroundTask::take` 는 결과 유무와 대기 여부를 같은 락 안에서 읽어 `EditorTaskPoll`(`Idle` · `Running` · `Ready`) 하나로 돌려줍니다 — `take` 가 비었다고 `isPending` 을 따로 읽으면 그 사이 끝난 결과를 새 요청이 버립니다(E-9 Quick Open 결함). 요청 여부는 `take` 의 반환값으로 정하고 `isPending` 은 화면 표시용입니다. 풀 핸들(`TaskHandle` · `TaskStageHandle`)의 수명 순서는 참조 계수로 닫혀 있습니다(매니저가 사라질 때 남은 핸들이 풀을 이어받음, `TaskNodePool::detachOwner`).
- **엔진 루프 클래스는 `Engine` 이고 서비스 네임스페이스 `engine` 은 그대로 둡니다**(2026-10-15, 정리 ⑥). 클래스(`sw::Engine`)와 네임스페이스(`sw::engine`)는 규칙(타입 PascalCase · 네임스페이스 소문자)이 구분합니다. 네임스페이스는 `engine::` 가 엔진 범위 창구의 수명 이름이라(`game::` · `editor::` 와 짝) 바꿔도 얻을 것이 적습니다. 클래스를 `EngineLoop` 로 두지 않는 까닭은 이 객체가 루프만이 아니라 부트스트랩 · 서비스 · 엔진 세 범위와 프레임 관찰자 · 종료 코드를 소유하는 호스트의 본체이기 때문입니다(언리얼 `UEngine` 도 같은 모양으로 압니다). 별칭 · 옛 이름은 두지 않습니다.
- **호스트 범위가 엔진 범위의 부모다 — 엔진 앞에 서서 뒤에 사라지고, 호스트가 엔진에 내주는 것을 든다**(2026-10-15, 정리 ⑥). App · ServerApp 이 `SubsystemScope _host` 를 `_engine` 보다 앞에 두고 `Engine::initialize` 의 마지막 인자로 넘겨 부트스트랩 범위의 부모로 잇습니다(사슬: 엔진 → 서비스 → 부트스트랩 → 호스트). 거는 것은 둘입니다.
  ① **모듈 이미지 창구**(`ModuleImageHostSubsystem`, `IModuleImageHost`): 엔진의 `ModuleTypes` 단계가 `loadTypeProviders` 를, `ModuleImages` 종료가 `onScenesReleased` 를 부모로 올라가며 찾아 부릅니다. 옛 `Engine::setModuleTypeLoader` · `setOnScenesReleased` 와 델리게이트 멤버 둘은 지웠습니다. DLL 언로드는 그대로 씬 뒤 · 서비스 앞에서 일어납니다(엔진 범위 종료는 모든 서브시스템에 `stopSubsystem` 을 먼저 돌린 뒤 `shutdownSubsystem` 을 도는 두 패스).
