# 5-3. Core 와 플랫폼

> 질문: 5-3. Core 와 플랫폼 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **macOS 는 지원 대상이 아닙니다**(2026-10-04). 코드는 지웠고 `CheckTargetMacros` 가 막습니다. `Vcpkg.cmake` 의 APPLE 분기와 osx 트리플릿은 사용자가 정리합니다.
- **파일 존재 술어는 `FileUtil::exists`(무엇이든) · `isDirectory` · `isRegularFile` 셋입니다**(2026-10-06). 경로 전용 타입(`FilePath`)은 만들지 않습니다. 파일 오류는 그 자리에서 경고하고 `[[nodiscard]] bool` 로 돌려주며, 실패를 알리지 않는 시도는 `FileUtil::tryRemoveFile` 하나입니다(언리얼 `IFileManager::Delete` 의 `bQuiet`). 2026-10-27 부터 `ensure*Directory*` · `collectFiles` · `collectFolders` · `makeRelativePath` · `makeAbsolutePath` · `getFileStamp` 도 `[[nodiscard]]` 이고(실패 동사 목록에 `ensure` · `collect` 등을 더해 `CheckFallibleNodiscard` 가 새 선언도 막는다), 순회가 도중에 멈추면 `forEachDirectoryEntry` · `collectFiles` 가 경로를 알리고 false 입니다 — 부분 목록을 전부로 믿은 쿠커가 구울 것 · 지울 것을 빠뜨렸습니다. 폴더가 없어 빈 목록이 맞는 호출만 `(void)` 와 이유를 답니다.
- **`std::hash<fixed_string>` 은 대소문자를 구분합니다**(2026-10-06). `string` 과 같은 규칙입니다.
- **`fixed_string` 은 길이 필드 없이 배열 하나만 듭니다**(2026-10-11). 길이를 정하는 연산이 꼬리를 0 으로 채워 바깥이 `data()` 에 널 없이 써도 길이가 맞습니다(ImGui · `formatstring` · Win32 가 `data()` 에 쓰므로 C 배열과 같은 계약. EASTL · folly 는 길이를 들지만 이 계약이 없음). 캐시하던 `mutable` 길이는 const `size()` 가 써서 데이터 레이스였습니다. 넘침은 잘라 경고하고 잘림이 틀린 값이면 `try_assign` · `try_append` 를 씁니다. 대입이 8.4 → 2.0 ns, `sizeof` 가 줄고 `clear()` 만 O(N) 이 됐습니다(`fixed_string<8192>` 를 되풀이해 비우는 호출처 없음). 꼬리를 길이만큼만 채우는 안은 ImGui 가 널 뒤에 남긴 옛 글자를 못 지워 기각. [측정: Release `FixedStringBenchTest` 번갈아 3 회 중앙값 · 2026-10-11]
- **Win32 API 는 W 버전을 이름으로 부르고 A 버전도 막습니다**(2026-10-06). 전역 `UNICODE` 정의는 대상마다 빠지면 말없이 A 버전으로 돌아가 택하지 않았습니다(언리얼 · 유니티 · Godot 모두 W 만). X11 창 제목은 `XStoreName` 과 `_NET_WM_NAME` 을 함께 적습니다.
- **벽시계는 `WallClock` 하나만 읽습니다**(2026-10-06). 서비스는 현재 시각을 매개변수로 받고 테스트는 가짜 시각을 넣습니다.
- **문자열 타입은 담는 것으로 고르고 `string` 을 `fixed_string` 으로 일괄 치환하지 않습니다**(2026-10-10, 규칙은 [agents/NamingCpp](../agents/NamingCpp.md#function-names)). `sw::string` 은 SSO 라 짧은 이름은 `fixed_string` 의 이득이 없고 긴 텍스트는 잘립니다. 프레임 경로를 지나는 후보는 0 건이었고 프레임 경로의 이름은 `hashed_string` 이나 `string_view` 로 넘깁니다. `fixed_string` 은 상한이 코드 상수이고 힙이 금지된 경로(크래시 · 로그 · 시그널)나 고정 버퍼가 필요한 곳(ImGui 입력)에만 씁니다.
- **Engine 폴더 사이의 작은 고리는 "위층이 아래층 등록표에 등록" 과 "둘을 다 아는 층으로 옮기기" 로 풉니다**(2026-10-11). 자동화 실행기는 UI 를 모르고 UI 가 시작 차단 조건(`SW_AUTOMATION_START_BLOCKER`)을 올리며(언리얼 Automation 도 모듈이 등록), `MeshVertexAnimationBaker` 는 `Object/SceneAnimation` 으로, 물리 디버그 선 어댑터는 `Engine.cpp` 로 옮겨 `Graphics` 가 `Animation` · `Physics` 를 include 하지 않습니다.
- **엔진 내장 에셋 캐시는 기능 폴더가 등록하고 `AssetManager` 는 등록표만 봅니다**(2026-10-11). 캐시 .cpp 에 `SW_BUILT_IN_ASSET_CACHE( MaterialCache )` 한 줄을 두고 매니저가 표를 훑어 만듭니다(언리얼 서브시스템 · Godot `register_types` · 유니티 `ScriptedImporter` 방향). 타입으로 찾는 창구는 `getAssetCache<T>()` 이고 모듈의 캐시는 `registerAssetCache` 로 올리고 내립니다. **에셋 캐시는 서브시스템으로 만들지 않습니다**(C-27 ②) — 세울 것 · 내릴 것 · 서로 기대는 순서가 없는 값 저장소이고 언리얼도 그렇습니다.
- **캐시는 `CacheStats` 에 이름으로 올려 적중 · 실패 · 비우기 · 항목 수를 세고 새 캐시는 상한과 넘칠 때의 동작을 선언합니다**(2026-10-25). 숫자 없이 캐시를 키우지 않으려는 것입니다. 규칙: ① 상한과 **넘칠 때의 동작**을 코드 주석에 선언하고 전체 비우기는 쓰지 않습니다(두 세대 교대나 LRU — thrash 방지). ② 무효화 사유를 열거합니다. ③ `Core/Diagnostics/CacheStats.h` 에 올리고 `recordHit` · `recordMiss` · `recordClear` 를 부릅니다. 보고는 `-gv_profileFrames` 창 끝의 `[CacheStats]` 줄입니다. `IAssetCache` 는 생성자가 `CacheTracking`(`counted( 종류 )` 또는 `uncounted( 사유 )`)을 받아 계측 선언 없이 지을 수 없습니다(형식으로 막음, 엔진과 모듈은 함께 다시 빌드). `ResourcePaths::findLooseFile` 캐시는 "없음" 도 기억하되 낡음을 배치 세대(`clearPathCache`)와 `FileUtil::getCreationEpoch`(이 프로세스가 만든 파일)로 막습니다. 다른 프로세스가 만든 파일을 먼저 묻고 나중에 읽는 흐름은 `clearPathCache` 를 부릅니다. `TextMeasureCache` 는 두 세대 교대이고 해시 후 원문 확인 키입니다.
- **씬마다 하나인 기능 서비스는 기능 폴더가 등록하고 `GameObjectManager` 는 레지스트리만 봅니다**(2026-10-12). 서비스 .cpp 에 `SW_SCENE_SERVICE( SceneNavigation, Navigation )` 한 줄을 두면 매니저가 만들고 프레임 단계에서 `update` 를, `clear` 에서 `onSceneCleared` 를 부르며 찾는 창구는 `getSubsystem<T>()` 입니다. 씬 서비스는 서브시스템이고 매니저의 씬 범위가 소유합니다(C-27 ①, 언리얼 `UWorldSubsystem` · `UNavigationSystem` 과 같은 방향). 프레임 단계 갱신은 서브시스템 계약 밖입니다.
- **`AABB` 는 Core 수학 타입입니다**(2026-10-11). 언리얼 `FBox` · 유니티 `Bounds` 도 수학 타입이고 레이어를 보는 `queryOverlaps` 만 물리에 남습니다.

- **서브시스템(초기화 · 종료 짝 + 의존 순서)은 Core 의 계약입니다**(2026-10-14). `ISubsystem` · `SubsystemCollection` 은 `Core/Subsystem/`, 호스트 종류는 Core 의 비트 마스크이고 비트의 뜻은 엔진이 정합니다. 언리얼은 `ShouldCreateSubsystem` 으로 호스트를 거르고 순서를 `InitializeDependency` 로 실행 중에 정하는데, 여기서는 의존 선언 전체를 위상 정렬(동점은 이름 순)하고 의존 칸이 이름 상수(`kSubsystemName`)를 가리켜 철자 오류가 컴파일 오류입니다. 낮은 층이 높은 층보다 늦게 서야 하면 높은 층이 역방향 의존(`getSubsystemDependents`)으로 적고 정방향 의존은 없으면 오류입니다. 목록은 로그를 남기지 않고 오류 글을 돌려줍니다(로거도 서브시스템이 될 수 있게).
- **컬렉션 하나가 범위 하나이고 호스트는 세 범위를 듭니다**(2026-10-14, 정리 ④): 부트스트랩(진단 · 이름 풀 · 로거 · 명령줄 · 크래시 핸들러 · 리소스 루트 · 메모리 예산) → 서비스(이벤트 · 지역화 · 프로파일러 · 크래시 보고 · 백엔드 레지스트리 등) → 엔진(기동 단계). 아래가 다 선 뒤 위가 서고 위가 다 사라진 뒤 아래가 내려갑니다. 서비스 범위를 엔진 범위로 내리면 소멸자 · 종료 경로의 쓰임을 모두 찾아 의존을 적어야 해서 택하지 않았습니다. 엔진 창구(`engine::getSubsystem<T>()`)의 칸은 바인딩 때 한 번 찾아 둔 조회 캐시이고 필수 행이 비면 호스트가 서지 않습니다. 테스트는 부모를 하네스 범위로 둔 범위에 같은 타입을 넣어 서비스를 갈아 끼웁니다(`test::ScopedEngineServiceOverride`). 호스트가 모듈에 주는 서비스도 범위(`engine::bindModuleServices` — 게임 모듈에는 `GameVisible` 행만)이고 서비스 id 열거형 · id 배열 표는 지웠습니다. 서브시스템 목록은 `Engine/EngineSubsystemSet.cpp` 한 곳입니다.
- **서비스 접근은 소유 수명마다 한 창구 한 어휘 — `getSubsystem<T>()`(반드시 있음 `T&`) · `findSubsystem<T>()`(없을 수 있음 `T*`)**(2026-10-15, C-28). 엔진 `engine::`, 씬 `GameObjectManager::`, 게임 `game::`, 에디터 `editor::` 이고 이름 붙은 엔진 접근자 서른 개 · `getService<T>` 등은 지웠습니다. 언리얼이 범위마다 `GetSubsystem<T>()` 를 두는 것과 같고 유니티 서비스 로케이터 · Godot `get_singleton( "이름" )` 의 이름 조회는 철자 오류가 실행 때 드러나 택하지 않았습니다. 엔진 칸은 템플릿이 컴파일 때 색인을 고르고 목록 밖 타입에 `getSubsystem` 을 쓰면 `static_assert` 입니다. 게임 서비스를 묶지 않은 실행(쿠커 · 테스트 하네스)에서 `game::` 창구는 엔진 범위를 봅니다. 숨은 전역 가변 상태는 게이트가 막습니다: `CheckServiceAccess`(옛 창구 · `static getInstance()` · 참조를 돌려주는 정적 접근자 — 이름이 아니라 모양을 봄)와 `CheckMutableStatics`(정적 저장 기간의 가변 변수, 예외는 `rules/CheckMutableStatics.toml` 에 이유와 함께, 신규부터 막고 기존은 `[pending]` 상한 래칫으로 줄임 — 사용자 결정 2026-10-25).
- **`.cpp` 안의 `static T& getXxx() { static T s; return s; }` 가변 상태 접근자는 쓰지 않고 소유자를 둡니다**(2026-10-25). 에디터 둘이나 병렬 테스트에서 섞이고 모듈 재로드 때 값 수명이 정해지지 않았습니다. 소유자는 모양으로 고릅니다: 소유 객체가 있으면 그 멤버, 선택 서비스(`ScreenshotMailbox`), 엔진 수명 범위(`ScopeOwned<T>` — 정적 함수가 부르는 캐시 · 표), "한 번만 알림"(`LogOnce`, 호출 지점마다 한 번은 `SW_LOG_*_ONCE`), 링크 때 등록 표(침입 연결 목록), 호출 사슬 상태(`thread_local` 한 변수), Core 아래 층 · 핫 경로 칸(상수 초기화 이름공간 변수 하나). 옮기지 않은 곳: 엔진보다 오래 사는 `RHIRenderResource` 표, 링크 때 등록 표(`AssetTypeRegistry` 등 — 등록 목록 통합 작업의 몫), 크래시 경로 저장소, 폴백 정적. 에디터에서는 값을 한 패널만 쓰면 패널 멤버, 이미 있는 서브시스템이 주인이면 그 멤버, 한 파일 안에서만 쓰면 **에디터 범위의 상태 저장소** `getEditorState<T>()`(`EditorContext` 가 만들고 함께 사라짐, 테스트는 `ScopedEditorStateService`)입니다. 상태 저장소는 EditorModule 안에서만 쓰고 확장 모듈은 패널 멤버나 `SW_EDITOR_SUBSYSTEM` 을 씁니다(모듈이 내려가면 vtable 이 사라짐). 환경설정 섹션 값은 등록자 `EditorSettingsRegistrar<T>` 가 들고 등록 안 된 섹션을 읽으면 기본값 대신 멈춥니다(`editPreferences<T>()`). 프로세스 단위가 성질인 값(ID 발급기, `ResourcePaths` 마운트 · 경로 캐시, 쿠커 해시 · 스탬프 캐시, RenderDoc 핸들, 모듈 리로드 세대)은 옮기지 않습니다.
- **스레드는 `sw::thread`, 백그라운드 잡의 상태는 한 번에 읽는다**(C-24). `std::thread` 직접 생성은 `CheckStdThread` 가 막고 `sw::thread` 는 합류 대기를 교착 검출기에 알리며 로더 락 안의 `join` 은 단언합니다. `EditorBackgroundTask::take` 는 결과 유무와 대기 여부를 한 락 안에서 `EditorTaskPoll`(`Idle` · `Running` · `Ready`)로 돌려줍니다 — `take` 가 비었다고 `isPending` 을 따로 읽으면 그 사이 끝난 결과를 새 요청이 버립니다(Quick Open 결함). 태스크 풀 핸들의 수명은 참조 계수로 닫혀 있습니다(`TaskNodePool::detachOwner`).
- **엔진 루프 클래스는 `Engine` 이고 서비스 네임스페이스 `engine` 은 그대로 둡니다**(2026-10-15). 규칙(타입 PascalCase · 네임스페이스 소문자)이 둘을 구분하고 `engine::` 은 `game::` · `editor::` 와 짝인 수명 이름입니다. 이 객체는 루프만이 아니라 세 범위 · 프레임 관찰자 · 종료 코드를 소유하는 호스트 본체라 `EngineLoop` 가 아닙니다(언리얼 `UEngine` 도 같음). 별칭은 두지 않습니다.
- **호스트 범위가 엔진 범위의 부모입니다**(2026-10-15). App · ServerApp 이 `SubsystemScope _host` 를 `_engine` 앞에 두고 부트스트랩 범위의 부모로 잇습니다(엔진 → 서비스 → 부트스트랩 → 호스트). 거는 것: ① **모듈 이미지 창구**(`ModuleImageHostSubsystem`) — 엔진의 `ModuleTypes` 단계가 `loadTypeProviders` 를, `ModuleImages` 종료가 `onScenesReleased` 를 부모로 올라가며 찾아 부릅니다(옛 `Engine::setModuleTypeLoader` 등은 지움). ② **자동화 구동기**(`AutomationSession`, App 만) — 엔진 서비스를 빌려 써서 엔진 종료 앞에서 내려야 하므로 `shutdownDependentsOf( 창구 )` 로 먼저 내립니다. `Dev` 호스트 비트는 두지 않았습니다(자동화는 Shipping 에서도 쓰므로 `#if` 로 감쌀 개발 도구가 아님). 테스트 하네스는 호스트 범위를 두지 않습니다.
- **압축 해제의 원본 크기 상한은 코덱이 낸다 — `ICompressionCodec::decompressBound` 는 순수 가상이다**(2026-10-17, B-5). 야간 퍼저가 81 바이트 입력(RLE · 원본 620 MB)으로 타임아웃을 냈습니다 — 헤더 값을 압축 크기와 견주지 않고 절대 상한(1 GiB)만 봐서 620 MB 를 할당했습니다. 최대 팽창률이 포맷마다 다르므로(RLE 65 · LZ4 255 · Deflate 1032 · Zstd 32768배) 코덱이 답하고 `CompressionStream` 이 할당 전에 견줍니다. - **외부 프로세스는 `ProcessCommand{ 실행 파일, 인자 목록 }` 으로만 띄우고 셸을 거치지 않습니다**(2026-10-27). 글 하나를 받던 `Process::launch` · `execute` · `launchDetached` 를 지웠습니다. POSIX 는 PATH 를 부모에서 찾아 `execv`(fork 뒤 async-signal-safe), Windows 는 `ProcessCommand::toCommandLine` 한 곳이 CommandLineToArgvW 규칙으로 인용합니다(언리얼 `FPlatformProcess::CreateProc` 은 글 하나를 받지만 POSIX 는 셸 없이 나눕니다. Godot `OS::create_process( path, List<String> args )` · Qt `QProcess` · 파이썬 `subprocess` 와 같은 방향). 인자 규칙이 다른 `explorer.exe /select,` · `rundll32 url.dll,FileProtocolHandler` 는 띄우지 않고 셸 API 로 바꿨습니다 — `Process::showInFileManager`(`SHOpenFolderAndSelectItems`) · `Process::launchURL`(`ShellExecuteW`, 언리얼 `LaunchURL` 과 같음). 날 명령줄 예외 칸은 없습니다. 사람이 적은 인자 줄(설정의 추가 인자 · IDE 열기 템플릿)은 `splitArgumentLine` 으로 먼저 나눈 뒤 값을 채워 값이 인자를 늘리지 못합니다. 남은 틈: 부르는 쪽이 `cmd.exe /c` 를 고르면 `%` 펼치기는 막지 못합니다.
- **바이트 직렬화의 정본은 `Core/Serialization` 입니다**(2026-10-27). 바이트 순서는 `LittleEndianUtil`(Container, 정수 · `float32`), 위치와 범위 검사는 `ByteWriter` · `ByteReader`(넘치면 0 과 `hasOverflowed`, `BitReader` 와 같은 규칙), 비트 단위 패킷은 `BitStream` 이 맡고 `BitStream` 은 Network 밖으로 내렸습니다. 파일 형식마다 두던 `readUint32` · `writeFloat32` 사본(프로브 둘 · 메시 · 파괴 기록 · 리플렉션 바이너리의 호스트 순서 `memcpy`)은 지웠습니다(언리얼 `FArchive` · `FMemoryReader`, Godot `StreamPeerBuffer` 도 한 타입).
- **고정 용량 기록은 `RingBuffer<T, N>`(2 의 거듭제곱, 가득 차면 가장 오래된 값을 덮어씀, 오래된 것부터 순회), 다시 쓰지 않는 id 는 `IDAllocator<TID>`(0 무효, 감기면 단언, `enum class` id 로 종류를 가름)입니다**(2026-10-27). `TickRingBuffer` 는 이 위로 올리지 않습니다 — 키(틱)를 슬롯마다 적고 용량이 실행 중에 정해지는 조회 표라 FIFO 링과 모양이 다릅니다(언리얼 `TCircularBuffer` 와 `FRepChangelistState` 도 따로). `ConcurrentQueue` 의 `push` · `pop` · `isEmpty` 별칭은 지우고 `enqueue` · `dequeue` · `empty` 하나만 둡니다.
- **기다리는 일을 전용 스레드 하나에서 받은 순서대로 돌리는 큐는 `DedicatedWorker<TJob>`(Core/Task) 하나입니다**(2026-10-27). 이름 있는 스레드 · 막히는 꺼내기 · 정지 계약(`stop` 은 받은 일을 버리지 않고 `bStopping` 으로 모두 처리 함수에 넘긴 뒤 합류, 그 뒤 `submit` 은 false)이고 버릴지는 처리 함수가 정합니다(언리얼 `FRunnable` + `TQueue`). `AsyncLogSink` 는 옮기지 않습니다 — 줄마다 뮤텍스 없이 넣는 lock-free 큐와 크래시 경로의 잠금 없는 비우기(`flushForCrash`)가 계약이라 막히는 큐로 바꾸면 그 둘을 잃습니다. `AsyncFileIOQueue` 도 옮기지 않습니다 — 우선순위 · 동시 진행 상한 · 여러 백엔드가 함께 꺼내는 스케줄러라 FIFO 전용 스레드가 아닙니다.
- **고정 스텝 누적기의 정본은 `Core/Time/FixedStepTimer` 하나입니다**(2026-10-27). 게임 시뮬레이션과 씬 물리가 같이 쓰고(물리는 프레임당 상한을 스텝 수 × 스텝 길이로 넘긴다), 보간 비 `getAlpha`(0..1), NaN · 음수 무시, 스텝의 10 만분의 1 허용(서브스텝 반올림)을 담습니다. `Engine/Physics/FixedStepAccumulator` 는 지웠고 버린 시간 진단(`getDroppedTime`)은 쓰는 곳이 없어 옮기지 않았습니다. `Countdown` · `RateAccumulator` 도 Core/Time 으로 내렸고, 쓰는 곳이 없던 `TimerQueue` 는 지웠습니다(언리얼 `FTimerManager` 같은 예약 타이머가 필요해지면 그때 Core 에 둡니다).
- **이어 갈 수 없으면 `SW_FATAL`(로그보다 아래 티어는 `SW_LOW_LEVEL_FATAL`)로 멈추고 `std::abort` 를 직접 부르지 않는다**(2026-10-27). 둘 다 `[[noreturn]] sw::internal::reportFatal` 로 모여 이유 한 줄을 stderr 에 먼저 동기로 쓰고 로그로 보낸 뒤 비동기 싱크를 비우고 멈춥니다(언리얼 `UE_LOG(Fatal)` 과 같은 한 경로). 직접 abort 하던 16 곳 중 4 곳은 싱크를 비우지 않아 마지막 줄을 잃을 수 있었습니다. `std::abort` 는 표준 · 서드파티 헤더가 쓰므로 형식으로 지울 수 없어 게이트 `CheckDirectAbort` 가 보고, 예외는 `Macros.cpp`(유일한 abort 자리) · `CrashContext.cpp`(크래시 재현) 둘입니다.
