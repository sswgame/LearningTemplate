# 5-11. 에디터와 외부 공개

> 질문: 5-11. 에디터와 외부 공개 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **에디터 시나리오는 경계 전후 값을 이름으로 기억해 견준다(`Remember` · `sameAs` · `differsFrom`) — 단언마다 기대값을 손으로 적지 않는다**(2026-10-15, `AutomationRunner`). 시나리오는 데이터라 변수가 없어(언리얼 Functional Test · 유니티 Editor Test 는 변수로 듦) 기억한 값을 글 그대로 견주며 64 비트 상태 해시(`Editor.StateHash`)까지 정확히 견준다. 실행기가 엔진에 있어 플레이 · 모듈 리로드 · 백엔드 교체를 넘어 기억한다.
- **에디터 인스턴스를 다시 만들 때 선택 · 미저장 표시는 엔진 서비스(`EditSessionState`)에 맡겨 넘기고 되돌리기 스택은 비우지 않는다**(2026-10-15). 백엔드 교체는 모듈 이미지를 내리지 않으므로 모듈 코드를 가진 되돌리기 명령도 남긴다(`setModuleImageKept`). 패널을 가리키는 명령은 `this` 대신 표지(shared_ptr)로 잡는다.
- **Apply to Prefab 은 같은 씬의 다른 인스턴스에 바로 퍼지고 파일 쓰기와 인스턴스 갱신이 되돌리기 하나다**(2026-10-15, `PrefabCache::updateInstance`). 덮어쓴 값은 옛 원형과 견줘 뽑아 새 원형에 얹는다(`Scene::instantiate` 와 같은 식이라 저장 전후 결과가 같음).
- **지형은 같은 에셋을 다시 읽을 때 저장하지 않은 편집을 넘긴다**(2026-10-15, `TerrainComponent::reloadTerrain`). 트랜스폼 · 프로퍼티 변경은 다시 읽기 안에서 편집을 들고 건너고(경로가 바뀌면 버림) 플레이 정지 복원은 플레이 스냅샷이 편집을 따로 싣는다.
- **메시 모디파이어 셰이딩 미리보기는 GPU 로 못 옮기는 스택이면 CPU 결과 정점 메시로 내려간다 — 와이어만 남기지 않는다**(2026-10-15, `MeshModifierSession::updateShadedPreview`). 바뀔 때마다 새 메시를 끼워 렌더 스레드가 든 사본과 겹치지 않는다.
- **미리보기 씬(툴 창의 월드)은 씬마다 `FrameRenderer` 인스턴스 하나로 그린다 — 주 렌더러 안의 GPUScene 을 씬 키 맵으로 바꾸지 않는다**(2026-10-15, `FrameRendererScenePreview.cpp`). 주 렌더러의 핫 패스를 그대로 두어 주 씬 그림이 바뀔 여지가 없다(유니티 `PreviewRenderUtility` 와 같은 모양). PSO 캐시는 주 렌더러의 것을 함께 쓴다(`FrameRenderer::_pPSOCache`, 창을 다시 열 때마다 엔진 PSO 를 다시 만들던 히치를 없앰). 정점 풀 · 머티리얼 그룹 버퍼는 렌더러마다 따로이고 계획(`EditorMultiWorld.md` 결정 2)의 정점 풀 공유는 미리보기 창이 여럿 열려 메모리가 문제일 때 다시 본다. 미리보기 렌더러는 디바이스에 하나인 GPU 타임스탬프 · 프로파일 구간 · 렌더 타깃 목록을 건드리지 않는다.
- **툴 창의 Undo 는 창마다 스택이고 포커스된 창이 자기 스택을 건다**(2026-10-15, `editor::setFocusedCommandStack` · `EditorPreviewPanel`). 오브젝트 Undo 명령은 기록할 때의 씬 키를 기억해 그 씬에서 되돌리며 창을 닫아 씬이 사라지면 아무것도 하지 않는다. 언리얼 · 유니티는 전역 스택 하나에 대상을 붙인다(계획 3 절).
- **확장 모듈(에디터 플러그인)은 등록 줄 `SW_EDITOR_SUBSYSTEM` 으로 에디터 서브시스템을 기여한다 — 함수 정적 싱글턴을 두지 않는다**(2026-10-14, `EditorExtensionSubsystems`). 확장은 에디터가 뜬 뒤에도 로드 · 언로드되므로 내장과 따로 두고 패널과 같은 장치(등록 목록 세대 · 모듈 언로드 직전 `releaseSubsystemsWithin`)로 만들고 내린다. 찾는 쪽은 `editor::findSubsystem<T>()` 다. 등록 줄은 UI 쪽 .cpp 에 둘 수 있다(세션 .cpp 를 에디터 없이 컴파일하는 EngineTest 가 있음).
- **렌더러 안(FrameRenderer 의 PSO 캐시 · 트랜지언트 풀 · 리드백 · 캔버스)도 서브시스템으로 만들지 않는다**(2026-10-14) — RHI 안(5-5)과 같은 이유로 핫 패스의 타입 있는 멤버이고 언리얼 렌더러도 명시 소유다. 모듈이 렌더 패스를 등록하는 창구(`G-1`)는 쓰는 모듈이 생길 때 만든다 — 내보낼 것이 `FramePassContext` · 커맨드 리스트 · 트랜지언트 풀과 렌더 스레드 안전 계약까지라 소비자 없이 만들면 검증되지 않은 채 썩는다.
- **버그 리포트는 언리얼 `BugIt` 모양의 엔진 개발 명령이다**(2026-10-10). 폴더 하나(zip 없음)에 info · 스크린샷 · 로그 사본 · 씬 사본 · 재현 명령을 두고 `bugitgo` 는 폴더를 주지 않으면 가장 최근 폴더다. 입력 녹화는 담지 않는다(전역 녹화기가 없음). 메모는 콘솔 `bugit <메모>` 로 붙이고 에디터 커맨드는 메모 없이 바로 모은다.
- **인스펙터의 "기본값과 다름" 은 컴포넌트 타입마다 만든 기본 인스턴스와 견준다**(2026-10-10, 언리얼 CDO). 이 저장소는 초기값을 생성자에 두어(AGENTS) 리플렉션 메타의 기본값 글이 대부분 비어 있다. 메타 글은 중첩 구조체처럼 인스턴스가 없을 때만 쓴다.
- **환경설정 · 단축키 · 모듈 창의 세부**(2026-10-10): 환경설정 값은 프로퍼티 글 형식(`formatPropertyText`)의 문자열로 저장한다(형식마다 JSON 타입을 맞추지 않아도 왕복이 같음). 단축키 키 이름은 낱말(`Comma` · `0`)이고 저장 파일은 `{ "id": [ "주 조합", "보조" ] }` 다. 모듈 창은 매니페스트를 고치고 Build 단추만 두며 다시 시작은 손으로 한다.
- **에디터 폴더는 층이고 틀은 아래 · 구체는 위다**(2026-10-11). 층 경계는 린트가 아니라 빌드 형식이 막는다(2026-10-22, 린트 `CheckEditorLayers` 를 지움): 티어마다 OBJECT 부분 `EditorTier<N>Model` · `EditorTier<N>View` 를 짓고 부분마다 자기 티어보다 위 층의 모든 헤더 자리에 `#error` 껍데기(`<빌드>/generated/sw/EditorLayerStubs/tier<N>`)를 include 자리 맨 앞에 둔다. 위 층 헤더를 include 하면(전이 포함) 컴파일이 멈춘다. 표는 `Scripts/lint/rules/GenerateEditorLayers.toml` 이고 폴더와 어긋나면 configure 가 멈춘다. 에디터를 짓지 않는 구성에서는 검사가 돌지 않지만 개발 구성 CI 가 에디터를 짓는다.
  패널 · 팝업 매니저는 인터페이스 옆(`Common/GUI`), 에셋 종류 동작 등록부는 `Workspace`, 커맨드가 패널을 여는 일은 창구 `IEditorPanelHost`, UI 를 만지는 명령의 등록 줄은 그 UI 의 .cpp 이며 상태 막대 항목은 등록 줄(`SW_EDITOR_STATUS_BAR_ITEM`)로 더한다. 예외는 어느 층에서 include 해도 되는 잎 헤더(`[prelude]`)뿐이고 모든 매니저를 만드는 조립 파일은 EditorModule 자신(`Source/Editor` 바로 아래)이 가진다. 큰 패널은 `Panels/<패널>/`, 혼자인 패널은 영역 폴더(`Scene/` · `Animation/` · `Data/` · `Settings/`)에 둔다.
- **ImGui 를 모르는 층(Common 의 Asset · Commands · Config · Localization · SourceControl · Workspace)은 OBJECT 라이브러리 `EditorModel` 로 짓고 오브젝트를 EditorModule DLL 에 그대로 넣는다**(2026-10-17, `sw_addModulePart`). 조립 파일(`EditorContextLifecycle.cpp` · `EditorModuleUnloadListener.*`)은 셸 옆에 두어 모델 폴더가 패널 · 팝업 매니저를 include 하지 않는다. 정적 라이브러리나 별도 DLL 로 떼지 않는다 — 확장 모듈이 따로 링크하면 정적 상태가 두 벌이 되고 export 가 빠질 수 있다. vcpkg 가 모든 패키지 헤더를 한 include 자리에 두어 imgui.h 를 include 자리로 숨길 수 없으므로 `IMGUI_USER_CONFIG` 에 `#error` 헤더를 주어 imgui.h 를 거치는 include 를 컴파일 오류로 만든다.
- **패널과 커맨드의 `EditorContext::get()`(62 파일 224 곳)은 생성자 · 인자 주입으로 바꾸지 않는다**(2026-10-11). 패널은 레지스트리가 인자 없이 만들고(`createEditorPanel<T>`) 상용 엔진도 에디터 하위 시스템을 전역 창구로 준다(언리얼 `GEditor->GetEditorSubsystem<T>()`, 유니티 `Selection.activeObject`). EditorTest 는 UI 매니저 때문에 `EditorContext` 를 만들 수 없어 인자로 바꿔도 테스트가 늘지 않는다. 테스트할 판단이 생기면 그 함수만 필요한 서비스 하나를 인자로 받는다. `editor::findSubsystem<T>()` 는 에디터 범위를 먼저 보고 없으면 호스트(엔진) 표를 본다.
- **임포터(`Editor/Common/Asset`)를 라이브러리로 떼지 않는다**(2026-10-11). 명령 줄 임포트(`App --import-*` · `--check-*`)는 App 이 에디터 모듈을 인스턴스 없이 로드해 C-ABI 진입점 `importEditorAssets` 를 부르고 쿠킹은 임포트 산출물만 읽으며 전용 서버와 Shipping 은 임포트하지 않는다. `Common/Asset` 은 이미 ImGui 를 모르는 층 1 이라 에디터 없는 빌드 팜에서 임포트할 일이 생기면 그때 묶는 비용이 작다.
- **imgui-node-editor 는 vcpkg 내장 포트를 그대로 쓴다**(2026-10-18). `<exception>` 패치 오버레이는 macOS(libc++ 19+) 때문이었고 macOS 는 지원 대상이 아니어서 지웠다. 업스트림에 PR 은 내지 않는다(2026-10-06 사용자 결정).
- **DPI 150 % 는 대체 테스트로 확인하고 글자 래스터 선명도만 실제 모니터에서 확인한다**(2026-10-06). 남은 확인은 [후보 문서](../plans/Candidates-ui.md) `B-8` 에 있다.
- **에디터 보강의 결정 열다섯 개(D1 ~ D15)**(2026-10-06, 사용자 지시 "특별한 의도가 없으면 상용 엔진과 비교해 나은 쪽"으로 추천을 정함). 단위는 모두 적용했고 남은 로드맵은 [후보 문서](../plans/Candidates-editor.md) `D3-1` 이다.
  - **확장 지점**(D1 ~ D4): EditorModule 을 SHARED DLL 로 바꾸고 `SW_EDITOR_API` 로 내보낸다. GameFramework · 키트의 에디터 확장은 `Source/GameFramework/PlugIn/Editor/<이름>/` 의 `GF_EditorPlugIn_<이름>`(런타임 층 `Base/` 밖의 별도 축이라 한 곳에 모음), 게임의 것은 `SWGameEditor` 이며 매니페스트 종류는 `EditorExtension`(Dev 전용)이다. 등록부만 따로 떼지 않은 이유는 확장이 쓸 위젯 · 선택 · Undo 까지 결국 옮겨야 하기 때문이다. vcpkg imgui 는 정적 라이브러리라 DLL 마다 사본이 생기므로 CMake 가 확장마다 ImGui 컨텍스트 결속 소스를 만든다(Dear ImGui FAQ). 확장의 메뉴와 단축키는 등록 줄 `SW_EDITOR_COMMAND` 로 더한다.
  - **설정**(D5 ~ D7): 에디터 환경설정은 `Saved/Editor/EditorPreferences.json` 에 기본값과 다른 값만 두고 섹션은 리플렉션 구조체 하나다. 단축키 덮어쓰기는 `Saved/Editor/Shortcuts.json` 이다. 모듈 켜고 끄기는 프로젝트 매니페스트를 고치고 빌드와 재시작을 묻는다(실행 중 켜기 없음, 언리얼 Plugins 창의 Restart Now).
  - **디버그와 캡처**(D8 ~ D13): assert 무시 대화상자는 대화형 에디터 실행에서만 띄우고 자동 실행(`-unattended`, 시나리오, 프로파일)에서는 멈춘다. GPU 캡처는 네 백엔드를 모두 잡는 RenderDoc in-app API 이고 PIX 는 하지 않는다. 스크린샷 버튼은 PNG, 테스트용 `-gv_screenshot` 은 PPM 이다. 보기 모드는 Normals · Depth · Overdraw 를 더하고 Shader Complexity 는 하지 않는다(머티리얼 그래프가 없어 의미가 약함). 스레드 미니 타임라인은 프로파일러 패널 안에 두고 깊은 분석은 Tracy 로 한다.
  - **씬 뷰 / 게임 뷰 분리**(V1, 2026-10-10): 에디터 카메라 뷰(Scene)와 게임 카메라 출력(Game)은 다른 패널이고 같은 영역의 탭이 기본이며 재생 단추는 상단 툴바에 있다. 보이는 패널의 뷰만 그리고 엔진에는 게임 뷰를 주 출력으로 · 씬 뷰를 호스트 타깃 추가 뷰로 요청한다(렌더러를 두 번 돌리지 않고 다중 뷰 하나로).
  - **씬 뷰 툴바는 떠 있는 오버레이 바**(2026-10-11, 사용자 요청): 유니티 Overlays 처럼 바마다 끌어 옮기고 붙이고 접고 숨긴다(언리얼의 고정 툴바는 좁은 씬 뷰에서 잘림). 재생 툴바(상단)는 그대로 둔다(도킹 창으로 바꾸는 안은 사용자가 거둬들임).
  - **선택 표시는 경계 상자**(N1, 2026-10-11): 고른 오브젝트는 강조 주황 경계 상자로 그린다(Godot 3D 선택 상자). 언리얼 · 유니티의 실루엣 외곽선은 선택 오브젝트만의 스텐실 · id 버퍼가 네 백엔드에 다 있어야 해 미뤘다(`postoutline` 은 깊이 불연속 외곽선이라 선택을 모름).
  - **에디터의 통계 표시는 디버그 HUD 하나로**(2026-10-11, 사용자 요청): 씬 뷰 Stats 상자와 게임 뷰의 `DebugOverlayState` 줄을 지우고 HUD 섹션으로 바꿨다(같은 수치를 두 경로로 그리면 값 · 서식이 갈라짐). 게임 뷰는 런타임 HUD 를 그대로 보이고 씬 뷰는 같은 섹션 본문을 ImGui 로 그린다. 상태는 엔진 사용자 설정 한 곳이다.

- **에디터 시나리오는 원본 폴더가 아니라 실행마다 새로 만든 사본 폴더에 쓴다**(2026-10-20). 근본 원인은 시나리오가 `Resource/` 원본에 쓰는 것이고 파일을 지우거나 되돌리는 것은 증상 처리다. `<Scenario>` 아래 `<Scratch from="<추적 중인 폴더 id>" as="scratch/<이름>"/>` 로 선언하면 실행기가 시작할 때 `Resource/scratch/<이름>` 을 지우고 원본을 복사한다(`AutomationScratch::prepare` — 글 파일 안의 원본 id 는 사본 id 로, `.meta` 의 guid 는 새로 만듦, `Resource/scratch/` 는 `.gitignore`). 복사 실패는 LoadError 다.
  사본을 리소스 루트 밖(`Saved/`)이 아니라 루트 안의 보통 도메인 폴더로 둔 이유는 에디터에 `ResourcePaths::getRootFolderPath()` 에 id 를 직접 붙이는 곳이 43 군데라 경로를 돌리는 덮개가 그 길을 모두 놓치기 때문이다. 개발 명령 `asset.openScratch <사본 id>` 는 `scratch/` 밖의 id 를 받지 않아 원본을 열어 고치는 경로를 형식으로 막는다. 역색인의 참조 도메인에 `scratch/` 를 더했고 쿠커의 도메인 목록에는 없어 팩에 들지 않는다. 작업 트리가 깨끗한지 보는 게이트와 `<Scratch>` 없는 시나리오의 쓰기를 실패로 적는 검사는 두지 않았다(체인 192 단계 뒤 `git status` 가 시작 전과 같았고 검사는 쓰기 경로마다 훅이 필요함 — 새 시나리오가 원본에 쓰면 체인 뒤 `git status` 로 드러남). 게임 시나리오(`game/*/automation`)는 점검하지 않았다.

- **머티리얼 그래프(노드로 셰이더를 짜는 편집기)는 두지 않는다 - 마스터 머티리얼 + 값 · 텍스처 칸으로 간다**(2026-10-24, `DesignerDataToolsAudit` D3). 스크립팅 층을 두지 않는 이유(2절)와 같은 줄이다: 셰이더 논리는 HLSL 이고 디자이너가 만지는 것은 마스터 머티리얼이 드러낸 값과 텍스처 칸이다(`MaterialPanel`). 그래프를 두면 노드 → HLSL 생성기, 노드마다의 순열 키, 생성한 셰이더의 쿠킹 · 캐시 무효화, 네 백엔드에서 같은 결과라는 확인까지 떠안는다. 한 번 쓰면 되돌리기 어려운 비용인데 얻는 것은 "마스터 머티리얼이 드러내지 않은 식을 코드 없이 짜는 일" 뿐이다.
  **다시 볼 조건**: 마스터 머티리얼 + 값으로 못 담는 식이 아트 쪽에서 세 번 이상 나오면(새 마스터를 코드로 더해야 했던 경우를 센다) 그래프가 아니라 "마스터 머티리얼에 식 칸 더하기"부터 따진다. 뷰 모드 Shader Complexity 를 하지 않은 이유도 같은 뿌리다.
- **일반 게임플레이 상태 머신 데이터 형식은 두지 않는다 - 기믹 회로 · 행동 트리 · 퀘스트 · 대화 · 애니메이션 상태 머신이 갈음한다**(2026-10-24, `DesignerDataToolsAudit` D5). 이름 붙은 상태가 배타적으로 바뀌는 논리는 이미 자리마다 있다: 환경 논리는 기믹 회로(`Latch` · `Toggle` · `Counter` · `Timer` · `Delay` 노드를 원핫으로 이음), 행위자의 판단은 행동 트리(`*.bt.xml`), 진행은 퀘스트 · 대화 그래프, 몸짓은 애니메이션 상태 머신. 새 형식을 더하면 같은 논리를 어느 쪽에 쓸지 갈리고 편집기도 하나 더 는다. **다시 볼 조건**: 위 넷 어디에도 못 담는 "이름 붙은 단계 + 단계별 들어오기 · 나가기 동작"이 실제로 필요해질 때(예: 보스 단계) 기믹 회로에 상태 노드 종류를 더하는 쪽부터 따진다.
- **일괄 임포트(`AssetImportStampUtil::importAll`)는 원본 파일을 병렬로 임포트하고 합치기는 파일 순서대로 직렬로 한다**(2026-10-25). 원본 폴더마다 준비(직렬) - 임포트(사슬 단위로 `TaskManager` 와 나눔) - 합치기(직렬)로 돈다. 파일마다 결과(`FileResult`)가 자기 칸에 담기고 요약 · 스탬프 표는 파일 순서로만 만들어져 결과 바이트 · 스탬프 · 요약은 직렬일 때와 같다. 작업 시스템이 없으면(테스트 하니스) 이 스레드가 같은 순서로 돈다. 텍스처 한 장의 띠 병렬 압축은 그 안에서 중첩해도 된다(`runParallel` 이 기다리는 동안 다른 일을 돕고 호출 스레드가 첫 청크부터 직접 돎). 언리얼 `UAssetImportTask` 는 한 번에 하나씩, 유니티 Asset Import Worker 는 원본별 워커 프로세스로 나눠 한 곳에서 적는다(기억에 의존) — 여기는 워커 스레드 + 직렬 합치기다.
  **임포터 규칙**(`IRawAssetImporter` 헤더): ① `const` 함수는 동시에 불리므로 무상태다. 원본 하나의 결과는 반환값으로만 내고 `importSource` 는 공유 상태를 바꾸지 않는다. ② 임포트는 자기 결과 자리(`makeImportedPath` 에서 확장자를 뗀 경로와 그 아래 옆 폴더)에만 쓰고 지운다. 같은 자리거나 한쪽이 다른 쪽의 옆 폴더 아래인 원본(`a.glb` · `a.gltf`, `x.glb` · `x/y.glb`)은 한 사슬로 묶여 한 스레드가 파일 순서로 돈다. ③ **다른 원본의 임포트 결과를 읽는 순서 의존은 데이터로 선언한다**(`hasOrderDependency`). 지금은 규칙에 `body_surface` 가 있는 장비 메시가 몸 `.mesh` 를 `MeshCache` 로 읽는 경우뿐이고, 선언된 원본이 든 사슬은 의존 없는 원본이 모두 끝난 뒤 이 스레드에서 직렬로 임포트한다(예전에는 파일 이름 순서에 따라 옛 몸 메시를 읽었다). 의존을 위상 정렬하는 일정표는 의존이 하나뿐인 지금 과하고, 병렬 구간 밖에 두면 `Mesh::create` · `MeshCache` 를 워커에서 부르지 않아도 된다. 의존 대상 자신은 의존이 없어야 한다.
- **에디터 핫 리로드의 원본 임포트(모델 · 텍스처 · 높이장)는 에디터 스레드가 아니라 백그라운드 잡에서 돌고, 바뀐 원본만 임포트하며, 결과 적용은 에디터 스레드에서만 한다**(2026-10-25). 예전에는 감시 이벤트마다 에디터 스레드에서 동기로 루트 전체를 `ImportStale` 로 훑어(해시 읽기 · 텍스처 압축 · 모델 변환) 프레임이 멈췄다.

  ② `EditorAssetImportJob`(`EditorBackgroundTask`, `take()` 폴링)이 워커에서 임포터를 부르고 에디터 스레드(`AssetHotReload::update`)가 결과를 가져간다. 표(`AssetMatchRow::_importThread`)가 임포터가 도는 곳을 정한다(`Worker`: 모델 · 텍스처 · 높이장, `Editor`: 테마 토큰 표시). 한 번에 잡 하나만 돈다(두 워커가 같은 결과 자리와 `import.stamp` 를 밟지 않게).
  ③ 취소: 임포트 중에 같은 원본이 또 바뀌면 잡이 다음 원본 전에 멈추고(진행 중인 원본 하나는 끝까지 감) 건너뛴 원본과 바뀐 원본이 다음 잡으로 간다. 세대 토큰은 낡은 요청을 시작 전에 버리고 도는 중의 취소는 별도 표시로 한다(세대를 올리면 앞 워커와 새 워커가 겹침).
  ④ 결과 적용(`IAssetCache::reload` · `notifyAssetUsers`)은 임포트가 쓴 파일의 감시 사건을 에디터 스레드가 처리해서 한다. 임포트 결과는 여러 파일이고 일부는 원자적이지 않게 쓰이므로(DDS `SaveToDDSFile`, 모델은 옆 폴더를 지우고 다시 씀) **임포트가 도는 동안 온 그 밖의 파일 변경은 미루고 임포트가 모두 끝난 `update` 에서 처리한다**.
  ⑤ 자동화 시나리오: 감시 울타리(`ContentWatchFence`)가 표지 사건 뒤에도 임포트가 끝나기를 기다리고(120 초, 넘으면 오류) 탐침 `Editor.AssetImportBusy` · `Editor.AssetImportFinishedCount` 를 `WaitUntil` 이 쓴다. 진행 표시는 상태줄(`EditorAssetImportStatus`)과 로그다.

- **임포트 규칙은 한 원본에 하나만 맞아야 하고 겹치면 순서로 고르지 않고 오류다 — 겹침은 `exclude_patterns` 로 풀어 쓴다**(2026-10-25, `AssetImportRuleUtil`, 계획 `ImportRuleOverlap`). 패턴은 경로 마디 단위(`*` 는 폴더를 넘지 않고 마디 `**` 만 넘음)이고 조건 없는 나머지 규칙은 겹침에서 빼되 맨 끝에 하나만 둔다. 유니티 프리셋 · 언리얼 임포트 설정은 에셋마다 설정을 가리키는 쪽이라 겹침이 없고, 이 엔진은 와일드카드 표라 "첫 매칭 승" 이 새 팩의 파일에 다른 팩의 규칙을 조용히 씌웠다. 우선순위 필드를 더하지 않고 겹침을 쓸 수 없는 형식으로 풀었다(credits 표 `CheckResourceCredits` 와 같은 모양).
