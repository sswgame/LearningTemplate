# 5-2. 빌드, 스크립트, CI

> 질문: 5-2. 빌드, 스크립트, CI 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **GPU 잠금은 공유(두 프로세스)와 독점으로 나눈다 — 기능 확인 실행은 공유로 병렬, 측정 · 장치 제거 실험은 독점**(2026-10-15, `shared-lock acquire gpu --shared`). 결정적 시나리오와 hostgpu 는 서로의 수치를 오염시키지 않는다. 독점이 먼저다(독점이 기다리는 동안 새 공유는 물러남).
- **`AppBin` 잠금은 지금 풀지 않는다 — 에디터 시나리오의 고정 이름 쓰기 위치(`Resource/scratch/<이름>`, `Saved/Automation/<시나리오>/`)를 실행별로 나눈 뒤에 푼다**(2026-10-25, `HostGpuIsolation`). 풀어도 두 슬롯이 서로의 폴더를 지운다. 쓰기 위치 목록과 단위 H1 ~ H4 는 계획 문서에 있다.

- **게임 여럿을 한 빌드에서 짓는다 — 모듈 이름 `SWGame` 은 그대로, 타깃은 게임마다 `SWGame_<게임>`(활성 게임도), 산출물은 `Bin/Modules/SWGame`(활성) · `Bin/Games/<게임>/SWGame`, 고르기는 `SW_GAMES`(Dev 전용)**(2026-10-13, `C-25`). 게임 팩끼리 PCH 하나(`sw_game_pch`)를 나눠 쓴다. 실행 중에 키트를 더하고 빼는 경로는 만들지 않고(2026-10-14 사용자 결정 — 키트 조합은 빌드 · 기동 때 정함), 게임별 CMake 프리셋(`Ninja-Debug-<게임>`)도 두지 않는다(2026-10-14 사용자 결정 — `Ninja-Debug` 하나 + `-game=`).
  기동 때 고른 게임이 닿지 않고 다른 게임 팩만 닿는 키트는 호스트 로더가 매니페스트를 카탈로그에 넣지 않는다(유니티 패키지와 같음). 아무 게임도 닿지 않는 키트는 언리얼 `EnabledByDefault` 처럼 켜진 채 둔다. 전용 서버는 오디오를 디코드하지 않는다(`target_excluded_asset_kinds` → `ResourcePaths::isExcludedForHost`).
  언리얼은 엔진을 한 번 짓고 프로젝트 모듈만 프로젝트 폴더에 내며 유니티 · Godot 도 에디터 하나가 여러 프로젝트를 연다. 키트는 고른 게임들의 의존 합집합(`SW_BUILD_UNUSED_KITS=OFF`, 프리셋 `Ninja-Debug-Lean`)이고, Dev 는 `-game=<이름>`(`GameSelection`)으로 고르며 기본은 `Bin/Modules/ActiveGame.txt` 라 게임 이름이 엔진 TU 에 구워지지 않는다. Shipping 은 활성 게임 하나를 정적으로 링크하고 정체성을 빌드 시점에 굽는다.

- **include 경로에는 뿌리(`Source/` · `Resource/` · 생성 폴더)만 두고, `Source/` 아래 폴더(엔진 · Core · 모듈 · RuntimeAPI · App)는 include 경로가 아니다**(2026-10-23, 층 게이트 T6). `#include "pch.h"` 는 생성한 진입 헤더 하나(`generated/sw/pchentry/<engine|core>/pch.h`)로 풀고(`sw_addPchEntryDirectory`), 구성 끝에 `sw_verifySourceIncludeRoots` 가 소스 폴더 경로를 거부한다. 소스 폴더를 경로로 주면 접두 없는 include 가 다른 층으로 풀려 층 게이트(경로 앞부분으로 층을 앎)를 비껴갔다. Godot 이 저장소 뿌리 기준 경로만 쓰는 것과 같다. `pch.h` 를 새 pch 전용 폴더로 옮기는 안은 티어 표 · 루트 모음 헤더 규칙에 걸려 기각했다(언리얼 UBT 도 공유 PCH 를 Intermediate 의 생성 헤더로 연다).

- **Windows 지연 로드(`/DELAYLOAD`)를 쓰지 않는다 — 모듈끼리는 일반 import 이고 핫 리로드가 섀도 복사본의 import 이름을 세대 이름으로 바꾼다**(2026-10-12). lld 20.1.8 의 x64 지연 로드 썽크(`__tailMerge_<dll>`)가 xmm0~3 을 `__delayLoadHelper2` 호출의 홈 공간에 저장해 처음 묶는 호출의 float 인자가 망가졌다(LLVM 이슈 51941, 고침은 LLVM 21.x). 기각한 후보:
  (a) 도구 사슬을 LLVM 21 로 올리기 — 이 결함 하나로는 크고 올린 뒤에도 지연 로드가 필요한 자리가 없다. (b) 다시 올리지 않는 의존만 일반 import — 키트 → 키트 등 다시 올리는 의존에는 썽크가 남는다. (c) 모듈이 DllMain 에서 스스로 묶기 — 로더 락 안이라 안 되고 정적 초기화가 이미 썽크를 지난다. (d) 첫 호출을 float 인자 없는 함수로 만드는 프라이머 — 썽크가 import 마다라 지킬 수 없다. 모든 지연 import 를 미리 묶는 우회는 이미지 목록을 놓치면 조용히 다시 망가졌다.
  (e) **고른 것**: 복사본 파일 이름을 같은 길이의 세대 이름(`GF_Mai0003.dll`, 복사본마다 제 폴더)으로 하고 의존하는 복사본의 import 표 이름을 제자리에서 바꾼다(리눅스 SONAME 바꾸기와 같은 장치). 로더가 이미 올라온 같은 이름의 이미지를 쓰므로 원본이 두 번 올라오지 않고 썽크 자체가 없다. 없을 수 있는 시스템 DLL(Media Foundation · XAudio2 · TracyClient)은 LoadLibrary + 함수 표, 늘 있는 d3dcompiler_47 은 일반 import 다.
  상용 엔진: 언리얼은 모듈 DLL 을 정적 import 하고 핫 리로드 때 번호 붙은 새 이름으로 다시 링크하며, 유니티는 도메인 리로드, Godot GDExtension 은 함수 표라 import 가 없다. 가드는 빌드 `CheckNoDelayLoad`, 런타임 `LiveReloadManager` 의 거절(Debug 단언), 산출물 `ArchitectureTest.NoBuiltImageHasDelayLoadedImports` 다.

- **Shipping 의 RHI 백엔드는 쿠킹 테이블의 이름(`DirectX11`, `DirectX12`, `Vulkan`, `OpenGL`)으로만 고른다**(2026-10-06). 별칭이나 그 플랫폼에 없는 백엔드를 주면 configure 가 멈춘다(언리얼 TargetRules 도 같다).
- **App 의 백엔드 명령줄 철자는 백엔드마다 하나다 — `-dx11` · `-dx12` · `-vk` · `-gl`**(2026-10-07). 쿠킹 표의 `command_line_name` 칸이 정본이고 다른 철자는 받지 않는다. 셰이더 폴더 이름(`dx11` · `dx12` · `vulkan` · `opengl`)은 따로 있는 칸이다.
- **vcpkg 라이브러리 등록 함수는 `sw_addVcpkgPackage`(못 찾으면 configure 실패)와 `sw_addVcpkgHeaderOnly` 두 가지다**(2026-10-06). 언리얼 ThirdParty 모듈의 두 종류와 같다.
- **서드파티 헤더는 그 라이브러리 타깃을 링크해서만 얻는다. vcpkg include 폴더를 모든 타깃에 거는 전역 경로는 두지 않는다**(2026-10-15). 전역 경로는 설치가 남은 PC 에서만 통과하고 새 CI 러너에서 지는 include 누락을 만들었다(언리얼 Build.cs 의 명시 의존과 같다).
- **키트 빌드 순서는 모듈 매니페스트 의존 관계의 위상 정렬이다**(2026-10-06). 폴더 이름 순서로는 공유 키트가 먼저 정의된다는 보장이 없다.
- **스크립트 이름과 도움말 규칙**(2026-10-06): 도움말은 한국어다. `Scripts/dev/` 의 이름은 동사로 시작하고(`Make*`, `Run*`) "Generate" 는 빌드가 만드는 생성물에만 쓴다. `py -3 -m Scripts gate|fix|report|selftest <이름>` 은 폴더를 찾아 부르고 CMake · 커밋 훅 · CI 는 경로로 부른다.
- **게이트는 파일을 고치지 않는다**(2026-10-06). include 순서와 namespace 블록은 픽서(`FormatIncludeOrder`, `FormatNamespaceBlocks`)가 고치고 대상은 `--files` 하나로 고른다. 포맷터는 내용 밖의 바이트(BOM, 줄끝)를 바꾸지 않는다.
- **configure 중의 파이썬 생성기는 한 프로세스로 돌린다**(2026-10-06). configure 시간의 29 % 가 파이썬 기동이었다.
- **커밋 훅의 트리 전체 게이트는 코어 수만큼만 동시에 띄우고, 린트 CTest 는 동시에 4 개씩 돌린다**(2026-10-06). 4 와 8 이 측정 오차 안에서 같고 4 가 CPU 를 절반만 쓴다. CI 린트 잡은 처음부터 실패를 막는 단계다.
- **Release 와 Shipping 도 디버그 정보를 만들고, 기본은 줄 정보만(`SW_RELEASE_DEBUG_INFO=lines`)이다**(2026-10-06). 배포물 PDB 는 `Symbols/`, 테스트 실행 파일 PDB 는 `TestBin/` 에 둔다.
- **vcpkg 포트를 고칠 때는 트리플릿이 아니라 오버레이 포트(`ThirdParty/<pkg>/vcpkg-port/`)를 쓴다**(2026-10-06). 트리플릿 파일의 해시는 모든 포트의 ABI 에 들어가 고치면 공유 설치 트리 전체를 다시 빌드한다. 포트 버전을 올릴 때는 오버레이도 같이 올린다.
- **의존성 기준선은 vcpkg 레지스트리 커밋 하나(`builtin-baseline`)로 올리고 같은 커밋으로 `Tools/vcpkg` 를 맞춘다**(2026-10-10). 남은 판은 `py -3 -m Scripts deps-outdated` 가 보인다. OpenSSL 4(libpq 의 `openssl` 기능이 따라오는지 먼저 봄), glad2(GL 백엔드 초기화를 다시 씀), DXC 최신(구운 셰이더 전부와 네 백엔드 그림이 바뀜)은 기준선과 따로 올린다.
- **Dev `Bin` 은 실행 파일 · 엔진 · 서드파티 DLL 만 두고, 모듈은 `Bin/Modules`, PDB 는 `Bin/Symbols`, 테스트는 `TestBin` 에 낸다**(2026-10-10). 언리얼이 플러그인 DLL 을 플러그인 `Binaries/` 에, 유니티가 네이티브 플러그인을 `Plugins/` 에 따로 두는 것과 같다. 모듈이 쓰는 서드파티 DLL 도 `Bin` 한 벌이다(vcpkg applocal 이 모듈 옆에 사본을 두지 않게 함).
- **개발 기본 빌드(`all`)는 테스트를 짓지 않는다**(2026-10-10). Debug CPU 시간의 26 % 가 테스트(614 TU)였다. `Test/` 는 `EXCLUDE_FROM_ALL` 이고 `AllTests` 타깃이 모은다. CI · 검증 프리셋(`CI-*`, `*-Shipping*`, `Ninja-Debug-ASAN`)은 build 프리셋의 `targets` 로 테스트까지 짓고, `ctest` 는 셋업 픽스처(`BuildTestBinaries`), `py -3 -m Scripts test` 도 먼저 짓는다(옛 실행 파일로 통과하는 일을 막음). 기각: 캐시 옵션으로 `all` 에 넣고 빼기(프리셋마다 configure 가 갈림), `all-with-tests` 를 `all` 전부에 의존시키기(`ALL` 없는 사용자 타깃을 가려낼 수 없음).
- **게이트가 나눠 쓰는 글 읽기는 `Scripts/common/CodeText.py` 한 자리이고, 3,000 줄이 넘는 게이트는 규칙 묶음 패키지(`Scripts/lint/conventions/`)로 나눈다**(2026-10-10). 층 게이트 다섯을 표 하나로 구동하는 한 구현은 하지 않았다 — 판정이 서로 다르고 CTest 이름 · 자기 테스트가 게이트마다 달려 있어 도우미만 나눴다.
- **`cmake/Engine/` 은 책임 하나에 파일 하나다**(2026-10-10). `ModuleTargets.cmake` 를 컴파일 규칙 · 지연 로드 · ABI 도장 · 모듈 레지스트리 · 모듈 팩토리 · 실행 파일 링크로, `ModuleManifest.cmake` 를 해석 · 켜짐 조회로 나눴다(UBT 가 ModuleRules · TargetRules · 링크 규칙을 따로 두는 것과 같다). 하지 않은 정리: 테스트 폴더 머리의 "Server 타깃이면 건너뛴다" 줄(`return()` 은 부른 파일에 있어야 함), 타깃 공통 기본값 함수(링크 순서를 흔듦), QA 스크립트 테스트 등록 함수, `ConfigConstants.h.in` 의 파이썬 생성기화, zlib · LZ4 · Zstd 의 ThirdParty 래퍼 타깃(리눅스 CI 의 임포트 타깃을 받치는 링크가 빠짐).
- **`NOMINMAX` · `WIN32_LEAN_AND_MEAN` 은 CMake 컴파일 정의다**(2026-10-10). 헤더에서만 정의하면 먼저 `windows.h` 를 include 한 TU 에 min/max 매크로가 생긴다(Godot 도 빌드 정의). 헤더의 `#if !defined` 정의는 빌드 플래그 없이 헤더를 읽는 도구를 위해 남긴다.
- **서드파티 고지(`THIRD_PARTY_NOTICES.txt`)는 빌드가 모은다**(2026-10-06). 대상은 매니페스트가 끌어오는 의존 전부(개발 전용 포함)이다. 넘치는 고지는 해가 없지만 빠지면 라이선스 위반이다.
- **규칙 예외 감사에서 정한 넷**(2026-10-07): ① 두 플랫폼이 같은 명시적 경고 목록을 쓴다(clang-cl 의 `-Wall` 은 `-Weverything`). `Clang.cmake` 가 clang-cl 에 `-clang:-Wall -clang:-Wextra` 를 넘기고, 두 집합에 `-Wundef` 를 더했다(정의하지 않은 매크로를 `#if` 로 읽는 파일을 잡음, 서드파티는 SYSTEM include 라 범위 밖). ② `(void)` 와 이유 주석은 `[[nodiscard]]` 가 붙은 실패 가능 함수에만 요구한다. ③ 백엔드 명령줄 철자는 하나씩만 둔다. ④ 출처를 모르는 리소스는 저장소에서 생성한 것이나 CC0 로 확인한 것으로 바꾼다.
- **게이트와 짝 픽서 · 보고서가 나눠 쓰는 판정은 린트 틀 층(`Scripts/lint/*Rules.py`)에 둔다**(2026-10-24). 게이트의 판정을 픽서가 부르면 층 2 끼리 import 하지 못하는 규칙(`CheckScriptLayers`)에 예외 줄이 늘었다. `LoopBraceRules` · `IncludeOrderRules` · `NamespaceBlockRules` · `DiscardReasonRules` 로 옮겨 예외 네 줄을 지웠다.
- **로그 · assert 문자열의 한글은 게이트 `CheckLogLanguage` 가 막는다**(2026-10-24). 규칙만 있고 게이트가 없어 약 270 곳으로 늘었었다. 호출 인자 밖에서 만든 한글(상수에 담아 넘기는 글)은 게이트가 보지 못하므로 로그로 나가는 글은 호출 안에 리터럴로 적는다.
- **린트의 규칙 데이터는 `Scripts/lint/rules/<이름>.toml` 에 두고 `Scripts/common/RuleData.py` 하나가 읽는다**(2026-10-11). clang-tidy 의 `.clang-tidy`, 언리얼의 `.ini` 처럼 코드 밖에 둔다. TOML 인 이유: 주석이 되고 표 · 배열로 예외 표가 그대로 적히며, JSON 은 주석이 없고 YAML 은 표준 라이브러리에 읽기가 없다. CI 린트 잡의 파이썬이 3.10 이라 `tomllib`(3.11+)이 없어 쓰는 문법만 아는 부분 집합 읽기를 같이 두고 `CheckExemptionTables` 가 두 읽기의 결과를 견준다.
  - 게이트 예외는 크기와 상관없이 모두 옮겼다("예외는 한 자리" 를 셀프테스트가 지키려면 게이트 소스에 표가 없어야 함). 목록은 사람이 늘리는 데이터만 옮겼다(티어, 제품 낱말, 금지 동사 · 줄임말, 약어 등록부, 실패 가능 동사 등).
  - 옮기지 않은 것: 정규식이 든 표(쓰는 코드 옆에), 여러 칸짜리 레코드(부분 집합 읽기에 표 배열이 없음), `Constants.py` 의 경로로 짓는 표, 언어가 정한 낱말, 명명 판정 표(`conventions/NamingVocabulary`), 확장자 목록.
