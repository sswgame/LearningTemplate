# 5-2. 빌드, 스크립트, CI

> 질문: 5-2. 빌드, 스크립트, CI 영역에서 이미 정한 것은 무엇이고 근거는 무엇인가?
> 독자: 같은 제안을 다시 하려는 사람, 정한 이유를 찾는 사람.
> 결론: 결정 기록 5 절의 한 영역이다. 번호 체계와 쓰는 법은 [결정 기록](../09_Decisions.md) 5절에 있다.

- **GPU 잠금은 공유(두 프로세스)와 독점으로 나눈다 — 기능 확인 실행은 공유로 병렬, 측정 · 장치 제거 실험은 독점**(2026-10-15, `shared-lock acquire gpu --shared`). 결정적 시나리오와 hostgpu 는 서로의 수치를 오염시키지 않는다. 독점이 먼저다(독점이 기다리는 동안 새 공유는 물러남).
- **`AppBin` 잠금은 지금 풀지 않는다 — 에디터 시나리오의 고정 이름 쓰기 위치(`Resource/scratch/<이름>`, `Saved/Automation/<시나리오>/`)를 실행별로 나눈 뒤에 푼다**(2026-10-25, `HostGpuIsolation`). 풀어도 두 슬롯이 서로의 폴더를 지운다. 단위 H1 ~ H4 는 계획 문서에 있다.

- **게임 여럿을 한 빌드에서 짓는다 — 모듈 이름 `SWGame` 은 그대로, 타깃은 `SWGame_<게임>`, 산출물은 `Bin/Modules/SWGame`(활성) · `Bin/Games/<게임>/SWGame`, 고르기는 `SW_GAMES`(Dev 전용)**(2026-10-13, `C-25`). 게임 팩끼리 PCH 하나(`sw_game_pch`)를 나눠 쓴다. 실행 중에 키트를 더하고 빼는 경로는 만들지 않고(2026-10-14 사용자 결정 — 키트 조합은 빌드 · 기동 때 정함) 게임별 CMake 프리셋도 두지 않는다(2026-10-14 사용자 결정 — `Ninja-Debug` 하나 + `-game=`).
  기동 때 고른 게임이 닿지 않고 다른 게임 팩만 닿는 키트는 호스트 로더가 매니페스트를 카탈로그에 넣지 않는다(유니티 패키지와 같음). 아무 게임도 닿지 않는 키트는 켜진 채 둔다(언리얼 `EnabledByDefault`). 전용 서버는 오디오를 디코드하지 않는다(`target_excluded_asset_kinds`). 언리얼 · 유니티 · Godot 도 엔진(에디터)을 한 번 짓고 여러 프로젝트를 연다. 키트는 고른 게임들의 의존 합집합(`SW_BUILD_UNUSED_KITS=OFF`, `Ninja-Debug-Lean`)이고 Dev 는 `-game=<이름>`(`GameSelection`, 기본 `Bin/Modules/ActiveGame.txt`)이라 게임 이름이 엔진 TU 에 구워지지 않는다. Shipping 은 활성 게임 하나를 정적으로 링크한다.

- **include 경로에는 뿌리(`Source/` · `Resource/` · 생성 폴더)만 두고 `Source/` 아래 폴더는 include 경로가 아니다**(2026-10-23, 층 게이트 T6). `#include "pch.h"` 는 생성한 진입 헤더(`generated/sw/pchentry/<engine|core>/pch.h`)로 풀고 `sw_verifySourceIncludeRoots` 가 소스 폴더 경로를 거부한다. 소스 폴더를 경로로 주면 접두 없는 include 가 다른 층으로 풀려 층 게이트(경로 앞부분으로 층을 앎)를 비껴갔다(Godot 도 저장소 뿌리 기준). `pch.h` 를 새 pch 전용 폴더로 옮기는 안은 티어 표 · 루트 모음 헤더 규칙에 걸려 기각했다.

- **Windows 지연 로드(`/DELAYLOAD`)를 쓰지 않는다 — 모듈끼리는 일반 import 이고 핫 리로드가 섀도 복사본의 import 이름을 세대 이름으로 바꾼다**(2026-10-12). lld 20.1.8 의 x64 지연 로드 썽크가 xmm0~3 을 홈 공간에 저장해 처음 묶는 호출의 float 인자가 망가졌다(LLVM 이슈 51941, 고침은 LLVM 21.x). 기각: 도구 사슬을 LLVM 21 로 올리기(이 결함 하나로는 큼, 지연 로드가 필요한 자리도 없음), 다시 올리지 않는 의존만 일반 import(키트 → 키트 등에 썽크가 남음), DllMain 에서 스스로 묶기(로더 락), 첫 호출을 float 인자 없는 함수로 만드는 프라이머(import 마다 필요해 지킬 수 없음), 모든 지연 import 를 미리 묶기(이미지를 놓치면 조용히 다시 망가짐).
  **고른 것**: 복사본 파일 이름을 같은 길이의 세대 이름(`GF_Mai0003.dll`, 복사본마다 제 폴더)으로 하고 의존하는 복사본의 import 표 이름을 제자리에서 바꾼다(리눅스 SONAME 바꾸기와 같은 장치). 로더가 같은 이름의 이미지를 재사용해 원본이 두 번 올라오지 않고 썽크가 없다. 없을 수 있는 시스템 DLL(Media Foundation · XAudio2 · TracyClient)은 LoadLibrary + 함수 표, d3dcompiler_47 은 일반 import 다. 가드는 빌드 `CheckNoDelayLoad`, 런타임 `LiveReloadManager` 의 거절, 산출물 `ArchitectureTest.NoBuiltImageHasDelayLoadedImports`.

- **Shipping 의 RHI 백엔드는 쿠킹 테이블의 이름(`DirectX11`, `DirectX12`, `Vulkan`, `OpenGL`)으로만 고르고, App 의 명령줄 철자는 백엔드마다 하나(`-dx11` · `-dx12` · `-vk` · `-gl`)다**(2026-10-06 · 07). 별칭이나 그 플랫폼에 없는 백엔드를 주면 configure 가 멈춘다(언리얼 TargetRules 도 같음). 쿠킹 표의 `command_line_name` 이 정본이고 셰이더 폴더 이름은 따로 있는 칸이다.
- **vcpkg 라이브러리 등록 함수는 `sw_addVcpkgPackage`(못 찾으면 configure 실패)와 `sw_addVcpkgHeaderOnly` 두 가지다**(2026-10-06). 서드파티 헤더는 그 타깃을 링크해서만 얻고 vcpkg include 폴더를 전 타깃에 거는 전역 경로는 두지 않는다(2026-10-15) — 설치가 남은 PC 에서만 통과하고 새 CI 러너에서 지는 include 누락을 만들었다.
- **키트 빌드 순서는 모듈 매니페스트 의존 관계의 위상 정렬이다**(2026-10-06). 폴더 이름 순서는 공유 키트가 먼저 정의된다는 보장이 없다.
- **스크립트 이름과 도움말 규칙**(2026-10-06): 도움말은 한국어, `Scripts/dev/` 의 이름은 동사로 시작하고 "Generate" 는 빌드가 만드는 생성물에만 쓴다. 게이트는 파일을 고치지 않고 픽서(`FormatIncludeOrder` · `FormatNamespaceBlocks`)가 고치며 포맷터는 내용 밖의 바이트(BOM, 줄끝)를 바꾸지 않는다.
- **configure 중의 파이썬 생성기는 한 프로세스로 돌린다**(2026-10-06). configure 시간의 29 % 가 파이썬 기동이었다. 커밋 훅의 트리 전체 게이트는 코어 수만큼, 린트 CTest 는 동시에 4 개씩 돌린다(4 와 8 이 오차 안에서 같고 CPU 를 절반만 씀).
- **Release 와 Shipping 도 디버그 정보를 만들고 기본은 줄 정보만(`SW_RELEASE_DEBUG_INFO=lines`)이다**(2026-10-06). 배포물 PDB 는 `Symbols/`, 테스트 PDB 는 `TestBin/`.
- **vcpkg 포트를 고칠 때는 트리플릿이 아니라 오버레이 포트(`ThirdParty/<pkg>/vcpkg-port/`)를 쓴다**(2026-10-06). 트리플릿 파일의 해시는 모든 포트의 ABI 에 들어가 고치면 공유 설치 트리 전체를 다시 빌드한다. 포트 버전을 올릴 때는 오버레이도 같이 올린다.
- **의존성 기준선은 vcpkg 레지스트리 커밋 하나(`builtin-baseline`)로 올리고 같은 커밋으로 `Tools/vcpkg` 를 맞춘다**(2026-10-10). 남은 판은 `deps-outdated` 가 보인다. OpenSSL 4 · glad2 · DXC 최신은 파급이 커서 기준선과 따로 올린다.
- **Dev `Bin` 은 실행 파일 · 엔진 · 서드파티 DLL 만 두고 모듈은 `Bin/Modules`, PDB 는 `Bin/Symbols`, 테스트는 `TestBin` 에 낸다**(2026-10-10). 언리얼이 플러그인 DLL 을 플러그인 `Binaries/` 에 따로 두는 것과 같다. 모듈이 쓰는 서드파티 DLL 도 `Bin` 한 벌이다.
- **개발 기본 빌드(`all`)는 테스트를 짓지 않는다**(2026-10-10). Debug CPU 시간의 26 % 가 테스트였다. `Test/` 는 `EXCLUDE_FROM_ALL`, `AllTests` 가 모은다. CI · 검증 프리셋(`CI-*`, `*-Shipping*`, `Ninja-Debug-ASAN`)은 build 프리셋의 `targets` 로 테스트까지 짓고 `ctest` 는 셋업 픽스처 `BuildTestBinaries`, `Scripts test` 도 먼저 짓는다(옛 실행 파일로 통과하는 일을 막음). 기각: 캐시 옵션으로 `all` 에 넣고 빼기(프리셋마다 configure 가 갈림), `all-with-tests`(`ALL` 없는 사용자 타깃을 가려낼 수 없음).
- **게이트가 나눠 쓰는 글 읽기는 `Scripts/common/CodeText.py` 한 자리이고 3,000 줄이 넘는 게이트는 규칙 묶음 패키지(`Scripts/lint/conventions/`)로 나눈다**(2026-10-10). 층 게이트 다섯을 표 하나로 구동하는 구현은 하지 않았다(판정 · CTest 이름 · 자기 테스트가 게이트마다 달라 도우미만 나눔).
- **`cmake/Engine/` 은 책임 하나에 파일 하나다**(2026-10-10). 하지 않은 정리: 타깃 공통 기본값 함수(링크 순서를 흔듦), `ConfigConstants.h.in` 의 파이썬 생성기화, zlib · LZ4 · Zstd 의 ThirdParty 래퍼 타깃(리눅스 CI 임포트 타깃을 받치는 링크가 빠짐).
- **`NOMINMAX` · `WIN32_LEAN_AND_MEAN` 은 CMake 컴파일 정의다**(2026-10-10). 헤더에서만 정의하면 먼저 `windows.h` 를 include 한 TU 에 min/max 매크로가 생긴다(Godot 도 빌드 정의). 헤더의 `#if !defined` 는 빌드 플래그 없이 헤더를 읽는 도구용이다.
- **서드파티 고지(`THIRD_PARTY_NOTICES.txt`)는 빌드가 모은다**(2026-10-06). 대상은 매니페스트가 끌어오는 의존 전부(개발 전용 포함) — 넘치는 고지는 해가 없지만 빠지면 라이선스 위반이다.
- **규칙 예외 감사의 결정**(2026-10-07): 두 플랫폼이 같은 명시적 경고 목록을 쓴다(clang-cl 의 `-Wall` 은 `-Weverything` — `Clang.cmake` 가 `-clang:-Wall -clang:-Wextra`, 두 집합에 `-Wundef` 추가). `(void)` 와 이유 주석은 `[[nodiscard]]` 가 붙은 실패 가능 함수에만 요구한다. 출처를 모르는 리소스는 저장소에서 생성한 것이나 CC0 로 확인한 것으로 바꾼다.
- **게이트와 짝 픽서 · 보고서가 나눠 쓰는 판정은 린트 틀 층(`Scripts/lint/*Rules.py`)에 둔다**(2026-10-24). 게이트의 판정을 픽서가 부르면 층 2 끼리 import 하지 못하는 규칙(`CheckScriptLayers`)에 예외 줄이 늘었다.
- **로그 · assert 문자열의 한글은 게이트 `CheckLogLanguage` 가 막는다**(2026-10-24). 호출 인자 밖에서 만든 한글(상수에 담아 넘기는 글)은 게이트가 보지 못하므로 로그로 나가는 글은 호출 안에 리터럴로 적는다.
- **린트의 규칙 데이터는 `Scripts/lint/rules/<이름>.toml` 에 두고 `Scripts/common/RuleData.py` 하나가 읽는다**(2026-10-11). TOML 인 이유: 주석이 되고 표 · 배열로 예외 표가 그대로 적히며 JSON 은 주석이 없고 YAML 은 표준 라이브러리에 읽기가 없다. CI 린트 잡의 파이썬이 3.10 이라 `tomllib` 이 없어 부분 집합 읽기를 같이 두고 `CheckExemptionTables` 가 두 읽기를 견준다. 게이트 예외는 모두 옮기고(게이트 소스에 표가 없어야 "예외는 한 자리") 사람이 늘리는 목록만 옮긴다. 정규식이 든 표 · 경로로 짓는 표 · 언어가 정한 낱말 · 명명 판정 표는 쓰는 코드 옆에 남긴다.
- **Python 모양 규칙은 이미 80 % 넘게 쓰던 관습만 올렸다**(2026-10-11, [agents/NamingScripts › Python](../agents/NamingScripts.md#python)). 새 취향은 만들지 않고 `CheckPythonConventions` 에 걸었다(Ruff 와 같은 내용이지만 외부 도구를 CI · 훅에 깔지 않음). 종료는 `sys.exit` 하나(`raise SystemExit` 는 트레이스백이 안 찍힘), 출력은 `print`(로깅 래퍼는 새 취향). 걸지 않은 것: 지역 컨테이너 접두어, 셔뱅, 광범위 `except Exception`(계속 가야 하는 경계라 산문 규칙만), `subprocess` 직접 호출(`CheckScriptCommonHelpers` 가 막음). `.claude/hooks/SessionGuard.py` 는 어떤 예외에도 세션을 막지 않게 0 으로 끝난다.

- **빌드 속도 개선은 계획의 1 ~ 6 단계까지 하고 7 ~ 9 단계는 필요할 때만 한다**(2026-10-10, 사용자 결정). 7 헤더 팬아웃 감시, 8 Debug 디버그 정보 줄이기, 9 링크 단위 분할이다. 남은 단계는 [빌드 속도 계획](../plans/BuildSpeed.md).
- **서드파티는 Jolt(3D 물리) · Box2D(2D 물리) · ACL(애니메이션 압축)**(2026-10-04, 사용자 결정), **Recast & Detour · Tracy**(2026-10-05), **OpenSSL · SQLite · libpq**(2026-10-06)다. 모두 vcpkg 로 들이고 엔진 인터페이스 뒤에 감싸며 헤더 경계는 `CheckThirdPartyIsolation.py` 가 지킨다. Tracy 는 클라이언트만 쓰고 C++17 오버레이 포트가 있으며 Shipping 은 링크하지 않고 뷰어는 저장소에 넣지 않는다. SQLite 는 `GF_SQLStore`, libpq(`openssl` 기능만)는 `GF_Server_SQLStore` 에서만 링크한다.
- **테스트 골든 기준은 기계별로 만들지 않는다**(2026-10-06, 사용자 결정). 기준은 그린 장치(GPU 이름, 드라이버)를 함께 적고 다른 기계에서 지면 그 기계에서 `--record` 해 드라이버 차이인지 회귀인지 가른다.
- **골든 · 시나리오 캡처는 시작부터 센 프레임이 아니라 화면이 자리 잡은 뒤에 찍는다**(2026-10-22). 자리 잡음 = 씬 플레이 시작 + 캡처 차단 조건 없음(로딩 화면 · 페이드 · 시계 잡기, `AutomationBlockScope`) + 에셋 일 0(`AutomationCaptureUtil::isReadyForCapture`). 골든은 `Test/QA/Games.json` 의 `settled_frames` 이고 120 초 안에 자리 잡지 않으면 오류로 끝난다(언리얼 자동화 스크린샷도 로드 · 셰이더 컴파일을 기다림). 빠른 기계에서 고정 프레임이 로딩 화면을 찍었다.
- **조건 세 부분 이상은 이름을 붙이고 기준선은 0 이다**(2026-10-15, `CheckConditionParts`). `if` 는 바로 앞에 `const bool` 을 두고, `else if` 는 부작용이 없고 앞 조건의 보호가 필요 없을 때만 체인 앞으로 올리며 부작용이 있으면 `else { const bool …; if ( … ) }`, `while` 은 `while ( true )` 와 이름 붙인 `break` 로 바꾼다.

- **통합 검증(`verify-batch`)이 느린 까닭을 구조로 줄인다: 기본은 정합성 검증뿐이고 측정은 따로, 선행은 항목에 적고, 긴 시나리오는 샤드로 겹쳐, 앞 단계가 지면 뒤를 안 돈다**(2026-10-27, verifyopt). 한 번에 약 80 분(측정 22개 40 ~ 45 분, 테스트 64개 약 18 분, 빌드 약 13 분, ctest 약 8 분)이던 전체 실행의 로그에서 정했다. ① 측정(`measure`)은 병합 정합성과 무관한 성능 판정이고 GPU 독점이라 혼자 돌므로 기본에서 빼고 `--measure` · `--measure-only` 로 성능에 닿는 변경에서만 부른다(이름 있는 프로필을 따로 두지 않고 기본을 뒤집었다 — 프로필 이름이 늘면 항목마다 소속을 또 적어야 하고, 통과 · 실패를 판정하는 측정 종류 항목은 `functional` 한 칸으로 기본에 남긴다). ② 다른 항목이 남긴 보고를 읽는 항목은 `requires` 로 선행을 적는다 — 선행이 졌을 때 그 보고를 읽다 연쇄로 지던 것(`scenario-thresholds-promote` 0 ~ 1 초)이 `건너뜀 선행` 으로 표에 오르고, 읽을 때 앞서 도는 항목만 선행이 될 수 있어 순환 · 거꾸로가 없다. ③ AppScenarioTest 는 케이스 단위로 쪼갠 뒤에도 `Scripts test` 가 한 프로세스(`shard0of1`)로 직렬로 돌았다 — `app-scenarios-release` 는 `ctest -L hostgpu`(비용표 샤드 `AppTest_HostOnly_Shard1~5`)로 돌리고(통합 S/T), `shards`(`test` 항목을 `--test_shard=k/n` 조각 n 개로 나눠 GPU 칸 수 `gpuSlots` 만큼 겹쳐 돌림, 실행 파일 정책에 `hostResourceLock` 이 남았으면 순서대로)는 ctest 샤드가 없는 긴 `test` 필터에 쓴다. 시나리오 보고는 `build/<프리셋>/AppRuns/shard<k>of<n>/<케이스>/Saved/Automation` 아래라 보고를 읽는 항목의 인자도 `build/{preset}/AppRuns` 다. ④ `ctest` 항목은 혼자 돈다: `ctest -j` 둘이 겹치면 CPU 경합으로 15 초 제한인 린트 둘이 가짜로 졌다. ⑤ `--fail-fast` 는 단계(빌드 → 쿠킹 → ctest → 테스트 → 골든 → 측정) 사이에서 멈춘다. 린트를 빌드 앞으로 옮기지 않았다 — 글롭 대조 게이트가 구성된 빌드 폴더를 읽어 낡은 구성으로 판정한다. 언리얼 자동화(Gauntlet)도 선행 단계가 지면 뒤를 돌리지 않고 장시간 시나리오를 노드에 나눠 병렬로 돈다.
