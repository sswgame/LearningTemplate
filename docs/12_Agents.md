# 에이전트와 토큰

> 질문: 일마다 어떤 에이전트 · 모델 · effort 를 쓰고, 토큰은 어떻게 아끼는가?
> 독자: 에이전트를 띄우는 세션(통합 담당, 사람).
> 결론: 일에 맞는 가장 싼 모델을 고르고 `model` · `effort` 를 항상 지정한다. 지시문에는 읽을 문서와 절을 이름으로 적고, 보고는 파일과 다섯 줄 안쪽으로 받는다.

에이전트를 띄우거나 세션의 토큰을 따질 때 읽습니다. 진행 방식은 [작업 방식](11_Workflow.md), 지시문 틀과 보고 틀은 [작업자 규칙](plans/WorkerRules.md)입니다.

## 1. 일과 에이전트

에이전트 정의는 `.claude/agents/` 에 있습니다.

| 일 | 에이전트(모델) | effort |
|---|---|---|
| 파일 · 호출부 · 지금 값 찾기, CI 로그 · 상태 모으기 | `scout`(haiku) | low |
| 규칙이 정해진 반복 편집(이름 바꾸기 · 이동 · 머리 줄 채우기 · 용어 치환 · 링크 고치기) | `mech-worker`(sonnet) | low |
| 문서 이관 · 정리처럼 항목마다 분류 판단이 드는 일(원본이 이미 지정돼 있을 때) | `mech-worker`(sonnet) | medium |
| 읽기 전용 대조 점검(낡은 문장 · 겹침 찾기, 모르면 "판단 불가"로 표시) | `Explore` 또는 `general-purpose`(sonnet) | medium |
| 범위가 정해진 C++ · CMake · 파이썬 변경, 새 도구 스크립트 + 테스트(변경이 국소적이고 명세가 있을 때) | `worker`(정의의 기본, sonnet) | medium |
| 설계 판단이 드는 C++ · CMake · 파이썬 변경(공개 형식 · 모듈 경계에 닿음) | `worker`(`model: opus` 를 지정해 올림) | medium |
| 문서 요약 · 불필요한 내용 삭제(무엇을 지울지 판단이 든다, 파일별 목표 바이트를 지시문에 적는다) | `worker`(sonnet) | high |
| 통합 실행(병합 · 게이트 · verify-batch 실행 · 결과 표 모으기, 실패 원인은 고치지 않고 원인별로 모은다) | `integrator`(`model: sonnet` 을 지정해 낮춤) | medium |
| 통합 중 실패 원인 수정 | `worker`(opus) | medium |
| 설계 · 모듈을 넘는 리팩터 · GPU/스레드 결함 | `integrator`(opus) | high |
| GPU · 창을 쓰는 실행과 캡처 확인(`py -3 -m Scripts shared-lock acquire gpu` 로 직렬화, 캡처는 눈으로 확인) | `gpu-verifier`(sonnet) | low |
| 에디터 UI 캡처의 UX 점검(읽기 전용, 기준은 [EditorUX](plans/EditorUX.md)) | `ux-reviewer`(sonnet) | medium |
| 구현 전 설계 · 구조 결정 검토(읽기 전용, 현재 구조 · 유지보수 · 성능 · 상용 엔진과 출시작 선례를 근거 수준 [코드] · [문서] · [기억] · [추정]과 함께 비교) | `design-reviewer`(opus) | high |
| 병합 전 브랜치 diff 검토(규칙 위반 · 작업자 충돌, 읽기 전용) | `code-reviewer`(opus) | high |

- `Agent` 호출에 `model` 과 `effort` 를 항상 지정합니다. `effort` 를 지정하지 않으면 호출한 세션의 레벨을 이어받아 단순한 일에도 비싸집니다.
- 에이전트를 맡겼다고 알릴 때는 종류 · 모델 · 레벨을 한 줄로 적습니다. 요청이 이 문서의 규칙과 부딪히거나 한도에 닿으면 실행 전에 한 줄로 알립니다.
- 읽기 전용 점검은 Sonnet 이하로 하고, 결론에 닿는 판단(무엇을 지울지, 무엇을 합칠지)은 맡긴 쪽이 합니다.

## 2. 에이전트에게 줄 때 토큰을 아끼는 규칙

- 지시문에 읽을 문서와 절을 이름으로 적고, 찾기만 하는 일은 `scout` 로 보내 결과를 열 줄 안쪽으로 받습니다.
- 코드를 찾는 지시문에는 `graphify query "<질문>"` 을 먼저 쓰라고 적고(작업자 워크트리에서는 MCP `query_graph`), 행 번호는 실제 파일에서 다시 확인하게 합니다. 사용법은 [CLAUDE.md](../CLAUDE.md) 가 원본입니다.
- **큰 문서는 `py -3 -m Scripts doc <파일>` 로 목차를 보고 `--section <제목 일부>` 로 절만 읽습니다.** 훅(`.claude/hooks/ReadGuard.py`)이 30KB 를 넘는 `.md` 와 48KB 를 넘는 코드의 `limit` · `offset` 없는 통째 읽기를 거절합니다(셸 `cat` · 넓은 `sed -n` 은 `GuardCommands.py`). 계획 문서는 `py -3 -m Scripts plans --file <이름> --section <절 제목 일부>` 로 읽습니다.
- `SendMessage` 로 이어 시키는 것은 같은 파일을 계속 만질 때만 합니다. 이어 시킬 때마다 지난 대화가 다시 입력으로 들어가므로 무관한 일은 새로 띄우는 쪽이 쌉니다.
- **긴 대기는 `run_in_background` 로 하고 `sleep` 으로 기다리지 않습니다.** `SendMessage` 는 받는 에이전트의 **다음 도구 호출에야** 닿으므로, `verify-batch` 를 전경에서 돌리거나 `sleep` 폴링 루프(전경 명령은 최대 590초)로 기다리는 동안은 사용자 · 메인의 지시가 큐에 쌓여 방향을 바꿀 수 없습니다. 수 분 넘는 검증 · 빌드는 `run_in_background: true` 로 띄워 끝 알림만 기다리고, 상태가 궁금하면 로그 끝을 한 번 읽습니다. `GuardCommands` 훅이 전경 `verify-batch` · `full-build` · `soak` · `load` · `perf-compare` 와 20초 이상 `sleep` 을 막으므로(`run_in_background` 호출은 통과) 문서에만 기대지 않습니다. 이미 전경으로 도는 중이면 상위 프로세스를 종료해(`taskkill /PID <py.exe> /T /F`) 메시지가 닿게 한 뒤 다시 띄우게 합니다.
- 조각이 끝날 때마다 토큰 수와 도구 호출 수를 6절 표에 한 줄 적습니다.

## 3. 세션 자체의 토큰

맡긴 쪽 세션은 매 턴 앞의 도구 출력과 에이전트 보고를 다시 입력으로 읽으므로, 에이전트보다 이쪽이 커질 수 있습니다.

- **같은 문서의 수정은 모아서 한 번에 합니다.** 문서 수정마다 워크트리 만들기 · 커밋 · push · 지우기가 한 바퀴(호출 약 15번) 돕니다. 같은 문서를 고칠 일이 여럿이면 한 워크트리에서 한 커밋으로 묶습니다.
- **쉬기 전에 끊습니다.** 프롬프트 캐시는 1시간이 지나면 식고, 그 뒤 이어 쓰면 컨텍스트 전체를 캐시 쓰기 단가(1.25배)로 다시 올립니다. 오래 쉬거나 주제가 바뀌면 압축 대신 인계를 적고 새 세션으로 시작합니다.
- **`graphify` 스킬은 `Skill` 로 부르지 않습니다.** 호출하면 46KB 가 그 세션의 모든 턴에 캐시 읽기로 따라붙습니다. 코드 질문은 CLI `graphify query` 로 충분합니다.
- **본 세션에서 여러 파일을 훑지 않습니다.** 둘 이상의 파일을 읽어야 답이 나오는 탐색은 `scout` · `Explore` 에 맡기고 결론만 받습니다.
- **상시 로드되는 것(`CLAUDE.md` · 메모리 색인 · 스킬 · MCP 지시문)을 늘리지 않습니다.** 매 턴 캐시 읽기에 들어갑니다. 공유 `.mcp.json` 은 graphify 하나만 둡니다.
- **배치가 끝나면 세션을 끊습니다.** 병합 · push 직후에 [NEXT](plans/NEXT.md)에 다음 일과 상태를 적고 새 세션을 권합니다. 새 세션은 NEXT 를 먼저 읽습니다.

## 4. 일을 쪼개서 맡기는 기준

한 단위를 통째로 비싼 모델에 맡기지 않고, 일의 성격이 바뀌는 곳에서 자릅니다. 1절 표의 한 줄이 한 조각입니다.

1. **판단이 드는 조각만 비싼 모델에 둡니다.** 공개 형식 · 모듈 경계 · 오류 처리 방침을 정하는 일은 `worker`(opus, medium)가 맡고, 결과를 명세 파일(스크래치패드)로 받습니다. 명세는 고칠 파일 · 함수 · 행, 결정과 그 이유, 빈 값 · 오류 처리, 추가할 테스트 이름을 적어서 구현자가 다른 문서를 읽지 않고 일할 수 있게 합니다.
2. **명세가 있는 구현은 `worker`(sonnet, medium)로 내립니다.** 명세에 없는 판단이 필요해지면 고치지 말고 맡긴 쪽에 되돌립니다.
3. **찾기와 문서 갱신은 따로 뗍니다.** 위치 찾기는 `scout`(haiku, low), 계획 문서 · 인계 문서 갱신은 `mech-worker`(sonnet, low)입니다.
4. **너무 잘게 쪼개지 않습니다.** 조각 사이마다 인계(지시문 + 보고)가 한 번 생기고, 이어 받는 쪽은 앞 결과를 다시 읽습니다.
   - 앞 조각의 결과가 다음 조각의 입력이 아닌 두 일은 병렬로 띄우되 파일 소유를 나눕니다. 다시 읽을 코드가 같고 판단이 없으면 하나로 묶습니다.
   - 건드릴 파일이 셋 안팎인 단위는 두 조각(설계 → 구현 + 문서)이면 충분합니다.
5. **실행 중인 작업자를 갈아엎지 않습니다.** 쪼개는 계획은 띄우기 전에 세웁니다.
6. **조각의 결과는 파일로 넘깁니다.** 보고는 다섯 줄 안쪽(파일 경로 + 핵심 결정)으로 받습니다.
7. **실행 중인 작업자에게 보낸 메시지는 다음 도구 호출 때 닿으므로** 긴 명령을 기다리는 동안은 막힙니다. 검증 범위 · 쿠킹 횟수 · 골든 범위 · 커밋 단위 정책은 띄우기 전에 지시문에 적고, 한 번에 수십 분 안에 끝나는 범위로 맡깁니다(한 시간 넘는 일은 단위별로 끊어 이어서). 진행은 메시지 대신 `git -C <워크트리> log main..HEAD` · `status` 로 봅니다.
8. 동시에 도는 에이전트는 8개 안팎을 넘기지 않습니다. 같은 영역의 후속 일은 하던 작업자에게, 없으면 같은 모델이고 레벨이 필요한 것 이상인 놀고 있는 작업자(medium 일은 high 에게도 가능)에게 `SendMessage` 로 잇고 새로 띄우기는 마지막입니다(`/worker-brief` 스킬 0번).

## 5. 훅

- 명령 가드 `.claude/hooks/GuardCommands.py` 는 Bash · PowerShell 호출 직전에 `git commit --no-verify` 와 링크(정션)가 든 폴더의 재귀 삭제(`Tools/LLVM` 같은 공유 도구가 함께 지워지는 것)를 막습니다. 훅이 거절한 명령은 우회하지 않습니다.
- 세션 가드 `.claude/hooks/SessionGuard.py` 는 알릴 것이 있을 때만 출력하고, 기록이 4MB · 8MB · 16MB 에 닿을 때마다(또는 압축 2회 이상) 단계마다 한 번 프롬프트를 막습니다. 무엇을 알리는지는 훅 파일이 원본입니다.
- `.claude` 에서는 에이전트 정의 · 훅 · 공유 설정 · 스킬 넷(`integrate` · `ci-triage` · `worker-brief` · `doc-slim`)만 추적합니다. 개인 권한 목록은 `.claude/settings.local.json` 입니다.

## 6. 토큰 측정값

표의 새 줄은 `py -3 -m Scripts agent-log --task <일> --piece <조각> --agent "<종류(모델, effort)>" --tokens "약 N만" --calls <수> [--note ..]` 로 더합니다(날짜는 오늘, 줄 끝 보존).

| 날짜 | 일 | 조각 | 에이전트(모델 · effort) | 토큰 | 도구 호출 | 비고 |
|---|---|---|---|---|---|---|
| 2026-10-19 | 인스펙터 선택기 | 위치 찾기 + 설계 명세 | `worker`(opus, medium) | 약 14만 | 39 | `scout` 선행 없이 |
| 2026-10-19 | 인스펙터 선택기 | 구현 + 테스트 | `worker`(sonnet, medium) | 약 16만 | 65 | 명세 파일만 읽게 함. 13분 |
| 2026-10-19 | 토큰 줄이기 | AGENTS.md 를 `docs/agents/` 7개 파일로 분할 + 링크 약 60곳 | `mech-worker`(sonnet, medium) | 약 10만 | 24 | 4분. 읽는 분량 52.7KB 통째 → 목차 4.9KB + 일에 맞는 파일 |
